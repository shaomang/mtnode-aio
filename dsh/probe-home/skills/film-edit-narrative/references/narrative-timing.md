# 节奏、转场与解说的可执行细节

## 1. 五段式节奏曲线

| 段落 | 时长占比（3 分钟片） | 信息密度 | 镜头长度 | 声音主体 |
| --- | --- | --- | --- | --- |
| 钩子 | 0–8 秒 | 最高，1 个问题／1 个反差 | 0.8–1.5 秒，≤ 2 个画面 | 旁白一句 + 音乐进入 |
| 建立 | 8–35 秒 | 中，交代谁／在哪／要什么 | 2–4 秒 | 旁白为主，留 1 处原声 |
| 转折 | 35–90 秒 | 高，一次认知反转 | 1–3 秒 | 原声或画面事件，旁白短句 |
| 升级 | 90–150 秒 | 中高，连续两次加码 | 1.5–3 秒 | 旁白与原声交替 |
| 落点 | 150–180 秒 | 低到中，答案 + 余韵 | 3–5 秒 | 原声／音乐，旁白收束 |

- 每个段落结束处给一次「呼吸」：0.4–0.8 秒的静音或环境声，不要用音乐硬顶。
- 全片只允许一次「信息轰炸」（连切 5 个以上短镜头），放在转折或高潮，前后都要有长镜头对比。

## 2. 转场选择决策树

```text
两镜之间要发生什么？
├─ 什么都没变，只是换个机位 → Hard cut
├─ 有共同的形状／动作／构图 → Match on <element>
├─ 时间跳过（几小时／几天） → Dissolve 12f（24fps）或 8f（30fps）
├─ 段落硬分隔，需要观众消化 → Dip to black 16f（重叠式）
├─ 下一镜的台词／环境声要提前 → J-cut 12–24f
├─ 上一镜的声音要延续 → L-cut 12–24f
└─ 只是为了盖住生成接缝 → Seam blend 4–8f（记为缺陷）
```

- 24fps 下 12 帧叠化＝半秒，观众不察觉；24 帧＝1 秒，观众开始注意「这是个转场」。
- 甩镜需要两个镜头里都有真实运动模糊，否则接缝比硬切更明显。
- 同一段落里叠化不超过 2 次；超过说明段落结构不清，应该重排 beat。

## 3. 声音对位

| 手法 | 做法 | 适用 |
| --- | --- | --- |
| J-cut | 后镜音频提前 12–24 帧进入 | 台词、揭示、让观众先听到再看到 |
| L-cut | 前镜音频延后 12–24 帧退出 | 环境声延续、情绪余韵 |
| 旁白压原声 | 原声降到 0.2（−14 dB），旁白结束 0.15 秒后恢复 | 旁白必须盖过对白时 |
| 原声留白 | 旁白整段让出 1.5–3 秒给原声关键台词 | 强对白、动作声 |
| 音乐换段 | 只在段落转折处换，交叉 0.5 秒 | 全片 |

- 旁白块与原声重叠时，原声侧链压缩参数：`threshold=0.05:ratio=8:attack=20:release=350`。
- 混音后旁白应比音乐高 ≥ 8 dB（口播类）；用 `ffmpeg -af astats` 分别测两轨 RMS 差值核对。

## 4. 解说写作骨架

一段旁白只做一件事，句式按功能选：

| 功能 | 句式 | 例 |
| --- | --- | --- |
| 补前提 | 「在此之前，X 一直是 Y。」 | 「在这之前，这扇门一直是锁着的。」 |
| 给判断 | 「真正的问题是 Z。」 | 「真正的问题不是他进不去，是有人不想他进去。」 |
| 连接因果 | 「所以当 A 发生时，B 已经注定。」 | 「所以当灯亮起时，结局已经写好了。」 |
| 抬价 | 「更糟的是……」 | 「更糟的是，钥匙一直在他口袋里。」 |
| 收束 | 「这就是为什么……」 | 「这就是为什么他从不回头。」 |

- 一句不超过 28 字；超过就拆成两句或删定语。
- 专有名词、人名、缩写第一次出现必须给一句解释，解释放在同一块里，不另起一块。
- 数字与结论必须能在画面或素材里找到对应；找不到就删。

## 5. 时间线文件（`timeline.json`）

```json
{
  "schema_version": 2,
  "canvas": {"width": 1920, "height": 1080, "fps": 30},
  "duration": 180.0,
  "tracks": [
    {
      "kind": "video",
      "name": "video",
      "clips": [
        {
          "source_path": "/media/orig.mp4",
          "source_start": 243.0,
          "source_end": 268.0,
          "timeline_start": 0.0,
          "timeline_end": 25.0,
          "audio": {"role": "original", "base_gain": 0.85,
            "volume_keyframes": [{"t": 0.0, "gain": 0.85}, {"t": 2.19, "gain": 0.2}]}
        }
      ]
    },
    {
      "kind": "audio",
      "name": "narration",
      "role": "narration",
      "segments": [
        {"source_path": "/media/_placed_0000.wav", "timeline_start": 2.19, "timeline_end": 5.9,
         "gain": 1.0, "text": "……", "overlaps_speech": true}
      ]
    }
  ]
}
```

- 时间单位统一为秒，音量为增益（1.0 = 原电平），不要混 dBFS。
- 视频轨只放一段 base video；图片叠层、字幕、音乐各自独立轨。
- 写时间线前先确认每个 `source_path` 存在，时长用 `ffprobe` 实测，不手填。

## 6. 粗剪检查表（第一遍结束时逐条打勾）

- [ ] 每个片段都有 `reason` 七段，且 `function` 不全相同。
- [ ] 删除了 15–20% 的时长，且没有一处切在词中间（随机抽 5 处回听）。
- [ ] 全片没有连续 2 秒「画面与声音都没有新信息」的区间。
- [ ] 钩子在 3 秒内给出一句可复述的承诺，第 5 秒前有第一个高能点。
- [ ] 同一素材没有出现两次以上，且没有靠变速／镜像伪装。
- [ ] 段落之间有明确的 `change`（谁知道什么变了）。

## 7. 精剪检查表

- [ ] 每个剪辑点落在动作完成帧，不是恢复呼吸之后。
- [ ] J-cut／L-cut 至少各用 1 处，且服务于台词或环境声，不是随手加。
- [ ] 旁白没有盖住关键台词；被盖住的台词要么删，要么让旁白让位。
- [ ] 字幕与旁白同源；屏幕大字最多早 1.5 秒，不晚于旁白。
- [ ] 音乐只在段落转折处换，句子中间没有硬切。
- [ ] 时长与 `target_duration` 偏差 ≤ 3%，超出就回到第 3 步改 beat。

## 8. 可复现与增量

- 每个产物带输入指纹：原片 SHA-256、转写版本、`clip_plan.json` 的哈希、渲染参数。指纹不变就复用缓存，不重跑。
- 精确失效：改一段旁白只失效该段 TTS、对应字幕和关联片段时长；改音乐只失效混音与封装。不要把「一处校验失败」解释成「整条重来」。
- 校验器输出 `repairPlan`，每项写清 `invalidates` 与 `preserves`；修复前确认不会重跑已付费的生成任务。
- 每个阶段换新文件名（`v01`、`v02`），原片只读；归档旧版本，不用覆盖的方式迭代。
