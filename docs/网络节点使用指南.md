# MTNode 网络节点使用指南（net_recv / net_send）

> 适用对象：① 在 MTNode 画布中通过「网络节点」做跨进程 / 跨机器数据交换的用户；
> ② 需要与画布网络节点对接的**其他应用程序开发者**（Python / Node / C# / 任何 TCP、UDP 栈）。
>
> 配套调试工具：`E:\dev\tools\netdebug`（独立 Electron 工具，与 MTNode 无关，支持通道选择与帧协议）。

---

## 1. 概述

画布提供两种网络节点：

| 节点 | 作用 | 说明 |
|---|---|---|
| **接收** `net_recv` | 监听某端口，按「通道」接收网络帧，收到后把**负载文本**异步推给下游 | 异步推送，不阻塞；同一端口可被多个接收节点共享，按通道分流 |
| **发送** `net_send` | 把**信息输入（端口 0）的文本**封装成帧，推送到 `目标地址:端口` 的指定通道 | 触发式（点「发送」或被上游控制）；无输出端口，是末端 |

特点：

- **跨画布**：任何画布（乃至任何应用）只要按本协议发帧，都能与网络节点互通——本机 `127.0.0.1` 或远程 IP 皆可。
- **节点级独立端口 + 通道分流**：接收（监听）与发送（目标）使用**相互独立的端口**——接收节点默认监听 `40999`，发送节点默认目标 `41000`，每个节点都可在节点体上单独改端口；用 **16bit 通道号（0–65535）** 在端口内做逻辑分流，互不干扰。节点端口留空(0)时才回退到「设置 → 网络端口」的全局默认（默认 40999）。
- **TCP / UDP 独立**：同一端口上 TCP 与 UDP 可同时存在、各自独立监听（`SO_REUSEADDR`）。

## 2. 画布节点用法

### 2.1 通用字段（两个节点都有）

| 字段 | 取值 | 说明 |
|---|---|---|
| 通道 Channel | 0 – 65535（16bit 整数） | 端口内的逻辑分流号。新建节点时自动分配下一个空闲通道；**收发的帧头都带此通道** |
| 协议 | TCP / UDP | 收发使用的传输协议 |
| 端口 | 1 – 65535；留空(0) = 用全局设置端口 | 接收节点=**监听端口**（默认 40999），发送节点=**目标端口**（默认 41000），各自独立，在节点体上直接改；「设置 → 网络端口」仅是节点留空时的回退默认 |

### 2.2 接收节点（net_recv）

- **输入**：无（它是异步数据源）。
- **输出**：端口 0 = 数据（收到的负载文本，`kind:"text"`）；端口 1 = **控制**（收到帧时触发下游可控制运行的节点）。
- 运行方式：点节点上的「▶ 开始监听」。之后任何按协议发到 `本机:端口` 且通道、协议匹配的帧，都会被投递到这个节点，级联下游数据节点并触发控制端子。
- 一个端口只需一个监听（多个接收节点共享同一 socket，按通道分发）；停止监听即取消本节点的订阅。

### 2.3 发送节点（net_send）

- **输入**：端口 0 = 数据（要发送的文本；连上文本处理/输入节点即可），端口 1 = 控制（触发发送）。
- **输出**：无（末端节点）。
- 额外字段：**目标地址**（默认 `127.0.0.1`，可填远程 IP / 域名）。
- 运行方式：点「▶ 发送」或由上游控制触发；把输入文本封装成帧发往 `目标:端口` 的指定通道。

### 2.4 端到端最小示例

1. 画布放一个「接收」节点：通道 `3`、协议 TCP、监听端口默认 `40999` → 点「开始监听」。
2. 放一个「发送」节点：通道 `3`、协议 TCP、目标 `127.0.0.1`、**目标端口改成 `40999`**（与接收节点的监听端口一致，默认 41000 用于连接对端）；信息输入连一个「文本」节点，写 `你好`。
3. 点发送节点的「▶ 发送」→ 接收节点状态变为「已收到 1 条」，下游级联。

> 跨画布：另一个画布（或另一台机器）用相同的端口 + 通道 + 协议即可互相通信，无需任何共享状态。接收端各听各的端口、发送端各发各的目标，互不影响。

## 3. 线上协议（Wire Protocol）—— 供其他应用对接

### 3.1 帧格式（固定 6 字节头 + 负载）

```
偏移    长度    内容
0       2      通道号，uint16，大端序（big-endian），0–65535
2       4      负载长度，uint32，大端序（负载的字节数）
6       N      负载，UTF-8 编码的文本（N = 上面声明的长度）
```

即：`[ 通道:2B BE ][ 负载长度:4B BE ][ UTF-8 负载 ]`，总长 = 6 + N。

要点：

- **通道**：写进帧头，接收端按它路由；同一端口可承载任意多通道。
- **负载**：必须是 **UTF-8** 编码的文本（节点收到后按 UTF-8 解码为字符串）。
- **长度**：大端序 uint32，理论上限 4 GiB；实际受网络与内存限制，建议单帧 ≤ 1 MiB。

### 3.2 TCP 语义

- 一次连接上可**连续发送多帧**（通道可以不同，靠帧头区分）。
- TCP 是字节流，接收端必须**按长度字段拆帧**：先收齐 6 字节头 → 读出 N → 再收齐 N 字节负载 → 循环（正确处理粘包 / 半包）。
- 发送端发送节点：连接 → 写一帧 → 忽略响应 → 关闭（4 秒超时）。
- 接收节点：共享监听 socket，逐连接拆帧、逐帧广播给匹配的接收节点。

### 3.3 UDP 语义

- **一个数据报 = 一帧**（数据报长度 ≥ 6 字节）。
- 接收端解析：读 2 字节通道 + 4 字节长度，负载取 `min(声明长度, 数据报剩余)`（数据报被截断时按实际剩余解码）。
- 发送节点：每触发一次 = 发一个数据报。

### 3.4 端口与协议矩阵

| 组合 | 行为 |
|---|---|
| TCP + 端口 P | TCP 监听 / 连接 P |
| UDP + 端口 P | UDP 绑定 / 发送 P |
| 两者同时 | 同一端口 TCP 与 UDP 各自独立，互不干扰 |

## 4. 对接示例

### 4.1 Python —— 发送（TCP / UDP）

```python
import socket, struct

def build_frame(channel: int, text: str) -> bytes:
    body = text.encode('utf-8')
    return struct.pack('>HI', channel & 0xFFFF, len(body)) + body

# TCP 发送（发给画布「接收」节点）
s = socket.create_connection(('127.0.0.1', 40999), timeout=5)
s.sendall(build_frame(3, 'hello from python'))
s.close()

# UDP 发送
u = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
u.sendto(build_frame(3, 'hello udp'), ('127.0.0.1', 40999))
u.close()
```

### 4.2 Python —— TCP 接收（拆帧，可对接画布「发送」节点）

```python
import socket, struct

def recv_exact(sock, n):
    buf = b''
    while len(buf) < n:
        chunk = sock.recv(n - len(buf))
        if not chunk:
            raise ConnectionError('对端关闭')
        buf += chunk
    return buf

srv = socket.socket()
srv.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
srv.bind(('0.0.0.0', 40999))
srv.listen(5)
print('监听 0.0.0.0:40999 ...')
while True:
    conn, addr = srv.accept()
    with conn:
        print(f'连接来自 {addr}')
        while True:
            try:
                hdr = recv_exact(conn, 6)
            except ConnectionError:
                break
            ch, ln = struct.unpack('>HI', hdr)
            body = recv_exact(conn, ln).decode('utf-8')
            print(f'[通道 {ch}] {body}')
```

### 4.3 Python —— UDP 接收

```python
import socket, struct

u = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
u.bind(('0.0.0.0', 40999))
print('监听 UDP 0.0.0.0:40999 ...')
while True:
    data, addr = u.recvfrom(65535)
    if len(data) < 6:
        continue
    ch, ln = struct.unpack('>HI', data[:6])
    body = data[6:6 + ln].decode('utf-8', errors='replace')
    print(f'来自 {addr} [通道 {ch}] {body}')
```

### 4.4 Node.js —— 发送

```js
const net = require('net');

const frame = (ch, text) => {
  const body = Buffer.from(text, 'utf8');
  const h = Buffer.alloc(6);
  h.writeUInt16BE(ch & 0xffff, 0);
  h.writeUInt32BE(body.length, 2);
  return Buffer.concat([h, body]);
};

const s = net.createConnection(40999, '127.0.0.1', () => s.write(frame(3, 'hello node')));
s.on('close', () => process.exit(0));
```

### 4.5 对接检查清单

- [ ] 帧头 6 字节：通道 uint16 BE + 长度 uint32 BE，顺序别反；
- [ ] 负载是 UTF-8（中文不乱码的前提）；
- [ ] TCP 端正确拆帧（粘包/半包）；
- [ ] 端口一致（接收节点监听端口 = 对端发送目标端口；默认 接收 40999 / 发送 41000，均可在节点体上改）；
- [ ] 通道一致（帧头通道 = 接收节点通道）；
- [ ] 协议一致（TCP 发 TCP、UDP 发 UDP）；
- [ ] 跨机器时：防火墙放行该端口、目标填远程 IP。

## 5. 用 netdebug 调试网络节点

`E:\dev\tools\netdebug` 是独立的图形化调试工具（Electron），双击 `启动.cmd` 或 `npm start` 打开。

### 5.1 通道选择与帧协议

- **通道 Channel**：与画布网络节点同义的 0–65535 通道号。发送时写进帧头，接收时从帧头读出并显示。
- **帧协议** 下拉：
  - `MTNode 通道帧`（默认）：发送时自动加 6 字节帧头；TCP 接收时自动拆帧、UDP 接收时按帧解析，日志里显示 `帧[通道 N · M字节]` 与负载正文。
  - `原始报文`：不加帧头、不拆帧，显示原始字节（通用 TCP/UDP 调试）。

### 5.2 从画布一键打开（画布打通）

在画布的「接收 / 发送」节点上点 **`netdebug`** 按钮，工具自动启动并**预填**协议、端口、通道（帧协议默认开启）：

| 从哪个节点打开 | 预填角色 | 用途 |
|---|---|---|
| 接收节点 | 客户端 | 直接发送测试帧灌进接收节点的监听端口 |
| 发送节点 | 服务端（监听） | 监听该端口，抓取发送节点（或对端）的出站帧 |

打开后按需改角色/地址，点「启动监听」或「发送」即可。

### 5.3 双向模式（同时监听 + 发送）

netdebug 支持**双向**角色：一边监听（绑定 `0.0.0.0`），一边向另一个目标 `IP:端口` 发送，两边同时工作、互不干扰：

- 典型场景：MTNode 接收节点监听 `40999`、发送节点目标 `41000` 时，netdebug 双向模式**监听 `41000`**（抓取发送节点的出站帧）**并发送到 `127.0.0.1:40999`**（向接收节点灌测试帧），一个窗口同时看到入站与出站。
- 界面：角色选「双向」→「监听端口」填要监听的端口、「目标地址/目标端口」填发送目标 → 分别点「启动监听」与「发送」。
- 命令行预填：`node start.js --proto tcp --role duplex --port 41000 --host 127.0.0.1 --target-port 40999 --channel 3`。
- UDP 双向的「回复上次来源」会自动回给最近一次发来数据的来源（与发送目标无关）。

### 5.4 典型调试场景

1. **验证接收节点**：接收节点开始监听（监听端口默认 `40999`，通道 3）→ netdebug 客户端：TCP、`127.0.0.1:40999`、通道 3、帧协议 → 输入 `hello` → 发送 → 画布接收节点应显示「已收到 1 条」。
2. **抓取发送节点出站**：发送节点目标端口默认 `41000` → netdebug 服务端（或双向）监听 `0.0.0.0:41000`、通道 3 → 触发画布发送节点 → netdebug 日志出现 `帧[通道 3 · n字节]` 与正文。
3. **对第三方应用做协议联调**：按第 4 节示例构造帧，用 netdebug 一边当参照物收发，一边核对第三方实现的字节序与拆帧。

## 6. 常见问题排查

| 现象 | 原因与处理 |
|---|---|
| 监听失败「监听失败：EADDRINUSE」 | 端口被占用（另一个接收节点/其他程序已监听）。换端口或关闭占用方 |
| 发送超时 | 目标不可达：IP 写错、服务未启动、防火墙拦截。先 `ping` / `telnet 目标 端口` 验证 |
| 收不到消息 | ① 通道不一致（帧头通道 ≠ 接收节点通道）；② 协议不一致（TCP/UDP 错配）；③ 端口不一致（接收监听 40999 但对方发到 41000，或反之）；④ 远程时防火墙未放行 |
| 中文乱码 | 发送方必须用 UTF-8 编码负载 |
| UDP 偶发收不到 | UDP 无重传：确认对端确实发出、端口绑定正确、数据报 ≥ 6 字节 |
| netdebug 启动报错 | 见 netdebug\README.md；`start.js` 已处理宿主注入的 `ELECTRON_RUN_AS_NODE` 环境变量问题 |
