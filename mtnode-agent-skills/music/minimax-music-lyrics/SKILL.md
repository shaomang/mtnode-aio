# MiniMax Music 歌词

**本技能是应用内置技能**（随安装包发版，来自创意工坊的那份已撤下）。用户要写 / 改 / 续写 MiniMax Music（网页端 Lyrics、Music 3.0、`music_gen` 节点）的 **歌词正文** 时使用。

歌词与风格提示词是**两个独立输入**：本技能只产出要唱出来的词；曲风、速度、乐器、人声表演、制作一律交给内置技能 `minimax-music-prompt`。

依据：[MiniMax Music Prompt Guide](https://www.minimax-music.com/blog/minimax-music-prompt-guide)（结构标签、段落说明、歌词赶 / 发音糊的处理、副歌 contrast 均出自该文）。MTNode 口径：「Minimax Music 3」节点（`music_gen`）**端口 1 = 歌词**、端口 0 = 风格提示词；「YuE2」节点（`yue_gen`）同。

## 任务

1. 先补齐缺失信息（一次问完，缺啥问啥）：主题 / 叙事、语言（中 / 英 / 双语）、情绪、目标结构、是否纯器乐。
2. 产出**可直接粘贴**的歌词正文：纯文本，结构标签独占一行，只有会唱出来的话才写进正文。
3. 附一行提示：哪些内容应写进风格提示词（`music_gen` 端口 0），不要塞进歌词。

纯器乐：不要编造唱词。只给 `[Intro]` `[Instrumental]` `[Outro]` 这类骨架，并说明该走器乐生成、唱词留空或写 `[instrumental]`。

## 输出格式

按顺序，歌词永远在最前面：

1. **歌词正文**（唯一供粘贴的一段：纯文本、含标签与换行，**不要用代码围栏包起来**，也不加标题）
2. **结构说明**（各段承担什么，3–6 条）
3. **演唱风险**（过长行、难读词、已做的改写）
4. **交给提示词的一句**：编曲 / 人声 / 制作 / 段落强弱去写 `minimax-music-prompt` 那段六句散文

不要在正文里写歌名行（除非用户要把歌名唱出来）；不要把标题写进节点输入。

## 硬性规则

- **不要把舞台指示写进会唱出来的正文。** `(music fades)`、`(repeat twice)`、`(Soft piano)`、`(Fade out...)` 会被逐字唱出来。乐器、渐强、淡出属于风格提示词。
- 括号只用于**要发声**的衬词与和声：`(Ooh-ooh-ooh)`、`(Yeah)`、`(Coming back to me)`；每段最多 1–2 行衬词。
- **结构标签独占一行**，用方括号写法。标签是可执行的结构指令，不是歌词。
- **为唱而写**：缩短长句、降低信息密度、让相邻行长度接近。在目标语速下说不顺的句子必须改短。
- 专有名词、缩写、难读词：按读音拼写，或拆到两行。**先改那一行，不要整首重写。**
- 副歌与主歌必须有**文本层面的对比**：副歌更短、更可重复、有 1–2 个核心短语。
- 长度：接 `music_gen`（MiniMax Music 3 后端）时非器乐正文 **1–3500** 字符；翻唱常见 10–1000。默认完整流行歌控制在约 1500–2800 字符，优先可唱而非堆段数。
- 行长：中文按顿挫断行，一行约 **6–12 字**；英文一行约 **8–12 词**。
- 语言：按用户语言写正文（中文歌词官方支持）；风格提示词仍然只用英文。
- 事实与编造：用户没给的专名、情节不要硬写成「原著」；可写通用情绪歌词并说明是创作。

## 结构标签

Music 3 核心（优先这套，同一首只用一种拼写）：

`[Intro]` `[Verse]` / `[Verse 1]` `[Pre-Chorus]` `[Chorus]` `[Post-Chorus]` `[Bridge]` `[Instrumental]` `[Solo]` `[Outro]`

网页端与歌词生成 API 另可见：`[Hook]` `[Drop]` `[Build-up]` `[Breakdown]` `[Break]` `[Interlude]`，以及空格写法 `[Pre Chorus]` `[Build Up]` `[Inst]` `[Transition]`。**统一用连字符那一套**：`[Pre-Chorus]`、`[Post-Chorus]`、`[Build-up]`、`[Instrumental]`。

| 标签 | 写什么 |
|---|---|
| Intro | 短衬词或留空（器乐开场属于提示词） |
| Verse | 叙事、细节、推进 |
| Pre-Chorus | 蓄力，指向副歌钩子 |
| Chorus | 核心承诺句，可原样重复 |
| Post-Chorus / Hook | 更短的记忆点、拟声 |
| Bridge | 视角或和声对比，不复述副歌 |
| Instrumental / Solo / Interlude | **不填唱词**；演奏说明写进提示词 |
| Outro | 回收钩子或极短收束 |

默认完整结构（按需删减，别为显完整堆无词标签）：

`Intro → Verse → Pre-Chorus → Chorus → Verse → Pre-Chorus → Chorus → Bridge → Chorus → Outro`

电子 / 舞曲可加 `[Build-up]` `[Drop]` `[Breakdown]`。

## 标签后面的段落说明

官方口径：**结构标签告诉模型歌在哪，段落说明告诉模型这里发生什么。** 网页端允许在标签后写编曲 / 人声 / 情绪备注，例如：

```
[Chorus] Fuller drums, wider harmonies, and stronger vocal delivery.
```

但走 MTNode 的 `music_gen` / `yue_gen` 时，提示词与歌词**分两个端口进后端**，标签后的备注有被当成正文处理的风险。因此：

- 段落是**唱法 / 配器 / 强度**变化 → 写进风格提示词那句 Structure（`minimax-music-prompt` 第 5 句），歌词只留干净的标签。
- 段落是**唱词本身**的变化 → 留在歌词正文里。
- 只有用户明确要网页端就地标注时才交付带段落说明的版本，并说明这份不是纯唱词。

情绪骨架：`Introduce → Build → Release → Contrast → Resolve`；副歌比主歌更直接。

## 写法

1. **先定钩子**：副歌 1–2 句，能单独成歌。
2. **主歌服务副歌**：给细节与场景，别在主歌提前耗尽钩子。
3. **重复是功能**：副歌可原样重复；Verse 2 换细节、不换节奏型。
4. **保留锚点**：全曲回同一人声口吻、核心动机、情绪方向，段落才不脱节；能量渐变，不要整块换声。
5. **中英混合**：钩子用短英文、主歌用中文，每行仍要可唱。
6. **叙事推进**：每段推进一件事（场景 → 冲突 → 表态 → 释怀），不要把同一个意思换三种说法填满。

## 与提示词的分工

**风格提示词定义世界；歌词结构指挥世界里发生什么。** 同一指令不要两边各写一遍。

| 写进 lyrics（本技能） | 写进 prompt（`minimax-music-prompt`） |
|---|---|
| 要唱出来的词 | 曲风、情绪、场景 / 用途 |
| `[Verse]` `[Chorus]` 等段落标签 | 速度与律动 |
| 可唱的和声拟声 `(Ooh)` `(Yeah)` | 乐器角色与演奏法 |
| 钩子、重复、对白式短句 | 主唱身份、唱法、和声层次 |
| —— | 段落对比、制作、混音 |

歌词标签里若混进了「加鼓、加和声」这类**音乐指令**：不要抄进唱词，搬到风格提示词那一段，并在交付时说明你替用户搬了哪几条。

## 修改与续写

- 只改出问题的段或行（官方：**先改那句歌词，不改整段 prompt**）。
- 续写沿用已有标签拼写、行长与钩子，不要顺手改前人设定。
- 只有一个元素坏 → 只改那处；风格 / 情绪 / 人声 / 结构全错 → 才重新构思。

### 常见故障速修

1. **听着赶 / 挤进旋律**：缩短长句、简化密集短语、让相邻行长度接近。
2. **发音糊**：换成更简单的词、缩写按读音拼、难句拆到两行。
3. **副歌不够大**：副歌文本写得更短更可重复，把「更满的鼓、更宽的和声、更强的唱」搬到提示词。
4. **段落脱节**：补回锚点（同一人声角色、核心乐器、动机、情绪方向）。

## 示例形态（结构骨架，主题自定）

```
[Intro]
(Ooh-ooh)

[Verse 1]
短句叙事
短句叙事

[Pre-Chorus]
蓄力短句
(呼应钩子)

[Chorus]
核心钩子
核心钩子变体
(短衬词)

[Verse 2]
新细节，行长与 Verse 1 接近

[Bridge]
对比视角
不复述副歌

[Outro]
钩子碎片
```

## 校验清单

- [ ] 每个演唱段落都有标签，标签独占一行，拼写全曲统一
- [ ] 正文里没有任何舞台指示 / 乐器 / 混音说明
- [ ] 副歌有可重复钩子；主歌与副歌能量不同（contrast）
- [ ] 行长适合演唱，相邻行长度接近，难读词已处理
- [ ] 每段衬词 ≤ 1–2 行；器乐段没有假唱词
- [ ] 总字符在目标接口上限内（`music_gen` 非器乐 1–3500）
- [ ] 没把曲风、BPM、配器、人声表演写进歌词
- [ ] 与风格提示词无重复指令；歌词正文未被代码围栏包裹
