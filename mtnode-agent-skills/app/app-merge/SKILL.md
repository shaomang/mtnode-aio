# MTNode 应用版本合并

这是**合并会话**用的技能：把「对方那一版」（云端某位作者的某一版）与「本机开发目录」的差异，按用户**逐项确认**的结果合进本机。它不自己下载、不自己解包、不自己比差异 —— 那些都由 MTNode 主进程做完，会话契约里已经写好两边的绝对路径与文件级差异清单。

与 `mtnode-app-dev` 的分工：那边管「从零开发 / 改一个应用」，这边只管「两个版本之间怎么合」。冲突、取舍、要不要跟版本号，全由用户当场定，**你不用也不许替他决定**。

## 一、契约给了你什么（都从会话契约里读，别自己猜路径）

| 字段 | 是什么 |
| --- | --- |
| 本机开发目录 | **要改的就是它**（用户的开发副本，写盘只写这里） |
| 对方那一版 | 主进程解包好的**暂存目录**（只读；通常还会再下钻一层才是应用根 —— 认入口页 `index.html` 在哪一层） |
| 对方 | 作者名 + 版本号 + 版本说明（可能是空） |
| 本机版本号 | 这次**不会**改那个号 |
| 合并前整目录备份 | 主进程在拉取前拷好的整目录备份（要回滚就是把它拷回开发目录）；只报给用户，不主动恢复 |
| 文件级差异清单 | 每个文件的 `add`（对方新增）/ `diff`（两边都有但内容不同）/ `same`（一致）/ `local`（只有我有）+ 字节数 + 是否二进制 |

差异是**两方**比出来的（没有共同祖先）：`diff` 只说明「两边内容不一样」，**不说明谁改的** —— 所以每一项都要问，不要替用户判断「这是他改的还是我改的」。

## 二、硬规则（违反任何一条都算做错）

1. **用户确认之前，一个字都不许改** —— 不许先动手再问，也不许「我先改好再让他确认」。
2. **只按拷问结果覆盖差异**，不做任何额外改动：不顺手重构、不顺手补注释、不顺手改别处。
3. **`local`（只有我有）的文件一律保留，不用问、也不许删**。
4. **不许改版本号，不许直接改 `app.json`** —— 合并留痕与版本号只由 MTNode 主进程写（见第四节）。
5. 不动 `storage/`、`data.json`、`*.mtnodes`（该应用的画布）、备份目录与任何以 `.mtnode-merge-backup` 开头的目录。
6. **不改对方那一版**（暂存目录只读）、**不删暂存目录**、**不写任何「合并报告」文件**。
7. **不自动上架**：合并完由用户自己去看、自己上架；不要调用任何发布入口。
8. 不猜：清单里列不下、目录里对不上、文件读取失败这类情况，如实说出来并问用户，绝不静默跳过。

## 三、怎么做（按顺序）

1. **加载拷问技能**：用 `skill` 工具加载 `mtnode-grill-me`，严格照它执行（一轮把整个前沿问满、用 `ask_user_question` 出询问窗、推荐项放第一位）。
2. **先读后问**：把差异清单里的 `add` / `diff` 逐个打开，读**两边**的内容，把每一项整理成「对方现在是什么样 / 本机现在是什么样 / 差别在哪一句话」。文件多时按「同一件事」归组（同一个页面的样式与脚本可以合成一题），但每一项都要有归宿。
3. **拷问两件事**（一次问满，别一项一项地弹）：
   - 每项差异怎么覆盖：`采用对方的` / `保留本机的` / `逐段挑`（用户给出具体取舍）；二进制文件只问「换成对方的吗」。
   - 我这一版要不要跟着动：默认**不动**；用户要是说跟，就问清填哪个号（采用对方的 vX，还是在我自己的号上 +1）。
4. **用户确认后才落地**：文本用你的文件工具改（保持原有换行与缩进风格；不要顺手格式化整个文件）；二进制与「对方新增」的文件用 shell 从暂存目录拷过去（例如 `Copy-Item`）。每改一项都能对回拷问里的那一句。
5. **自检**：改完后重新比一遍两边 —— 清单里每一项都落在「已按用户选择处理」的状态；`storage/` / `data.json` / `*.mtnodes` 与 `app.json` 一个字节都没动。
6. **收尾声明**：把这次采纳的清单写进 `<暂存目录>/.merge-done.json`（见下一节）。这一步是**必须**的：没有它主进程不会清暂存、入口也不会解禁。
7. **回执**：在会话里给一份中文清单（每个文件 → 怎么处理的），并说明「版本号没动 / 按你的选择改成了 vX」「本次没有上架」。别把过程日志当回执。

## 四、收尾声明文件（`.merge-done.json`）

写在**暂存目录的根**（不是开发目录，也不是对方应用根里那一层），内容：

```json
{ "done": true, "files": ["index.html", "style.css"], "version": "" }
```

- `files` = 这次真改过 / 真拷过去的文件（相对路径，本机开发目录那一侧）。
- `version` = **留空就等于版本号不动**；只有用户在拷问里明确要跟着动时才填他要的那个版本号（主进程据此写 `app.json`，你别自己写）。
- 写完这一份就结束，不要再去删暂存目录或备份目录 —— 主进程会接手（补一条合并留痕、清暂存、解禁入口）。

## 五、常见坑

- **下钻一层**：对方包里常常只有一层目录（`<id>/index.html`），别把那一层当成文件差异。
- **`app.json` 出现在两边**：它**不在**差异清单里（本机元数据不参与合并），你也别去读它当差异 —— 版本号与留痕由主进程处理。
- **`diff` 不等于冲突**：没有共同祖先，`diff` 就是「两边不一样」，用户的取舍才是结论。
- **用户中途改主意**：拷问可以多轮；每一轮都重新读一遍当前文件再问，别拿上一轮的印象报价。
- **写不进去 / 文件被占用**：如实报出来（有可能是那个应用的独立窗口正开着），让用户决定是否先关掉它 —— 不要自己关窗口、也不要跳过这一项。
