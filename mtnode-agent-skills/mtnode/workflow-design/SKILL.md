# 工作流设计（节点层即工作流）

## 一、触发与产出

- 触发：用户要「做一个工作流」「把这段流程封装成节点层」「设计一个可复用的工作流」，或让你把画布上散着的一串节点收进一颗壳。
- 产出物 = 画布上**一颗** `super`（节点层），壳内部就是能一键重跑的数据流：**输入 → 处理 → 保存**。
- 节点层**就是**工作流本身：不新增节点类型、不写新插件、不改宿主代码；用现成 kind 搭。
- 建壳用 `mtnode_canvas_edit` 的 `parentSuperId`（需 `canvas_super`），先 `mtnode_canvas_get` 读图，再一次调用建完整子图。
- 顺序：先想清「外部要什么、外部给什么」，再搭内部；不要先铺节点再补端子。

## 二、无状态依赖（硬规则，违反即不合规）

- **外部输入只走节点层的外侧输入端子**：内部不许靠「画布上别的节点随手连进来」取数；从外面看，这颗壳必须自洽——搬走它、单独看它，也知道数据从哪来、到哪去。
- **不许依赖画布级能力**：不写画布级 `@引用`、不依赖全局广播；不依赖「当前画布名 / 当前工作区 / 上一次运行的残留 / 某个节点恰好已经跑过」。
- **不许写死本机绝对路径**：输入 / 输出 / 模型 / 后端地址一律不钉死。输出用相对路径或用户可改的路径字段；密钥、本机后端地址**绝不**写进节点。
- 内部节点之间可以任意连线；跨壳取数只走端子，不用 `@` 抄正文。

## 三、外侧端子契约

- 至少 **1 个外侧输入 + 1 个外侧输出**；端子数按真实需要，不凑数。
- 每个端子都要**有含义**：内部用第一颗接收节点承接输入，最后一颗输出节点回连到壳的输出端子。
- 控制流要连通：从控制入（壳的输入端子 / `control` 起点）一路走到控制出。
- 端子序号与内部桥接**一一对应**：序号、含义、类型按顺序对齐，别只在壳上挂个名字不接线。
- 桥接怎么写（从壳里拉出 / 连成边界端子、跨层级用 `superConnect`）见技能 `mtnode-canvas-edit-rules` 的 super 边界端子与 scope 部分——按那一条来，不要在这里另立一套。

## 四、结构规范

- 骨架：入口（`control` 起点）→ 处理（`proc_text` / `proc_image` / 生成类 / `agent_task` 等）→ 保存（`save` / `save_text` / `save_image` / `save_pdf`，或媒体节点自己的 `outputPath`）。
- 规模：一颗壳内部不要超过必要体量；**超过约 12 颗内部节点就拆成多层嵌套节点层**，每层一个职责（如「取数层 / 处理层 / 落盘层」）。拆法：把「处理」收成一颗内层 `super`（外侧端子 = 外层需要的输入 / 输出），外层只留「取数 → 调内层 → 落盘」三颗。
- 命名：壳标题 = 工作流名（用户一眼知道这壳干嘛）；内部节点标题写清职责（「切分台词」「润色」「存终稿」），不用「节点 1 / 文本节点 2」。
- 排版与可操作区：可编辑 / 控制节点靠上（小 y），处理与保存往下或往右；分区用 `createMarks`。见技能 `mtnode-canvas-layout-ux`。
- 一键重跑：`control` 直接连到每个该重跑的节点（控制流不走数据线）；不要建 `clear`。

## 五、可运行性自检清单（交付前逐条过）

- [ ] **无悬空必需端子**：该接的都接了，没有只挂名不接线的端子。
- [ ] **无重复标题**：全画布标题唯一（含壳内部）。
- [ ] **保存节点有输出路径**：`save` 族 / 媒体节点 `outputPath` 已给（相对路径或用户可改字段），不是本机绝对路径。
- [ ] **批次 `batchMode` 正确**：`batch` 时每次只看当前这一条，禁止把整批 N 条再灌进每次运行；要一次看全部用 `agg`。见技能 `mtnode-canvas-batch-safety`。
- [ ] **`proc_image` 一次只出 1 张**：要多图就一条批量项出一张，或用多个节点 / `attempts`。
- [ ] **控制线闭环**：控制入 → … → 控制出连通，`control` 能一键重跑整条链。
- [ ] **零状态依赖**：外侧端子够用、无画布级 `@` / 全局广播、无写死绝对路径与密钥。
- [ ] 拿不准的规则回查技能 `mtnode-canvas-edit-rules`（唯一真源），不要凭记忆接线。

## 六、交付口径

- **不自动存进工作流库**，不替用户上传工坊，不声称已经保存 / 已分享。
- 搭完只报告四件事：
  1. **节点层标题**；
  2. **外侧端子清单**：序号 + 含义（输入、输出分开列）；
  3. **内部节点清单**：标题 + 一句话职责；
  4. **跑一次需要用户填什么**：输入文件 / 文本、输出路径、模型或服务商等。
- 收尾提示：用户可右键节点层「保存到工作流库」或「分享到工坊」——由用户确认后自己点，你不要代点。

## 七、最小示例骨架（只给结构与端子，不写 API 细节）

**示例 A：文本批处理 → 保存**

- 壳「文本批处理」
  - 外侧输入：`0` 待处理文本（text）
  - 外侧输出：`0` 处理结果（text）
- 内部：`control` 起点 → `input_text`（承接端子 0）→ 批量 `split` → `proc_text`（`batchMode: "batch"`，每条只处理自己）→ `merge` → `save`（输出路径用相对路径）→ 回连壳输出端子 0。
- 用户要填：输入文本、输出目录。

**示例 B：图片 → 提示词 → 生成 → 保存**

- 壳「图生图流水线」
  - 外侧输入：`0` 参考图（image）
  - 外侧输出：`0` 生成图（image）
- 内部：`control` 起点 → `input_image`（承接端子 0）→ `proc_text`（看图写提示词）→ `proc_image`（参考图接数据槽端口 1+，一次 1 张）→ `save`（`.png`）→ 回连壳输出端子 0。
- 用户要填：参考图、输出目录、图像服务商。
