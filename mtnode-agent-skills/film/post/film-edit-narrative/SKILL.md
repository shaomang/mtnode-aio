# 解说与节奏剪辑

## 何时用

- 手上有口播、访谈、课程、影视长片，要剪成 1–10 分钟的短片或解说成片。
- 素材几十条、不知道先剪哪条；或剪完自己看一遍觉得「拖」「平」「没重点」。
- 要决定钩子怎么前置、第几秒给第一个高能点、段落之间怎么接。
- 要写解说词，并让它与画面、原声、音乐在同一时间轴上对位。
- 粗剪交给别人（或下一轮自己）继续做，需要一份能执行的 EDL 与时间线。
- 不适用：只做转码／抽帧（用 `film-edit-ffmpeg`）；已定平台规格出多版本（用 `film-deliver-platform`）；成片体检（用 `film-post-qc`）。

## 核心原则

1. **先写剪辑决定，再动 ffmpeg**。每个片段先落成一条 JSON／表格：`start`、`end`、`reason`。没有 `reason` 的片段不许进时间线；理由写不出「删了什么、换来什么」，这段就是水。
2. **前 3 秒必须回答「为什么看下去」**。给具体收益、未解问题或反差，不给氛围铺垫；第 5 秒前出现第一个高能点（信息反转、强画面、音乐爆发）。做不到就重写开头，不要靠加特效救。
3. **粗剪只删不加**。第一遍只做删停顿、删口误、删重复、删跑题；不加音乐、不加字幕、不加转场。混着做会导致「不知道是内容拖还是包装拖」。
4. **声音完整性优先于帧精度**。入出点落在句末或自然停顿内，宁可多留 0.3 秒，也不要在词中间切；中间切断会让被切掉的词听起来像被吞掉。
5. **节奏由信息密度决定，不由秒数决定**。「快」不等于短镜头，而是每个镜头都有新信息；「慢」也不等于长镜头，而是画面在空转。
6. **转场是减法，不是装饰**。默认硬切；用一次叠化就少 N 帧时长，四次叠化在一个 22 秒段落里悄悄吃掉 2 秒故事。
7. **素材数量是上限，不是 KPI**。`7/10` 条独立好素材优于 `10/10` 夹带重复；同一素材不得靠改名、变速、镜像、调色伪装成多条。
8. **解说不是默认音轨**。先答「这一段为什么需要旁白」（补信息／给判断／连接因果），答不出就让原声或画面自己说；墙到墙旁白是最常见的失败。

## 工作流

1. **转写**。输入：原片。动作：用词级时间戳转写（ElevenLabs Scribe、Whisper 或本地 ASR），输出 `transcript.json`（`words[{text,start,end}]`）。产出：一份可检索的逐字稿；没有词级时间戳就不要进入第 4 步。
2. **素材治理**。输入：候选素材池。动作：先写视觉契约（主体／动作／镜头／光线／场景／连续性／拒收项），再按素材 ID、作品集数、时间区间去重；下载后按 SHA-256 去重，必要时加首／中／尾抽帧感知哈希。产出：`candidates.yaml`，每条带 `usableRanges[{in,out,evidence}]` 与 `licenseStatus`。
3. **定故事线**。输入：逐字稿 + 候选片段。动作：写 0–1 个 cold open，然后 setup → turn → escalation → payoff；每个 beat 标 `function`（hook／setup／turn／escalation／payoff／CTA）与 `change`（谁知道什么、从什么变成什么）。产出：`story_plan.json`，beat 数 5–9 个。
4. **粗剪**。输入：beat 表。动作：按停顿与句界切；删静音用固定参数（模板 2），删口误逐条 review 后再执行；每段写 `reason`。产出：`clip_plan.json` + `edited_source.mp4` + 重定时的 `transcript.edited.json`。
5. **节奏校准**。输入：粗剪。动作：按 1 秒间隔抽帧通看，标出「连续 2 秒没有新信息」的区间；对照节奏底线表（模板 3）改切点或删段；算 ASL。产出：节奏问题清单（时间码 + 具体改法），不写「再紧凑一点」。
6. **精剪**。输入：校准后的时间线。动作：加 J-cut／L-cut 让声音先入或后出；把反应镜头放到信息落点上；跨段用匹配剪辑（同一形状／动作／构图）替代叠化。产出：`timeline.json`（视频轨 + 原声轨 + 旁白轨 + 音乐轨）。
7. **写解说**。输入：输出时间线。动作：逐块写 `narration.json`（模板 5），按 4.2 字/秒估时、留 0.45 秒头尾；块与块间隔 ≤ 1.6 秒归为同一段。产出：通过时长校验的解说稿（每块实际时长 ≥ 文本预算）。
8. **包装与对位**。输入：解说 + 原声 + 音乐。动作：字幕、花字、音效只在信息点上加；屏幕大字最多比旁白早 1.5 秒，不能晚于旁白；音乐在段落转折处换，不在句子中间换。产出：`final_master.mp4` + 字幕文件。
9. **交接**。输入：全部工程文件。动作：打包母版、`clip_plan.json`、`timeline.json`、`narration.json`、`transcript.edited.json`、参数记录。产出：可复现的工程目录；进入 `film-post-qc`。

## 关键参数与模板

### 1. 剪辑决定（`clip_plan.json`）

```json
{
  "target_duration": "3m",
  "clips": [
    {
      "start": 12.0,
      "end": 28.5,
      "reason": "b02 | hook | knowledge: 未知→威胁 | POV=主角 | 保留倾听反应 | 入点=问题落下 | 出点=沉默结束"
    }
  ]
}
```

`reason` 固定七段：`beat_id | function | change | POV | preferred moment | 入点 | 出点`。缺任何一段，这段就不该进时间线。

### 2. 删静音与删口误参数

| 参数 | 值 | 说明 |
| --- | --- | --- |
| 词间停顿阈值 `gap` | 0.55 秒 | 超过才剪；剪到只剩 0.24 秒自然呼吸 |
| 句界呼吸 | 0.20 秒 | 句子之间保留更长一点 |
| 段界呼吸 | 0.14 秒 | 段落内部可以更紧 |
| 头留白 `head-pad` | 0.22 秒 | 第一个词之前的静音保留量 |
| 尾留白 `tail-pad` | 0.34 秒 | 最后一个词之后保留量 |
| 硬切淡入淡出 | 20–30 毫秒 | 两个词之间直切时加，避免爆音 |
| 预期删除比例 | 全片 15–20% | 远高于 30% 通常说明剪到了词中间 |

- 删口误（口吃、重复词、假起句、重录）必须逐条带上下文复核：强调式重复（「绝不，绝不」）与口吃在机械检测里长得一样。
- 很干净的表达剪出 0 条是合法结果，不要为凑比例硬剪。

### 3. 节奏底线（最短停留）

| 内容 | 最短停留 |
| --- | --- |
| 主打镜头／重点展示 | 1.3 秒 |
| 快切蒙太奇单镜头 | 0.65 秒（低于此只能当氛围，不能指望读字） |
| 标题 + 一组卡片／数据 | 3.5 秒 |
| 网址、二维码、CTA | 3.0 秒，且放在高潮处 |
| 逐个出现的元素 | 间隔 ≥ 0.3 秒，出齐后再停 0.8 秒 |
| 开场叠字快切 | 前 4 秒 ≤ 2 个画面，每行字出齐后停 1.5 秒 |
| 推镜里的每个焦点 | 1.4 秒（不含移动时间） |

密度要求：任何时刻往后 2 秒内必须有新信息或明显画面事件；纯转场 ≤ 0.6 秒；同一版式最多连续 2 次；除高潮与 CTA 外单场景 ≤ 4 秒。ASL（平均镜头长度）落在 3–5 秒；若与段落功能不符且说不出理由，是剪辑错，不是数字错。

### 4. 转场记法与时长算术

| 记法 | 含义 | 消耗帧 | 何时用 |
| --- | --- | --- | --- |
| `Hard cut` | 直切 | 0 | 默认；说不出理由就用它 |
| `Match on <element>` | 按共同形状／动作／位置对齐的直切 | 0 | 两镜共享运动元素，可掩盖轻微不连戏 |
| `Dissolve Nf` | N 帧叠化，跨切点居中 | N | 时间流逝、段落结束；24fps 下 12 帧＝半秒 |
| `Dip to black Nf` | 淡出到黑再淡入 | N（重叠式）或 −N（淡出+停留+淡入） | 硬段落分隔；必须写明是哪种，两者对总时长影响相反 |
| `J-cut Nf` | 后镜声音提前 N 帧 | 0 | 台词、揭示；耳朵领眼睛 |
| `L-cut Nf` | 前镜声音延后 N 帧 | 0 | 环境声、余韵 |
| `Seam blend Nf` | 4–8 帧微叠化 | N | 只用于修生成接缝，记为缺陷不记为风格 |

```text
frames   = seconds × fps
duration = src_out − src_in            （出点为排他）
rec_in(n) = rec_in(n−1) + duration(n−1) − overlap(n)
overlap(n) = N（叠化／甩镜／接缝混合）= N（重叠式黑场）= −N（淡出+停留+淡入）= 0（直切／匹配／J／L）
program  = Σduration − Σoverlap
```

时长对不上时按此顺序查：混入不同帧率的片段、出点按包含计、叠化被 NLE 当成尾随而非居中。

### 5. 解说块（`narration.json`）

```json
[
  {
    "start": 5.0,
    "end": 12.0,
    "narration": "他以为门后是空的。推开的瞬间，灯已经亮着。",
    "pause_after_ms": 250,
    "overlaps_speech": true,
    "emotion": "紧张"
  }
]
```

| 字段 | 规则 |
| --- | --- |
| `start` / `end` | 输出时间线秒数；与上一块间隔 ≤ 1.6 秒视为同一段，紧接上一块结尾 0.35 秒播放，最多比 `start` 提前 1.2 秒（提前部分不压原声对白） |
| `narration` | 按连续思路写完整句，不为字幕换行断句；一段一个 TTS 任务 |
| `pause_after_ms` | 默认 250；转折处 400 |
| `overlaps_speech` | 铺在原声对白上为 `true`；真正静音槽为 `false` |
| `emotion` | 整块一个语气标签，不逐句切 |

写作规则：先有「这一段旁白要干什么」（补前提／给判断／连接因果），再写句子；按 4.2 字/秒估算，块时长不足就删字而不是加速；旁白引出原声时，块尾要留一个让人想听的钩子，原声结束后下一块承接它造成的变化。不要固定「一句一停」，也不要墙到墙。

更细的节奏曲线、转场决策树、`timeline.json` 结构与粗剪／精剪检查表见 `references/narrative-timing.md`。

### 6. 判断标准（交付前逐条过）

- 只读旁白稿，外行能否复述「是什么 → 怎么回事 → 怎么证明 → 结果 → 现在怎么办」；断链就改稿。
- 第 3 秒的画面里是否已有痛点或核心亮点；第 5 秒前是否有第一个高能点。
- 每一处转场能否说出「用硬切会损失什么」；说不出就改回硬切。
- 每个剪辑点是否落在句末／动作完成帧，而不是恢复呼吸之后。
- 时间线上是否存在连续 2 秒无新信息的区间。
- 字幕内容与旁白是否同一件事；有无字幕比旁白晚出现。

## 常见坑

- **症状：剪完听着「一顿一顿」，字被吃掉。** 原因：静音阈值给小了，切点落在词中间。修法：`gap` 提到 0.55 秒以上，句界呼吸给 0.20 秒，切点吸附到句末；硬切处加 20–30 毫秒淡化。
- **症状：开头信息很密，观众仍在第 5 秒划走。** 原因：开头在交代背景，没有给「看下去的理由」。修法：把最反常的结果或最强的画面提到 0–3 秒，背景改成一句大白话，第 5 秒给第一次反转。
- **症状：全片都在说，但没有一个镜头被记住。** 原因：墙到墙旁白，画面沦为配图。修法：每个 beat 指定 `audio_owner`（旁白／原声／音乐／静音），至少 30% 的 beat 交给原声或画面。
- **症状：加了几次叠化后总时长对不上，字幕整体后移。** 原因：转场消耗时长未计入。修法：按模板 4 重算 `program`，字幕与音效整体按新时间线重排，不要单独挪字幕。
- **症状：同一段素材在成片里出现三次，观众觉得在凑时长。** 原因：素材池不足却按目标条数硬凑。修法：回到候选池扩到目标数 2–3 倍；连续两轮仍不足就换来源或缩短成片，不用变速／镜像造新镜头。
- **症状：解说说「看这里」，画面却还没到。** 原因：旁白与画面各自排时间。修法：以画面事件为锚点写旁白，屏幕大字最多提前 1.5 秒，绝不晚于旁白关键词。
