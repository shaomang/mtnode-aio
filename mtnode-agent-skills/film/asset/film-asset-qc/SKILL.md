# 资产与角色一致性质检

## 何时用

- 角色 / 地点 / 道具刚出完参考图，要判断「能不能进正式生成」。
- 已经开始出镜头，发现某个人越拍越不像、某个房间越拍越不像，要定位是哪一层坏了。
- 要交付角色动画或成片前，跑一遍技术 + 视觉的终检。
- 要写资产护照、登记表、验收记录，让下一班人接得上。
- 要给返修排队：手上十条问题，先修哪条。
- 不适用：资产还没建（先做 `film-asset-character` / `film-asset-scene-prop`）；纯风格定调（用 `film-asset-style-bible`）。

## 核心原则

1. **护照是资产的记忆**。一个资产一份护照，描述文字与已批准参考图原样复制进后续提示词；护照没有的字段，等于资产没有这一项。
2. **只有压力测试能写 `locked`**。建资产的人只能写 `draft`，任何人不得手改状态。
3. **角色 10/10 才算锁**。十次测试十次不漂移；低于 10/10 就是失败，不能「9 次也不错」。
4. **地点与道具不套 10/10，但要有人签字**：矩阵跑完、逐项核对后，由用户给显式通过决定。
5. **miss 不许平均**。一条身份漂移就是 miss，不能因为其他几张好看而抹掉。
6. **场景级门禁**：该场里每个角色、每个状态变体、每个地点、每个道具都 `locked`，才能开始生成该场；任何一件还是 draft，就点名被阻塞的场次并停在贵生成之前。
7. **测试用便宜的静态图做完**。压力测试不生成视频；不把测试变成一次昂贵的运镜实验。
8. **四层记录分开**：文字通过、实际生成通过、图像/视频检查通过、用户接受，四件事分别记，不能互相冒充。

## 工作流

1. **核对护照完整性**。输入：资产卡 + 参考图。动作：查 9 个必填段落是否齐全（见「护照字段」）；缺描述或缺参考文件就停止锁定，点名要回哪一步补。产出：完整性结论。
2. **收集真实场景条件**。输入：分场表。动作：列出该资产出现的每个场次、该场的光线、与它同框的每个资产、每场对应的状态变体。产出：条件清单；缺的条件逐条问，不替用户假设。
3. **建压力测试矩阵**。输入：条件清单。动作：按「角度 × 景别 × 实际场次光 × 同框配对」铺行；每个同框对象至少一行双人镜头；同一配对在不同光线下出现就多铺一行。产出：矩阵（写进护照 `## Stress test`）。
4. **写测试提示词并跑图**。输入：矩阵。动作：逐行粘贴护照描述原文（不许缩写）、指向已批准参考文件、正向写角度与景别、复现该场光线、加一个简单静态构图。产出：静态测试图，按版本号存在护照旁。
5. **逐行判定**。输入：测试图 + 参考图。动作：逐行判 `pass` / `miss`，记录输出路径；同框镜头两个身份都要查。产出：得分或决策。
6. **过门禁**。输入：判定结果。动作：角色按 10/10；地点/道具按用户显式通过。通过了才把登记行与护照从 `draft` 改为 `locked`，记录锁定决策与结果路径。产出：锁定记录。
7. **角色动画终检**（有动画/成片时）。输入：预览或渲染产物。动作：跑五层检查（schema → 静态资产 → 浏览器预览 → 运动抽帧 → 成片 ffprobe + 人眼）。产出：检查单。
8. **返修排队**。输入：全部 miss 与问题。动作：按 P0–P3 分级，定「改描述/换参考/局部编辑/重生成」四选一。产出：返修单，每条带位置与现象。
9. **复查与放行**。输入：返修结果。动作：只复跑受影响的测试行；改了描述就复跑全部受影响行，不许只跑改的那一行。产出：复查记录。

## 关键参数与模板

### 1. 护照字段（9 段，缺一段不算护照）

| 段 | 内容 | 硬要求 |
| --- | --- | --- |
| 标题行 | `# <tag> — version <n>` | 一个版本一个文件，绝不覆盖旧文件名 |
| `Status` | `draft` / `locked` | 只有压力测试能写 locked |
| `Type` | character / location / prop | 状态变体也是独立资产 |
| `Scenes` | 出现的场次 ID | 与分场表对齐 |
| `Seed files` | 种子文件或参考板路径 | 按项目既有约定，不新造约定 |
| `## Canonical descriptor` | 一段完整散文，穷尽视觉身份 | 不提供简写版；不为简洁省略细节 |
| `## Reference-sheet prompt` | 描述原文逐字粘入的参考板提示词 | 中性灰底，五视图 |
| `## Reference files` | 版本化路径或 `pending` | 不填虚构路径 |
| `## Stress test` | 矩阵 + 结果 + 锁定决策 | 未跑就留空，不许写「通过」 |

登记表列固定为 `tag · type · version · seed file · scenes · status`，按 tag 与版本精确定位，不静默合并两个 tag、不改已有 tag。

### 2. 角色描述必须覆盖的 9 项

脸、发、年龄线索、体形、皮肤、服装、鞋、随身物与磨损、识别细节。

- 地点额外覆盖：布局、表面、建筑、固定物、尺度、风化、空间地标，以及主/辅/强调色、光特性、内置影调。
- 道具额外覆盖：形制、尺度、材料、颜色、表面处理、磨损、标记、可动件、识别细节。
- 参考板视图固定五项：正面、3/4、侧面、背面、特写（人物或细节）；全部中性灰底、无场景陈设、无叙事动作。

### 3. 压力测试矩阵列

| Test | Angle | Shot size | Scene lighting | Paired asset | Prompt | Result | Verdict |
| --- | --- | --- | --- | --- | --- | --- | --- |

- `Verdict` 只用 `pending` / `pass` / `miss`。
- 每行能追溯到具体场次（用了该场光或配对就要写）。
- 双人镜头逐人查脸、发、年龄线索、体形、服装、识别细节、变体状态。
- 地点查布局、地标、材质、色板、光特性、影调；道具查形制、尺度、材料、标记、磨损、识别细节。

### 4. QA 检查点（六层，逐层过）

| 层 | 查什么 | 判定证据 |
| --- | --- | --- |
| 1 结构校验 | 角色设定、绑定计划、姿势库、动作时间线四份数据是否齐全且互相引用成立 | schema 校验通过 |
| 2 静态资产 | 引用的部件、背景、参考图是否真实存在 | 文件存在 + 路径可解析 |
| 3 浏览器预览 | 载入预览页、截图、收集 console 错误 | `chromium.launch()` → `newPage({ viewport: { width: 1280, height: 720 } })` → `goto(url, { waitUntil: "networkidle" })` → `screenshot` |
| 4 运动检查 | 抽帧比对是否有非平凡差异 | 抽帧至少覆盖开头/中段/结尾各 1 帧（通用经验值：每 0.5s 一帧，总量 ≤12 帧） |
| 5 成片检查 | ffprobe 元数据、时长、分辨率、音轨 | 时长与分镜表一致；分辨率与交付规格一致；有无音轨、采样率 |
| 6 人眼复核 | 断肢、层错、出画、表情不可读、文字乱码、穿模、漂浮、重复物 | 逐帧看；发现问题记位置与帧号 |

判定三档：`pass`（技术全过且表演可读）、`revise`（可修的绑定/时间线问题）、`fail`（缺资产、空渲染、运行失败、运行时长错误）。

### 5. 返修优先级

| 级 | 现象 | 处理 | 是否阻断 |
| --- | --- | --- | --- |
| P0 | 缺资产、空渲染、运行失败、时长/分辨率错 | 修配置或重跑 | 阻断交付 |
| P1 | 身份漂移、断肢、层错、出画、同框两人脸互串 | 改描述或换参考后整批重生成 | 阻断该场 |
| P2 | 表情不可读、文字乱码、材质塑料感、暗部死黑 | 局部编辑或补参考；保留有效部分 | 不阻断，记入待修 |
| P3 | 构图可优化、颗粒度偏好 | 记录，不返修 | 不阻断 |

分级口径是把上游 `pass / revise / fail` 三档落到排期上，属通用经验值；判定本身仍按三档。

### 6. 勾选表

完整可勾选清单（护照 9 段、角色/地点/道具三套逐项核对、动画 QA 六层、返修单模板）见 `references/qc-checklists.md`；护照写法与登记表样例见 `references/asset-passport-spec.md`。

### 7. 判定卡（贴进交付说明）

```markdown
资产: @lin (C03) v2
护照: assets/characters/lin-v2.md
测试: 10 行 / pass 10 / miss 0  →  决策: locked
参考: lin-v2_face.png, lin-v2_back.png（2 张进生成）
未解决: 无
下游可用性: 可进 S04 S07 S11
```

### 8. 每条 miss 的证据留痕（三样，缺一不算记录）

| 证据 | 内容 | 反例 |
| --- | --- | --- |
| 位置 | 场次 + 镜头号 + 画面区域（左颊、右手、背景门） | 「有一张脸不对」 |
| 现象 | 可指认的可见差异（疤缺失、按键 6→7、外套变亮） | 「感觉不像」 |
| 修法 | 四选一：改描述 / 换参考 / 局部编辑 / 重生成 | 「再生成一次看看」 |

- 修法必须能回答「改哪一段文字、换哪一张图、重生成哪些行」。
- 只保留有效部分：局部编辑优先于整套重生成，除非错在描述本身。
- 不许用加雾、加遮挡、裁切或特写藏住被要求展示的连接错误。

### 9. 门禁速查（一句话版）

| 问题 | 答案 |
| --- | --- |
| 角色能进正式生成吗 | 10 行测试 10 行 pass，登记行 locked |
| 地点/道具能进吗 | 矩阵跑完 + 用户显式通过 + locked |
| 这一场能开拍吗 | 该场所有角色/变体/地点/道具都 locked |
| 资产能改参考图吗 | 能，但新版本新文件、新护照版本，旧版本保留 |
| 动画能交付吗 | 六层全过 + ffprobe 时长/分辨率/音轨无误 |

## 常见坑

1. **描述被缩写** → 测试提示词里少了「左眉尾 1cm 疤」→ 每次都要重查 → 护照描述必须是完整散文，测试提示词逐字粘贴。
2. **只跑通过的那几行** → 矩阵看起来全绿 → 十行必须全跑；改了描述要复跑全部受影响行。
3. **用视频做压力测试** → 成本高、变量多、定位难 → 全程用便宜静态图；测试不为画面加多余运镜。
4. **把「有文字约束」当通过** → 描述里写了六个按键，图里七个 → 以图为准判 miss，不能反向改基准。
5. **状态变体被基准资产顶替** → 该湿透的镜头用了干爽参考 → 变体必须是独立资产、独立护照、独立行。
6. **一条 miss 被「其他都好」平均掉** → 锁定后整批漂移 → 任何一条 miss 都保持 draft。
7. **动画只看了预览截图** → 交付后才发现时长错、无音轨 → 成片必须 ffprobe 查时长/分辨率/音轨，再抽帧人眼复核。
8. **锁定后偷偷改参考图** → 下游全部对不上 → 新版本新文件、新护照版本，旧版本保留。
