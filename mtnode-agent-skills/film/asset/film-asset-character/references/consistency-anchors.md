# 一致性锚点手册：Soul ID、参考图、种子、换脸

跨镜头「还是这个人」靠三件事：一张不会自我漂移的基准图、一组明确的锚点参数、
一套每次生成都照抄的交接文本。本文件给可执行参数与判定线。

## 1. 四种锚点，各自锁什么

| 锚点 | 锁住 | 不锁 | 何时用 | 何时别用 |
| --- | --- | --- | --- | --- |
| Soul ID / 角色库 | 脸、肤色、基本五官 | 服装、光线、构图 | 同一角色 ≥3 个镜头 | 只出一张图；或本片要大幅造型变化 |
| 参考图（@ 图） | 你指定的那部分（身份 / 服装 / 光位） | 未指定的部分 | 想精确控制「只锁脸不锁姿势」 | 参考图本身分辨率低、脸在暗部 |
| 种子 seed | 同描述下的整体分布（脸、光位、构图倾向） | 换描述后不保证 | 同场次补拍、同机位重出 | 换角度换场次还硬用同一个 seed |
| 文字锚点 | 结构、材质、磨损、比例 | 具体长相 | 前三种都拿不到时 | 用形容词代替结构描述 |

组合优先级（冲突时从高到低）：**用户已锁定的资产 > 参考图 > Soul ID > 种子 > 文字**。

## 2. 参考图怎么给

| 项 | 数值 | 说明 |
| --- | --- | --- |
| 送进生成的张数 | 2–3 张 | 正面 / 3-4 / 侧面 |
| 张数上限的替代方案 | 整张角色板当 `@Image1` | 特征漂移时改用整板，比继续加单图有效 |
| 单张图要求 | 正面或 3/4、均匀光、中性到微笑、不糊、单人 | 模糊、暗部、多人都会让锚点失效 |
| 每张图职责 | 只写一个 | 「锁脸」与「锁光位」分开，混在一张会把光也带走 |
| 建板张数（不送生成） | 主角 10–20、地点 8–15、道具 3–5 | 板是资料库，进生成的只是其中 2–3 张 |

反例：把一张暗部全景当人脸锚点 → 模型只能猜脸 → 整批一起错。首张参考必须先核对是否满足人物与装备目标。

## 3. 权重与 denoise（模型无关经验值）

| 控制 | 建议值 | 低于下限 | 高于上限 |
| --- | --- | --- | --- |
| 身份参考权重 | 0.6–0.8 | <0.6 脸自由发挥 | >0.9 姿势、构图被一起锁死 |
| 只锁脸（MJ `--cref --cw`） | `--cw 0` | — | `--cw 80` 会把服装一起锁 |
| 改状态（图生图） | denoise 0.25–0.4 | 动了但没变 | >0.5 房间与光跟着变 |
| 风格参考 | 1 个主锚点 + 1–2 个辅 token | — | 3 个以上 token 注意力被稀释 |

> 上述数值是跨模型的通用经验值，不是任何一家上游的实测标定。不同 UI 的
> 「参考强度」方向可能相反（有的越高越像，有的越高越自由），必须在一张测试图上先试方向。

## 4. 种子与版本

| 规则 | 做法 |
| --- | --- |
| 一个角色一个基准 seed | 写进卡头，补拍同机位时复用 |
| 换角度 | 换 seed，只保留 Identity Block 与参考图 |
| 新状态 | 新 seed + 新编号，不在旧卡上改 |
| 版本 | 参考图文件名带版本；新版本新文件，绝不覆盖旧文件名 |
| 记录 | 卡里记：seed、参考图路径、权重、实际提示词、审核意见、结果路径 |

## 5. 多状态变体

| 做法 | 步骤 | 适用 |
| --- | --- | --- |
| 方案 A：提前出变体板 | 在资产阶段直接生成「湿透 / 受伤 / 换装」独立板，各自编号 | 状态会在片中反复出现（推荐） |
| 方案 B：改图 | 用已批准基准 + denoise 0.25–0.4 定点改，只写要变的部位 | 一次性小改，且基准图质量高 |

禁止：用文字「让他出汗 / 弄湿」在生成时临时改状态——模型会自由发挥，脸跟着糊。

`@lin`、`@lin_wet`、`@lin_blood` 是三个资产、三份护照、三行登记；变体卡必须写明与基准的可见差异和不变量（脸、疤、身高、步态）。

## 6. 换脸（后期补救，不是资产方案）

| 项 | 要求 | 来源 |
| --- | --- | --- |
| 源图 | 恰好一张脸；分辨率越高越好 | faceswap |
| 目标 | 任意含可见脸的视频 | faceswap |
| 提交 | `POST /v1/workflows/executions`，`workflow_type: "FaceswapNode"`，`input.source_image_url` + `input.target_video_url`，头 `X-Api-Key` | faceswap |
| 轮询 | 每 10 秒查 `GET /v1/workflows/executions/{id}`，直到 `completed` | faceswap |
| 交付 | 取返回 `video_url` | faceswap |

换脸只解决「脸不对」，不解决体型、发型、服装、步态；这些必须在角色卡里对，否则换完还是不像。换脸后仍需按质检表复查边缘、牙齿、耳廓、发际线。

## 7. 交接包（下游只读这四样）

```markdown
角色: @lin (C03) v2 / 状态 locked
Identity Block:
  <角色卡原文，逐字，不改写不缩写>
参考:
  face_front: assets/characters/lin-v2_face.png   （职责: 锁脸，权重 0.7）
  full_back:  assets/characters/lin-v2_back.png   （职责: 锁体型，权重 0.7）
锚点:
  Soul ID lin_v2 / seed 883421 / 参考职责: 只锁身份，光位与构图按场次重设
禁止:
  换脸、改发型长度、加帽子、把参考图的姿势一起搬过来
```

## 8. 一致性失败的定位顺序

1. 先看参考图：脸是否清晰、是否单人、是否暗部。
2. 再看提示词：Identity 与 Motion 是否混写；是否重复描述五官。
3. 再看权重：是否 >0.9 把姿势锁死，或 <0.6 完全放开。
4. 再看场次光：参考图的光位是否被误当成本场光位。
5. 最后才改卡：补「发尾接触位置」「肩宽」这类可画字段，不要加形容词。
