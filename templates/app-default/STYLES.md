# 新建应用默认页 · 设计风格系统（STYLES.md）

面向「改这套模板的人」：新增一种风格、或调整已有风格之前先读这里。
真源口径（产品级）见根目录 `DESIGN.md` §4；本文件只管这一套模板的内部契约。

## 1. 一份内容 + 一份基础 + 七份风格

```
templates/app-default/
  index.html          页面 DOM + Markdown 正文 + 页内渲染器（**与风格无关，逐字相同**）
  base.css            结构与排版：标题栏、H1、正文、三步、引用、脚注、响应式、入场动画
  styles/<id>.css     一套风格 = 一份「语义变量赋值 + 少量质感覆盖」
  previews/<id>.png   该风格真实渲染出来的首屏预览（新建应用 / 换风格浮层里给用户看的那张）
  STYLES.md           本文件
```

`index.html` 里有两个占位符（主进程 `apps-store.js` 在写入应用目录时替换）：

| 占位符 | 换成什么 |
| --- | --- |
| `{{APP_NAME}}` | 应用标题（HTML 转义后） |
| `{{STYLE}}` | 风格 id（写在 `<html data-style="…">` 上） |

模板里那行 `{{STYLE_CSS}}` 注释标记的位置，就是注入时把 `base.css` 与
`styles/<id>.css` 内联进来的地方（见 `apps-store.js` 的 `defaultPageHtml()`）。

**注入后整页仍是单文件自包含**：样式是内联的，所以写进应用目录的 `index.html`
不需要再跟着复制 `base.css` / `styles/`。应用目录里也不会出现这两个目录。

## 2. 风格清单（id 唯一真源是 `apps-store.js` 的 `APP_STYLES`）

| id | 名称 | 世界 | 默认 |
| --- | --- | --- | --- |
| `minimal` | 极简 · 工程笔记本 | 深墨底、一根竖线、材料只有线 / 留白 / 一个紫点 | ✅ 出厂默认 |
| `tech` | 科技 · 工程网格 | 石墨底 + 冷青强调 + 等宽标记 + 刻度式编号 | |
| `warm` | 暖读 · 纸与衬线 | 纸白底、暖棕墨、大字号衬线、行距放宽 | |
| `editorial` | 编辑 · 杂志内页 | 白纸、超大衬线标题、首字下沉、双线报头 | |
| `terminal` | 终端 · 磷光绿 | 单一色相等宽屏、扫描线、`>` 提示符 | |
| `glass` | 玻璃拟态 · 夜光 | 两块大面积光斑 + 磨砂面板 + 大圆角 | |
| `retro` | 复古印刷 · 棉纸专红 | 棉纸白、粗线条、网点编号、一处红色错版 | |
| `custom` | 自定义 | **没有模板**：选中它 = 先问用户要什么风格，再照答案做入口页 | |

浅色四套（`warm` / `editorial` / `retro`）与深色三套各占一半 —— 让「换风格」真的换的是
气质，而不是同一个深色页换了个强调色。

### 2.1 「自定义」不是第八套模板

`custom` 是清单里唯一的**询问入口**，它与上面七套的差别是结构性的：

- **没有 `styles/custom.css`、也没有 `previews/custom.png`**（所以 `appPresetStyleIds()`
  把七套预设单独列出来：第 3 节的「新增一套风格」只对预设那七条生效）。
- `normAppStyle("custom")` 回落 `minimal`（生成入口页 / 取预览图时它必须落到一套真模板上，
  页面绝不花）；`normStoredAppStyle("custom")` 原样留住 —— `app.json` 的 `style` 要记住
  「用户选的是自定义」，否则开发页与「换风格…」会把它当成极简，问风格这一轮就回不来了。
- 选中它之后：**新建应用**建完就停在开发页、往输入框填一句「你要什么风格」的提问；
  **换风格**只记下这个选择（入口页这一轮不动），同样把你带回开发页答那一句。
  用户点发送即走正常首轮开发会话，会话契约里多一段「本轮先问清风格再动代码」
  （`renderer/app-apps-dev.js` 的 `devStyleAskContract`，只在 app.json 里 style=custom 时附加）。
- 风格定下来之后由那次开发会话改写应用目录里的 `index.html`；如果后来想回到预设，
  在「换风格…」里选回七套之一即可（照旧用模板重写入口页）。


## 3. 新增一套**预设**风格要做什么（照单全做）

> 这一节只对预设（`appPresetStyleIds()` 那七条）适用。「自定义」没有模板文件、
> 也不参与预览渲染，别照这一节给它造 `styles/custom.css`。

1. 写 `styles/<id>.css`：按 `base.css` 顶部的变量清单赋值（外观层全要，结构层别改），
   需要质感时用 `--texture` / `--texture-op`，或按 `[data-style="<id>"]` 加少量覆盖。
2. 在 `apps-store.js` 的 `APP_STYLES` 里加一条（`id` / `zh` / `en` / `why`）；id 用
   ASCII 小写短横线 —— 它同时会写进 `app.json` 的 `style` 字段。
3. 跑一次预览渲染（在真实模板上出图，不是另画一张）：
   ```
   node scripts/app-style-previews.mjs            # 全部重出
   node scripts/app-style-previews.mjs tech       # 只重出 tech
   ```
   产物写 `templates/app-default/previews/<id>.png`，同时留一份到 impeccable 的取证目录。
4. 在 `renderer/i18n.js` 补词条：`风格名称(<id>)` 的英文名，以及浮层里那句说明的英文。
5. 在 `test/smoke-apps.js` 的 [10] 里确认新风格被清单、模板、预览三方同时接住
   （预设份数 = `appPresetStyleIds().length`，断言里别写死 7）。
6. 更新本文件第 2 节与根目录 `DESIGN.md` §4 的口径；`.impeccable/surfaces/` 里那份默认页
   简报也要跟上（它是给设计会话读的）。

## 4. 风格必须守住的底线

- **可读性不看风格**：正文与次要文字 ≥ 4.5:1，脚注 ≥ 4.5:1（浅底同理）；正文不小于 15px。
- **只有一处作者化的花样**：每套风格只允许一个签名动作（错版、提示符、光斑…），
  其余元素必须安静；不要三处都在发光 / 都有阴影 / 都在旋转。
- **浏览器自己的表面也要跟**：`::selection`、`:focus-visible`、`scrollbar-color`、
  `caret-color` 都由变量驱动，不许留着默认灰蓝。
- **响应式三条线**：1200×820（默认窗口）、640×480（最小窗口）、约 520px（开发页预览列）；
  窄了靠断点收结构与字号，不靠整体缩放。
- **动效**：只保留「竖线画出 + 三步落位」这一处入场，`prefers-reduced-motion` 与
  `?still=1` 下必须全部停住。
- **正文一字不改**：八条风格共用同一段 Markdown 与同一套行为（中英切换、关闭按钮、
  自动保存提示），风格只动视觉。

## 5. 落地口径

- 新建应用时在浮层里选（默认 `minimal`），选择写进 `app.json` 的 `style`。
- 「应用中心 → 开发」页的 ⋯ 菜单里有「换风格…」，确认后按所选风格重写应用目录的
  `index.html`（不生成备份；应用目录里用户后来改过的内容会被覆盖，确认框里已写明）。
- 选「自定义」时**两处都不套模板**：新建的入口页落 `minimal` 那套（只是占位），
  然后开发页问一句「要什么风格」；用户答完，由那次开发会话按答案改写入口页。
- 已存在的应用 / 已下载的应用不动它们的文件；`app.json` 没有 `style` 一律按 `minimal` 看待。
