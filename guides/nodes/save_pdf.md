# PDF生成

把上游的**文本 / Markdown** 排版成一份 PDF 文件落盘。入口：画布空白处右键 → 「处理节点」组里**鼠标悬停**在 **文本生成** 上展开二级菜单 → **PDF生成**（与「文本处理（LLM）」同在这一个悬停展开的二级菜单里，和「视频生成 / 音频生成」是同一种展开方式）。节点配色与「保存」节点一致（同一个保存族）。

它不是「另存为 txt」：正文按 Markdown 排版（标题层级、段落两端对齐、列表、引用、表格跨页重复表头、代码块折行、图片自适应），并用应用内同一套渲染器（`renderer/math-render.js`，KaTeX 离线内置排版，缺 KaTeX 时回退自研子集）把公式画成**排版结果**——画布预览里看到的公式长什么样，PDF 里就什么样。

## 支持的输入
- **连接文本来源**：文本节点 / 文本处理（LLM）/ 智能任务 / 素材节点文本条目 / 函数输出等，凡是输出文本的都能接。
- 多个文本输入可以一起接：单份 PDF 里按顺序拼起来，中间用分隔线隔开。
- 接不了图像 / 音频 / 视频（保存族里只有「保存」节点按输入自判媒体类型）。

## 公式
`$…$`、`$$…$$`、`\(…\)`、`\[…\]` 四种写法都渲染，支持分式 / 根号 / 上下标 / 希腊字母 / 大算符 / 矩阵 / cases / aligned / 重音（`\hat \bar \vec \overline`）/ `\substack` / `\xrightarrow` 等；围栏代码块与行内代码里的 `$` 不当公式。

## 生成时机
**连上不会自动生成，必须点节点上的 ▶ 才会生成一份 PDF**（控制节点指挥同样算显式运行）。
接线、上游更新都不会触发自动落盘——这是 PDF 生成与其它保存节点的区别（它没有「自动保存」开关）。

## 设置（节点头部 ⚙）
- **保存路径**：相对工作目录或绝对路径，后缀固定 `.pdf`（写成别的会自动纠正）。**留空 = 默认用「输入节点」的标题命名**（例如上游是「文本节点 2」就得到 `文本节点 2.pdf`）；节点卡片上的「文件名」输入框也能直接改名，留空即回到这套默认命名。
- **PDF 版面**
  - **页面尺寸**：A4（默认）/ A3 / A5 / Letter / Legal
  - **横向**：宽表格、宽公式更合适
  - **页边距**：无 / 窄 / 标准（默认）/ 宽
  - **正文字号**：小 / 中（默认）/ 大
  - **显示页码**：页脚居中「当前页 / 总页数」
  - **文档标题**：留空则不加；填了在正文顶部加一行居中大标题
- 摘要行显示「实际落盘路径 · 版面」，旁边的「浏览 / 位置 / 打开」照旧：**打开**交给系统默认 PDF 阅读器。
- 节点上方（头部）有一枚 **PDF 图标小按钮**（纸张 + 折角 + PDF 字样，不再写「打开」两个字）：用系统默认 PDF 阅读器打开已生成的 PDF；还没生成时点它只提示先按 ▶。
- **未选中（预览 / 浏览形态）不显示任何预览图**：卡片预览区只列一行文件名（尚未生成时是一行提示），打开动作走头部那枚小按钮。
- **选中（编辑形态）** 时卡片 body 是一枚铺满的 PDF 图标按钮（图标下带文件名），点一下同样交给系统默认应用打开。

## 批量
- **批量**（BATCH）：每个条目生成一份 PDF，命名规则与保存节点一致（`文件名_条目标题.pdf`）。
- **聚合**：全部条目合成一份 PDF，每个条目的标题当小标题（`## 标题`）。

## 端子
- **输入**：文本（可多个）；图像 / 音频 / 视频接不了。
- **输出**：1 个数据端子＝**本次生成的 PDF 落盘地址**（与「保存」节点一样有内容输出端子：文本保存给写盘的正文、图像 / 音视频保存给最后落盘的文件、PDF 生成给落盘地址）。可以直接连给下游节点继续处理，也能被提示词里的 `@标题` 引用；还没生成过时回落成上游输入的内容。
  - 它只是「落盘结果」的回执，不是控制端子：接不接线都不影响「点 ▶ 才生成」这条口径。
  - 与内置工具「Markdown 转 PDF」的分工：两者都是**上游文本 → PDF 落盘**，节点形态回的是**落盘地址**、且版面可在 ⚙ 里调；工具形态回**文件路径 + 字节数**两个出参、版面固定（见下一节）。

## Agent 也能生成 PDF（内置工具「Markdown 转 PDF」）
同一条写盘内核还有一个**内置工具**形态：工具库（顶栏那一格）里的 **Markdown 转 PDF**
（`markdown-to-pdf`，默认开「会话随时可调用」）。Agent / 会话可直接调用它，入参
`Markdown内容` / `源文件路径`（本机 `.md` / `.txt`，正文留空时才读）/ `输出路径`（必填），
出参 `文件路径` / `字节数`。
- 与这个节点的差别：工具形态回的是**文件路径 + 字节数**两个出参（Agent 拿得到「写哪儿了」和多大），节点形态回的是单一**落盘地址**（见上面「端子」）；工具形态还**没有版面下拉**（固定 A4 · 标准页边距 · 中号字 · 带页码）—— 要横向 / A3 / 大字号，用本节点。
- 两者共用 `pdf-write.js` 的同一份排版内核（隐藏打印窗 + `printToPDF`，公式同源）：`mtnode.writePdf`
  → 主进程 `fnPdfWrite` → `writeTextPdf`，与「PDF生成」节点的 `pdf:writeText` 是同一条路。
- 也把它插到画布上当普通工具节点用（右键 → 工具 → 工具库），同样点 ▶ 即可跑。

## 实现口径
排版本体在主进程 `pdf-write.js`（隐藏窗口 + `printToPDF`），页面模板 `renderer/pdf-print.html` + `renderer/css/pdf-print.css`，公式复用 `renderer/math-render.js`（与审阅 / 预览同源）；渲染层执行口径在 `renderer/app-nodes.js` 的 `savePdfOnce`。数据不落应用目录。Agent 侧的内置工具形态见 `docs/tool-library.md` §4b（条目三）。
