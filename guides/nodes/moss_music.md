# MOSS-Music 音乐理解（本地 · 音频 / 视频 → 分析结果）

画布右键 → **处理节点 › 音频生成 › MOSS-Music 音乐理解**（节点类型 `moss_music`，插件 id `moss-music`，插件类型 `mossmusic`）。
本机常驻后端（默认端口 **8790**），跑 OpenMOSS 的 **8B 音乐理解 Instruct 模型**（直接答，快）。

它做的是**理解**，不是生成：输入一段音频或带音轨的视频，输出**文字分析**，并落 **md / json / srt** 三份产物。
要「歌词 → 整曲」请用 `yue_gen` / `music_gen`；本节点不会产出音频。

## 端子

- **输入**
  - 端口 0 = **音频 / 视频**（接音频输入节点、视频输入节点或素材节点的输出；本机文件路径均可，视频会先抽音轨）
  - 端口 1 = **自由提问**（文本；留空则用节点上选的任务预设）
  - 端口 2 = **控制输入**（触发分析）
- **输出**
  - 端口 0 = **结果文本**（模型整段回答）
  - 端口 1 = **JSON**（结构化结果：模型 / 量化 / 时长 / 分段 / 时间戳 cues / 产物路径）
  - 端口 2 = **产物路径**（md 文件的绝对路径）
  - 三个都是数据端子，**没有控制输出**。

端口 0 必须有值：没接音频 / 视频时点 ▶ 会直接提示「没有音频 / 视频路径」，不会起后端。

## 任务预设

节点 body 上的「任务预设」下拉，决定不写自由提问时实际发出去的提示词：

| 预设 | 产出 |
| --- | --- |
| **完整分析**（默认） | 逐句歌词 + 时间戳、曲风 / 情绪 / 配器 / 曲式、调式 / 速度 / 和弦进行、关键时间点 |
| **整曲描述** | 风格 / 情绪 / 乐器 / 人声 / 段落变化 + 关键时间点，偏概述 |
| **时间戳歌词** | 只出逐句歌词与 `mm:ss` 时间戳 |
| **曲式与和弦** | 前奏 / 主歌 / 副歌 / 桥段 / 尾奏、调性、速度、和弦进行 |
| **情绪标签** | 3~5 个可用于检索的场景 / 情绪标签 + 理由 |

自由提问会**覆盖**预设（端口 1 接了文本，或节点 body 里填了字），适合追问：「副歌的和弦进行是什么？」「第 2 分钟发生了什么？」

## 参数（节点 body）

- **模型**：固定 **Instruct**（Thinking 档已移除，老工作流里的 thinking 会自动按 Instruct 跑）。
- **量化档**：`int8`（≥16GB，默认）· `int4`（≥12GB）。全精度档已移除；显存不够时先降档，再谈换卡。
- **长音频**：勾选后，超过 **5 分钟**的音频按 **3 分钟一段、相邻段重叠 5 秒**切片，逐段分析后把时间戳平移回原曲并去重。
  默认关闭；整曲很长时再开，更慢但不会因为超长被截断。
- **输出路径**：没有这个参数。产物固定写到**应用托管的画布资产目录**，用端口 2 拿 md 路径，需要归档就在下游按这个路径取用 / 复制。

## 运行口径

- 点 ▶ 后自动拉起后端并装载模型；首次需 **30~60 秒**启动 + 装载，之后就绪很快。
- 后端是**常驻单例**：关掉 MTNode 不会停它，下次启动直接复用；要停就去插件卡片「控制台」点「停止服务」。
- 节点上的 **■** 终止本次分析：后端在每个分块边界停下（3 秒不退就结束进程），并**连模型一起卸载**、显存立刻还回来；
  下次点 ▶ 会自动重起后端并重新装载（30~90 秒）。
- 全局同一时刻只允许 **1 个音视频任务**（与音乐 / 语音 / 视频节点共用一把媒体锁）；被占用时状态行会写明是谁占着。
- 单次分析超时 **45 分钟**；超时先开长音频分块、降量化档，或换短音频。
- 模型没给出逐句时间戳时，节点不会伪造对齐：按字数把已知时长摊到句子上，JSON 里标 `estimatedTimestamps: true`，srt 仍会写，可当草稿用。

## 产物

每次分析写三份（同一个 stem）：

- `<stem>.md`：元信息 + 提问 + 回答 + 时间轴；
- `<stem>.json`：完整结构化结果（模型 / 量化 / 时长 / 分段 / cues / 文件路径）；
- `<stem>.srt`：时间戳字幕（估算时同样注明）。

## 安装与排错

- 没装时节点 body 顶部会出现「⚠ MOSS-Music 插件未安装」警示条：到顶栏「**插件**」→「**MOSS-Music 本地音乐理解**」卡片里
  选安装目录 → 点「**安装（国内镜像）**」。建议预留 **≥60GB** 磁盘（8B 权重约 18GB）。
  该插件目前标着「插件测试中」，安装链较长、可能失败；失败按下面的修复入口走。
- 安装步骤 / 日志 / 进度在**通用安装窗**里（10 步：磁盘 → Python → CUDA torch → 依赖 → 源码 → 权重 → 校验 → ffmpeg → .env → 冒烟）；
  失败可点「重试」，也可以点「**交给 mtnode 会话修复**」按技能 `moss-music-install` 的【自我修复】修。
- 卡片上三颗按钮：**安装 / 重装** · **启用 / 停用** · **控制台**。控制台里有服务状态、量化档、显存读数、
  试听 + 自由提问、实时日志——生成报错先看那里的日志尾部。
- 节点 body 底部状态行会带错误码（如 `vram_low` / `load_failed` / `generate_timeout`）；主机也会弹错误报告并给「🤖 自动修复」入口。
  主动取消、正在安装、磁盘不足、没有 N 卡、驱动太旧、安装目录不合法这几类**只报告不自动修**（详见手册「插件报错弹窗与自动修复」）。
- 装完仍报 `not_installed`：确认装的是这个插件、安装目录没被移动；「补装要件」会重跑安装并补齐缺项。

## 注意

- 输出目录是应用托管目录，**不要**把大文件长期堆在那里；需要归档就在下游按「产物路径」取用 / 复制。
- 移除 / 停用插件**不删**已生成的 md / json / srt（在画布资产目录里），也不删安装目录里的权重——都要你自己清理；移除前先到控制台停掉常驻后端。
- 权重 / 源码都在用户选的安装目录，不写应用文件夹；换安装目录等于换一份完整后端（权重会重新下）。
- 上游源码 Apache-2.0；模型权重的许可以官方模型卡为准，商用前自行核对。
