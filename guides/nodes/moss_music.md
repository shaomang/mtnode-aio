# MOSS-Music 音乐理解（本地 · 音频 / 视频 → 分析结果）

画布右键 → **处理节点 › 音频生成 › MOSS-Music 音乐理解**（节点类型 `moss_music`）。本机常驻后端（默认端口 8790）跑 OpenMOSS 的 8B 音乐理解 Instruct 模型：输入音频或带音轨的视频，输出**文字分析**。它只做理解、不产出音频 —— 要「歌词 → 整曲」请用 `yue_gen` / `music_gen`。

## 端子
- **输入**：端口 0 = 音频 / 视频（必填；视频会先抽音轨）· 端口 1 = 自由提问（文本，留空则用任务预设）· 端口 2 = 控制输入
- **输出**：端口 0 = 结果文本 · 端口 1 = JSON（模型 / 量化 / 时长 / 分段 / cues / 产物路径）· 端口 2 = md 产物绝对路径

## 设置
- 在节点头部 **⚙ 设置** 打开的设置窗口里改。
- **任务预设**：完整分析（默认）/ 整曲描述 / 时间戳歌词 / 曲式与和弦 / 情绪标签；自由提问（端口 1 或节点上填了字）**覆盖**预设
- **量化档**：`int8`（≥16GB，默认）/ `int4`（≥12GB）
- **长音频（自动分块，30 分钟以上再开）**：默认关；按静音切块后分段分析再合并，更慢但不截断
- **单段输出上限**：2048 / 4096（默认）/ 8192 tokens；撞上限会自动把这段对半再切后合并
- 没有「输出路径」参数：产物固定写应用托管的画布资产目录（同 stem 的 md / json / srt），归档就按端口 2 的路径取用

## 注意
- 端口 0 没值时点 ▶ 直接提示「没有音频 / 视频路径」，不会起后端。
- 后端是常驻单例，关掉 MTNode 也不停；节点上的 ■ 让后端在分块边界停下并**连模型一起卸载**，显存立刻还回来，下次 ▶ 重新装载。
- 全局同一时刻只允许 1 个音视频任务（与音乐 / 语音 / 视频节点共用媒体锁）；单次分析超时 45 分钟。
- 没装时节点顶部有「插件未安装」警示条：**插件 › MOSS-Music 本地音乐理解** 卡片里选安装目录后点「安装（国内镜像）」，预留 ≥60GB；失败点「交给 mtnode 会话修复」按技能 `moss-music-install` 修。
