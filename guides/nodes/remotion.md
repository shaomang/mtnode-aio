# Remotion 视频（React 动效合成）

「Remotion 视频」节点由应用插件 **remotion** 提供：**构建期**由 Agent 把需求写成一整份 Remotion（React）工程；**固化后**运行期只做脚本渲染，把工程渲染成 `.mp4`，**再也不会调模型**——同一份工程每次跑出来的结果完全一致。渲染在本机完成，不依赖云端视频服务。每次运行只生成一个视频文件，视频交给下游「保存」节点保存（节点自身不设输出路径）。

## 两种状态：未固化 / 已固化

| | 未固化 | 已固化 |
|---|---|---|
| 来源 | 节点里只有功能说明，还没有工程源码（新节点 / 老画布） | 节点里存着整份工程源码 + 端子契约 |
| 点 ▶ | 不做现场生成：贴了合成代码 / 复用了包内工程 → 按它渲染；一条线都没接 → 提示先点「构建」 | **纯脚本渲染**，一个模型都不调 |
| 端子 | 无差别动态端子（端口 0、1、2… 连一条多一条） | 按工程里声明的契约钉死（每项一颗，末位一颗控制口） |
| 建议 | 点「构建」固化成脚本 | 要改画面 → 点「构建」填新需求（默认在现有源码上迭代） |

> 节点正文框是**功能说明**（这个节点干什么，只给人看）；构建需求在「构建」弹窗里填、单独存成 `remotionBuildNote`。老画布上写在正文框里的旧构建需求，第一次打开构建弹窗时会自动复制进去（正文框内容原样保留）。运行期不再有「现场生成一次」这条路。

## 构建（固化）

1. 点节点卡片上的「**构建**」（或 ⚙ 设置窗里的「构建…」），在弹窗里写这次构建的需求：画面、节奏、文字、素材怎么用。
   - 弹窗里还有「忽略现有源码，从头重建」勾选：默认**不勾** = 在现有源码上迭代，只改必要的文件。
   - 构建需求不能为空（空着不能构建，也不会退回功能说明或上一次的值）。
2. 构建 Agent 会：
   - 在 `<工作目录>/.mtnode/remotion/<节点 id>/build/src/` 下写出**多文件**工程（入口固定 `Composition.tsx`，可拆 `components/*.tsx` 等）；
   - 声明端子契约（见下）；
   - 写完先做静态校验（导入白名单 / 入口导出 / 相对文件 / 契约），再跑一次 **≤2 秒的短试渲染**；
   - 不通过就把报错回灌给 Agent 自修，**最多 3 轮**；3 轮仍不过 → **保留上一版能跑的源码**，只把报错写在节点上。
3. 通过后「**固化**」：整棵源码写进节点字段，端子按契约重排，状态条显示「已固化：N 个文件 · M 颗端子」。

构建 Agent 的模型三项（预设 / 供应商 / 模型 / 思考强度）在 ⚙ 设置窗里单独选，留空 = 跟随「设置」里的全局默认。

## 端子契约（写在源码里）

工程入口里 `export const inputs = [...]`，宿主据此生成节点端子——**改代码即改端子**，单一真源：

```tsx
export const inputs = [
  { key: "hero",  kind: "image",  label: "主图", required: true },
  { key: "voice", kind: "audio",  label: "旁白" },
  { key: "poster", kind: "image", label: "结尾图" },
  { key: "lines", kind: "text",   label: "台词", list: true },
  { key: "speed", kind: "number", label: "速度" },
];
```

- `kind` ∈ `image` / `audio` / `video` / `text` / `number` / `boolean` / `json`；`key` 就是组件收到的 props 名。
- `list: true` = 这颗端子可以接多路，值变成数组（多段视频 / 多句台词）。
- `required: true` 只是标记，没接线时宿主会在节点日志里点名，工程要自己兜默认值。
- 契约里没有的端口不存在；重构建后**同 key 的接线保留**，契约里已消失的端子上的接线会被断开并在状态条提示条数。

## 素材怎么进画面（props 约定）

| 端子 | 组件收到什么 | 怎么写 |
|---|---|---|
| image | `data:` URL 字符串 | `<Img src={hero} />` |
| audio / video | **裸文件名**（已落在工程 `public/`） | `staticFile(voice)` 包一层再给 `<Audio>` / `<OffthreadVideo>` |
| text | 字符串（`list` 时字符串数组） | 直接用 |
| number / boolean / json | 相应标量 / 解析好的 JSON | 直接用 |

**接了 audio 端子且探得到实际时长时，成片总长 = 音频时长**（覆盖节点设置里的「时长」）；否则用节点设置。宽高 / fps 一律由节点设置为准（工程里用 `useVideoConfig()` 读，别硬编码）。

## 工程约束

- 依赖只有 `react` + `remotion`，加上**工程内相对文件**（`./components/Title`）——不允许任何第三方 npm 包，宿主不会 `npm install`。
- 入口 `Composition.tsx` 必须导出 `Main`（React 组件），根容器 `<AbsoluteFill>`；`index.tsx` 由宿主生成。
- 不要在工程里写 `package.json` / 不要跑渲染；构建完成由宿主渲染。

## 设置窗

⚙ 设置窗分五段：

- **功能说明（与构建无关）**：与节点正文框同一字段，只描述这个节点干什么；构建 Agent 不读它；
- **构建 / 验证**：构建…（开构建弹窗）/ 试渲染 / 校验源码 三个按钮 + 状态（构建报错、试渲染报错、固化时间、文件数与端子数）；
- **构建 Agent 的模型**：预设 / 供应商 / 模型 / 思考强度（空 = 跟随全局）；
- **源码（固化工程）**：多文件编辑器（选文件 / 改 / 新增 / 删除）。**「保存并校验」只做静态检查**（导入白名单 / 入口 Main / 契约解析，并重算端子、断开失效接线）；真跑一次渲染请点「试渲染」（≤2 秒、不占全局音视频锁、产物即弃）；
- **渲染**：时长 / 帧率 / 分辨率；
- 最后是「中间产物」。

## 注意

- 全局同一时刻只允许 **1 个音视频任务**（音乐 / 视频互斥）。**构建期的短试渲染不占这把锁**（它只烧几秒、不产出交付物）。
- 首次渲染会自动下载 Chrome Headless Shell（走国内镜像，失败回退本机 Edge / Chrome）。
- 报 `inputRange must be strictly monotonically increasing`：工程里 `interpolate` 的关键帧数组有重复/倒序 —— 修源码（保存并校验 → 试渲染）或点「构建」勾上「从头重建」。
- 想彻底重写一版：点「构建」→ 勾上「忽略现有源码，从头重建」（失败时旧源码保留）。
- 未固化且一条线都没接时点 ▶ 不会跑：运行期不再调模型，先「构建」或先接素材 / 语音 / 台词。

## 中间产物（随工作流一起走）

封装成工作流时，Remotion 的合成工程作为**中间产物**一起打包：`remotionFiles`（整棵树）+ `remotionInputs`（契约）+ 入口 `tsx` 会跟着节点走。换机/分享后插回来，**端子直接按契约就位**，运行时只渲染这份源码，不需要模型、也不需要重新构建（除非你想改）。

## 会话（💬）

- **打开绑定会话**：点节点头部 **💬**，跳转到与节点绑定的智能会话（首次点击自动创建）。
- **过程记录**：每次渲染结束追加一条记录（成功：输出路径 / 分辨率 / 帧率 / 耗时 / 代码；失败：错误；取消：已取消），不重复堆叠。
- **迭代**：把想要的效果说给会话，或直接在 ⚙ 里改源码；改完「保存并校验」→「试渲染」→ 回画布点 ▶。
- **让助手改工程**：会话里的助手可以用画布编辑接口直接写 `remotionFiles`（整棵源码树，路径相对 `src/`）和 `remotionInputs`（端子契约）。写源码走的是与「保存并校验」同一条静态校验：通过就重算端子、同 key 的接线跟着搬；没通过时源码照样保存、端子保持上一版，原因写在回执里。读回时 standard 档给契约与文件清单，`detail:"full"` 才给整棵源码。

## 安装

节点随插件 **remotion** 提供：插件卡片「**安装**」（自动 `npm install`，过程在独立安装窗里逐步骤显示）→ 装好后主按钮变「**重装**」。它没有常驻后端，所以没有启动 / 停止。
