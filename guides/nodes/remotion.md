# Remotion 视频（React 动效合成）

由应用插件 **remotion** 提供：**构建期**由 Agent 把需求写成一整份 Remotion（React）工程；**固化后**运行期只做脚本渲染，把工程渲染成 `.mp4`，**不再调模型**——同一份工程每次跑出来完全一致。渲染在本机完成，不依赖云端视频服务。每次运行只生成一个视频文件，交给下游「保存」节点保存（节点自身不设输出路径）。

## 端子
- **输入**：未固化时是无差别动态端子（端口 0、1、2… 连一条多一条）；已固化后按工程里声明的契约钉死，每项一颗，末位一颗控制口
- **输出**：视频由下游「保存」节点保存

## 设置
在节点头部 **⚙ 设置** 打开的设置窗口里改：

- **功能说明**：与节点正文框同一字段，只描述这个节点干什么；构建 Agent 不读它。
- **构建 / 验证**：构建… / 试渲染 / 校验源码，外加状态（构建报错、试渲染报错、固化时间、文件数与端子数）。
- **构建 Agent 的模型**：预设 / 供应商 / 模型 / 思考强度，留空 = 跟随全局默认。
- **源码（固化工程）**：多文件编辑器，可改 / 新增 / 删除；「保存并校验」只做静态检查（导入白名单 / 入口 `Main` / 契约解析，并重算端子、断开失效接线）。
- **渲染**：时长 1–60 秒（默认 5）、帧率 1–60（默认 30）、分辨率（默认 1280x720）。

## 用法
1. 点卡片「**构建**」（或设置窗里的「构建…」），写清画面、节奏、文字、素材怎么用。构建需求不能为空；默认在现有源码上迭代，勾「忽略现有源码，从头重建」才重写。
2. 构建 Agent 在 `<工作目录>/.mtnode/remotion/<节点 id>/build/src/` 下写多文件工程（入口固定 `Composition.tsx`），声明端子契约，先静态校验再跑一次 ≤2 秒短试渲染；不通过就把报错回灌自修，最多 3 轮，仍不过则保留上一版能跑的源码。
3. 通过后固化：整棵源码写进节点，端子按契约重排。之后点 ▶ 就是纯渲染。

## 注意
- 契约写在源码里：`export const inputs = [...]`，`kind` ∈ `image` / `audio` / `video` / `text` / `number` / `boolean` / `json`，`key` 就是组件收到的 props 名；`list: true` 表示可接多路（值变数组），`required: true` 只是标记，没接线会在节点日志里点名。改代码即改端子；重构建后同 key 的接线保留。
- 素材怎么进画面：image 收到 `data:` URL；audio / video 收到**裸文件名**（已落在工程 `public/`），用 `staticFile(...)` 包一层；text / number / boolean / json 直接用。接了 audio 且探得到时长时，成片总长 = 音频时长，否则用节点设置；宽高与 fps 一律以设置为准。
- 工程依赖只有 `react` + `remotion` + 工程内相对文件，不允许第三方 npm 包（宿主不会 `npm install`）；入口必须导出 `Main`，根容器 `<AbsoluteFill>`。
- 全局同一时刻只允许 **1 个音视频任务**（音乐 / 视频互斥），构建期短试渲染不占这把锁；首次渲染会自动下载 Chrome Headless Shell（走国内镜像，失败回退本机 Edge / Chrome）。插件卡片「**安装**」装好（自动 `npm install`，过程在独立安装窗里逐步骤显示），装好后主按钮变「**重装**」；没有常驻后端，所以没有启动 / 停止。
- 报 `inputRange must be strictly monotonically increasing` = 工程里 `interpolate` 关键帧重复或倒序，改源码（保存并校验 → 试渲染）或「从头重建」。
