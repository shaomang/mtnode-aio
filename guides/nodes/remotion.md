# Remotion 视频（React 动效合成）

「Remotion 视频」节点由应用插件 **remotion** 提供：在节点里写视频描述（或直接接入素材 / 语音 / 台词），LLM 生成 React 动效合成代码，再经本机 Remotion（React 渲染）渲染成 `.mp4`——渲染在本机完成，不依赖云端视频服务。**每次运行只生成一个视频文件**，视频输出交给下游「保存」节点保存（节点自身不设输出路径）。

## 安装

节点随插件 **remotion** 提供；未安装或卸载插件时，菜单入口与画布节点均不显示。

1. 打开「插件 · Remotion 动效视频」，点卡片主按钮「**安装**」（没选过安装目录时会先弹目录选择框，需 ≥8GB 空闲磁盘）；
2. 安装自动跑 `npm install`（可走国内镜像）——**过程与日志都在那只独立「插件安装」窗里逐步骤显示**（失败就地「重试」，不重复已完成的步骤）；失败要重来就在那只窗里点「重试」；想看插件的完整窗（卸载 / 运行期设置）点卡片上的「**控制台**」（控制台窗里不再有安装目录与安装按钮）。
3. 装好后主按钮变「**重装**」——它没有常驻后端，所以没有启动 / 停止。

> **技能是可选增强**：安装过程不会自动下载任何 Agent 技能，**不装也能正常生成与渲染**。若想让 LLM 写出更规范的动效代码，可在「创意工坊 → Skill」搜索 **Remotion 动效视频** 自行下载（下载后落在本机 `dsh-home/skills`，供全局助手 / 智能会话 / 智能节点使用）；需要 Remotion 官方整包时也可自行执行 `npx -y skills add https://github.com/remotion-dev/skills --skill remotion-best-practices`。

## 使用流程

```
动态画面（H3 动态层 / 视频 / 图片） ┐
语音（Breeze 语音生成）          ├─▶ Remotion 视频节点 ──▶ 保存节点（输出 .mp4）
台词（文本节点）                ┘        描述写在节点里
```

1. **描述**：直接写在 Remotion 节点的正文框里（与文本处理节点同一套输入框：支持 `@节点标题` / `@标签` 引用已接线的上游内容，也能输入 `/` 呼出技能）。**描述可以留空** —— 留空时按已接线的素材 / 台词直接走内置「角色动态 + 台词卡」版面；
2. **接线**：把画面、语音、台词分别连到节点的输入端子上（端口 0、1、2… 连一条多一个，不必挑号）；
3. **运行**：描述非空时由 LLM 生成动效代码再本地渲染；描述为空（或描述里写了 `{{hero}}` / `{{narration}}` / `{{voice}}` / `{{bg}}` 占位、或点了「台词卡 / 左…右…」）时直接用内置模板渲染，素材与台词按接线注入。生成的代码若引用了 `react` / `remotion` 以外的包，或缺少可注册的组件导出，节点会直接报错并写明原因（不会悄悄换成内置标题卡）；
4. **保存节点**：把 Remotion 的控制输出接到保存节点触发保存，在其上配置输出路径（`.mp4`），渲染产物会复制到该路径。

## 端子

- **输入**：**无差别动态端子** —— 端口 0、1、2… 连一条多一条；数据线与控制线**共用同一批端子**，先占先得（控制节点连进来的那只口自动按控制口显示与上色）。**没有「描述」端子**，描述是节点自己的字段。
  - 接进来什么按来源自动归位：**视频 / 图片 → 主素材（hero）**、**音频 → 语音（voice）**、**文本 → 台词（narration，多条取最长的一条）**；另接一路「台词节拍表」时成片按节拍逐句吐字。
- **输出**：视频（下游可试看 / 保存）+ 控制

> 老画布上「端口 1 = 描述文本」的接线在读档时自动迁移：那条描述线转成节点里的描述（写成 `@上游标题`，上游改了描述跟着变），其余线号左移一位。

## 设置

描述 / 时长 / 帧率 / 分辨率与服务商模型都在节点头部 **⚙ 设置** 打开的设置窗口里改（描述在节点正文框里也能直接改），改完即时生效；节点卡片上只显示一行当前摘要。

## 参数

- **时长**：1–60 秒（默认 5）
- **帧率**：1–60 fps（默认 30）
- **分辨率**：1280x720 / 1920x1080 / 1080x1080 等（默认 1280x720）
- **服务商 / 模型**：用于生成动效合成代码（LLM 文本模型，需在「设置 · API/配置」配置 API Key）

> 视频输出路径在**下游「保存」节点**配置；渲染的合成代码、`render.json` 与成片都落在
> **画布工作目录**的 `.mtnode\remotion\<节点 id>\` 下（安装目录只放依赖，不写用户代码）。
> 画布没设工作目录时节点会直接提示先设目录，不会渲染。

## 会话（💬）

Remotion 节点与智能会话打通，方便查看生成过程与编辑迭代：

- **打开绑定会话**：点击节点头部的 **💬** 按钮，一键跳转到与该节点绑定的智能会话（首次点击自动创建绑定）。运行中也可点击，实时进度仍由节点状态条与 **▤** 控制台承担。
- **过程记录**：每次生成结束，会话自动追加一条过程记录——**成功**时含输出路径、分辨率、时长、帧率、耗时与生成的动效代码（TSX 代码块）；**失败**时含错误信息；**取消**时记为「已取消」。反复点击 💬 不会重复堆叠记录。
- **查看 / 复制 / 编辑 TSX**：会话消息里的 ```tsx 代码块可直接查看与复制；把动效代码反馈给会话中的智能体，即可继续修改迭代。
- **会话内改参数后重跑**：直接在会话里发消息让智能体调整节点（如「把标题动画改成立体翻转」「时长改为 8s、分辨率 1920x1080」「描述改成……」），智能体会更新节点参数；回到画布点 **▶** 重跑，新结果会再次写入会话——形成「查看过程 → 编辑迭代 → 重跑」闭环。

## 注意

- 全局同一时刻只允许 **1 个音视频任务**（音乐 / 视频互斥）。
- 生成分两段：LLM 生成动效代码（联网 API）→ 本地 Remotion 渲染（Chrome Headless Shell 首次自动下载）。
- **渲染报 `inputRange must be strictly monotonically increasing`**：这是 LLM 生成的动效代码里 `interpolate(frame, inputRange, ...)` 的关键帧数组出现重复或倒序（如 `[220,280,280]`，常发生在 map / 循环里按 `i` 计算帧号、`i` 增大后与固定帧重复）。节点会直接显示中文修复指引：删掉重复帧号，或在循环里用 `Math.max(...)` 保证后一个帧号严格大于前一个；也可把报错贴进节点 💬 会话让智能体直接修，或重跑节点重新生成动效代码。

## 中间产物（随工作流一起走）

封装成工作流（顶栏「工作流库」保存的那颗节点层）时，Remotion 的合成代码会作为**中间产物**一起打包：

- **收集**：保存到工作流库时，按「工作流库 → 中间产物规则…」里的扩展名白名单从节点工作目录收集；Remotion 的 `Composition.tsx` 即使工作目录里没有对应文件，也会从节点字段（最近一次生成的代码 / 直出代码）直接带走。
- **复用**：从工作流库插入（或从工坊下载）后，节点带着这份代码。运行时若**描述没改**（描述指纹一致）→ 直接复用包内代码渲染，**不再调用模型**；描述改过 → 自动以旧代码为参考、按新描述重新生成，新文件写进当前画布的产物目录（不覆盖工作流库里那份）。
- **查看 / 操作**：节点 ⚙ 设置窗最下面的「中间产物」区块列出文件名、大小、是否与当前描述一致，并提供「重新生成」（清掉指纹，让下次运行按新描述重生成）与「剔除」（不再复用）。
- **安全**：从工坊下载的工作流会带着别人的代码，首次运行前会弹窗告知并要你确认；分享时文本产物正文里的本机绝对路径会被清洗成相对文件名。
