# Breeze speech (Breeze TTS 2)

![diagram](img/breeze_gen.svg)

Right-click the canvas → **Process › Audio generation › Breeze speech**. Turns text into **speech**: the backend is the local management service started by the “Breeze TTS 2 Local TTS” plugin (default `127.0.0.1:8772`) plus the official `breeze_infer.api` inference engine (`127.0.0.1:8773`, **started on demand**). **Each run produces exactly one audio file** (`.wav` / `.flac` / `.mp3`) written to the node's own `outputPath`. **The output path may be left empty too**: wire its **data output** into a downstream **Save** node and the path becomes that node's job — the file lands in the **app-managed folder** (the canvas-asset / temp area under the app data directory) first, and that Save node then writes it to the save path you set. Data only lands in the install folder you pick and in `%APPDATA%\pipeline-console`.

## Ports
- **Input**: port 0 = text to speak · port 1 = reference audio (audio file URL) · port 2 = reference transcript (text, or an audio / video input node) · port 3 = instruction · port 4 = control input
- **Output**: port 0 = speech audio (play / save downstream) · port 1 = control output

## The two text boxes (editable right on the card)
- **First box = the text to speak** (port 0): **read-only while port 0 has input**, editable only when that port is empty (stored as `srcText` on the node, saved with it).
- **Second box = the reference transcript** (port 2): same rule, **read-only while port 2 has input**, editable only when that port is empty (stored as `refText`). With a voice-library voice selected and this box left empty, synthesis uses the transcript bundled with that voice.
- The boxes carry no title row and no state labels any more — **hover** a box to see what it is for (“when the port is empty, the text in this box is what gets spoken” / “read-only while port 0 has input”).
- This box **shows text only**: when port 2 is wired to an audio / video input node it shows **that node's port-1 transcript output** (the text it transcribed itself) — wired to that node's **audio output (port 0)** instead, that line carries the audio itself, so the box stays empty and the `file:///…` path is never shown as reference text; if it has not been transcribed yet the box stays empty and the node's status line points you at Transcribe on that audio node. When a port hands over an audio / video file (an audio URL, a local path such as `E:\…\ref.wav` — from a Save node, a generation node, or any node that passes a path as text), the box stays read-only and empty and that path is never shown as reference text: the node takes that audio as the **reference audio**, so the reference text must come from somewhere else — type it into the box, or wire the audio node's **transcript output** into port 2.
- Both boxes are **ports-first**: the moment you wire an input the box turns read-only, and disconnecting hands it back to you. This node **does no transcription** — fill the reference text in yourself or wire it into port 2 (transcription lives on the audio / video input nodes, see their guides).

## Characters (voice presets)
To keep using one voice without wiring a reference clip every time, use a **character preset**: a character = **one base voice + N alternative voices**, and each group = **a reference audio clip + its verbatim line + one instruction** (plus an optional scene tag). Characters are created **on this node**: the **👤** button in the node header opens the character dialog (the audio is copied into the data folder by the host, so your original file is never referenced — and the character is reusable from any canvas).

- **Three-step wizard** (every step can be revisited):
  1. **Voice design** — two entries:
     - **Design with AI**: type just a **character name + one line of voice description** (e.g. "a warm female voice in her early thirties, slow pace"). **Refine prompt with AI** expands it into a ready instruction using the **default text model + the built-in skill**, and the candidate lines are written by the model from that description too (roughly 40–70 CJK characters / 25–45 English words ≈ 8–15 s), all different. The model dropdown switches the model for this run (remembered in the plugin config; empty = follow the default).
     - **Reference audio**: pick a clip and type its **verbatim line** (+ optional instruction) → saved straight as a character.
  2. **Pick candidates** — generates the count you chose (3–6), **each with its own random seed and a random cfg (3–5)**; line / seed / cfg are all editable, a single candidate can be re-rolled, one more can be added, and generation can be cancelled (finished candidates are kept).
  3. **Confirm the voice** — pick one as the **base voice** (with an optional group name / scene); saving applies it to this node right away.
- **Adding alternative voices later**: **＋ Add alternative voice** in the character dialog runs the same wizard (same character, instruction re-tuned for the scene / emotion, using **voice direction** = the base voice's audio + the new instruction) — use it for angry / gentle / narration takes.
- **Everything is editable**: character name, voice description, instruction, and each group's line / name / scene can be changed and saved with **Save changes**; groups can be deleted, the character can be deleted, and an alternative voice can be **Set as base voice**.
- **Picking one**: the **👤** button opens the character dialog — pick a character on the left, and each group on the right shows a **waveform player** (preview right there), its line and its instruction; click **Use this group** to apply it (the dialog closes and the choice is stored on the node).
- **Once selected**: ports 1 / 2 are hidden on the card and **take no part in synthesis** — the reference audio and line both come from that group, and only the "text to speak" box remains.
- **Instruction**: a non-empty instruction on port 3 or in the node settings **overrides** the group's instruction; leave it empty to use the group's own line (the default is to fill in nothing).
- **Capability**: a selected character runs as **voice direction** (audio + instruction together), so the capability / voice-library rows disappear from the settings window; `cfg_scale` / `seed` stay adjustable.
- **No character selected = the old behaviour**: ports first, the voice library only when they are empty, exactly as before.
- **The plugin console** now only starts / stops the backend, shows logs and offers a **throwaway probe with a hand-typed instruction**; it no longer manages characters.


## Options
Click **⚙ Settings** in the node header to open the settings window; changes apply immediately and the card itself keeps showing just a one-line summary.

- **Character**: the character / group picked with the 🎭 button in the top menu bar (see the section above)
- **Voice**: a voice-library id (install folder `voices/<id>/{ref.wav, ref.txt}`); empty = use the reference audio wired into the port. **With a character selected neither this row nor the capability row appears.**
- **Capability**: auto / voice clone / voice design / voice direction
- **Instruction** / **cfg_scale** (default 4) / **seed** (default 42)
- **In voice-clone mode cfg_scale is always 1.0**: the engine's clone template (the `ref_clone_tata` path taken when there is reference audio and no direction instruction) defines no negative prompt and only accepts `cfg_scale=1.0`; any other value is rejected outright by the engine (HTTP 500). This path therefore always sends 1.0, the value in the settings window is not sent, and the card summary shows “cfg 1 (fixed in clone mode)”. **To tune CFG, add an instruction so the run becomes voice direction** (that template supports a negative prompt); voice design (no reference audio) supports CFG as before. If the management service does receive “clone + cfg≠1” it clamps the value back to 1.0 and logs it in the console instead of failing the whole synthesis.
- **Format**: `.wav` / `.flac` / `.mp3` · **Output path**: destination (relative to workspace / super subfolder). **Empty is fine once a Save node is wired** — the path then belongs to that Save node: the file lands in the app-managed folder first and the Save node writes it (see the Save node guide). Without a Save node it is required, and ▶ warns “Generation cannot start until an output path is set”.
- **Attempts**: gacha rolls (1–10); keep one result

## Notes
- **License**: the inference code is Apache-2.0, but **model weights, derivative models and self-hosted output fall under the BreezeBlue Research and Non-Commercial License — research and non-commercial use only** — Apache-2.0 grants no commercial rights to the weights, and a paid subscription only covers output from the breezeblue.ai hosted platform, never self-hosted output; unauthorized voice cloning and impersonation are forbidden.
- **Which reference wins**: a selected **character** wins outright (ports 1 / 2 take no part); with no character, the reference audio / text wired into the ports come first, and only when those ports are empty does the node fall back to the voice picked in its settings (voices are maintained in the **Plugins › Breeze TTS 2 Local TTS** console — one voice = the reference clip plus transcript in `voices/<id>/` under the install folder; existing voices are migrated into single-group characters the first time the console opens, and the original folders are kept). **Both audio ports count** — port 1 (audio file URL) and port 2 (an audio / video input node, whose own audio file is used); with both wired, port 1 wins. **A reference audio must always come with its reference text** (the official API requires the pair: fill in the “Reference text” box, or wire the audio node's **transcript output** into port 2 — if that node has not been transcribed yet, click Transcribe on it first), otherwise the node stops locally with a clear pointer instead of wasting an engine run. The node's status line states which source this run actually used.
- **The three capabilities (official semantics)**: reference audio and no instruction = **voice clone**; an instruction is present = **voice direction**; no reference audio = **voice design**.
- **mp3 needs ffmpeg**: wav / flac are wrapped by soundfile, mp3 goes through the portable ffmpeg the installer downloads to `tools/ffmpeg/` in the install folder; when it is missing the node spells out what to do and suggests wav / flac.
- Runs on the same **serial chain** as music / video (one generation task at a time) **and holds the app-wide audio/video mutex** — the engine needs about 7.7 GB of VRAM just to load eagerly, so it competes with music / video for VRAM; the lock-free separate speech process (SoVITS / `tts_gen`) is gone along with that plugin.
- Requires an **NVIDIA GPU, 12 GB VRAM to start** (about 7.7 GB eager); it runs natively on Windows (the official README only covers Linux — this plugin takes the default eager path and does not enable the CUDA Graph fast path).
- **The backend stays resident**: the management service and the engine are resident singletons and **do not exit with MTNode**; closing the console window does not stop the backend. To stop the services / free VRAM use the plugin card or the console's “Stop”, or the tray menu's **Stop services and exit**.
- **Backend errors pop a dialog**: when the install or the running backend breaks, the main window shows an **error report** (error code, error body, console log tail, the node that failed) and offers **🤖 Auto-repair** — a visible session that works in the `breeze-tts-local-install` skill's self-repair mode inside this plugin's **INSTALL_DIR** and, on success, **restarts the backend** and refreshes this node's status. Cancelled-by-you / busy / out of disk / no NVIDIA GPU / driver too old / invalid install directory get the report only, never an auto-repair (see "Plugin error dialogs and auto-repair" in the manual).
