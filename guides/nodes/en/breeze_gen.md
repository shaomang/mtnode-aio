# Breeze speech (Breeze TTS 2)

![diagram](img/breeze_gen.svg)

Right-click the canvas → **Process › Audio generation › Breeze speech**. Turns text into **speech**: the backend is the local management service started by the “Breeze TTS 2 Local TTS” plugin (default `127.0.0.1:8772`) plus the official `breeze_infer.api` inference engine (`127.0.0.1:8773`, **started on demand**). **Each run produces exactly one audio file** (`.wav` / `.flac` / `.mp3`) written to the node's own `outputPath`. **The output path may be left empty too**: wire its **data output** into a downstream **Save** node and the path becomes that node's job — the file lands in the **app-managed folder** (the canvas-asset / temp area under the app data directory) first, and that Save node then writes it to the save path you set. Data only lands in the install folder you pick and in `%APPDATA%\pipeline-console`.

## Ports
- **Input**: port 0 = text to speak · port 1 = reference audio (audio file URL) · port 2 = reference transcript (text, or an audio / video input node) · port 3 = instruction · port 4 = control input
- **Output**: port 0 = speech audio (play / save downstream) · port 1 = control output

## The two text boxes (editable right on the card)
- **Input text (the words to speak)** — the port-0 text to synthesize: **read-only while port 0 has input**, editable only when that port is empty (stored as `srcText` on the node, saved with it).
- **Reference text (words of the reference audio)** — the port-2 reference transcript: same rule, **read-only while port 2 has input**, editable only when that port is empty (stored as `refText`). With a voice-library voice selected and this box left empty, synthesis uses the transcript bundled with that voice.
- This box **shows text only**: when port 2 is wired to an audio / video input node it shows **that node's port-1 transcript output** (the text it transcribed itself) — wired to that node's **audio output (port 0)** instead, that line carries the audio itself, so the box stays empty and the `file:///…` path is never shown as reference text; if it has not been transcribed yet the box stays empty and the card tells you to click Transcribe on that audio node. When a port hands over an audio / video file (an audio URL, a local path such as `E:\…\ref.wav` — from a Save node, a generation node, or any node that passes a path as text), the box stays read-only and empty and that path is never shown as reference text: the node takes that audio as the **reference audio**, so the reference text must come from somewhere else — type it into the box, or wire the audio node's **transcript output** into port 2.
- Both boxes are **ports-first**: the moment you wire an input the box turns read-only, and disconnecting hands it back to you. This node **does no transcription** — fill the reference text in yourself or wire it into port 2 (transcription lives on the audio / video input nodes, see their guides).

## Options
Click **⚙ Settings** in the node header to open the settings window; changes apply immediately and the card itself keeps showing just a one-line summary.

- **Voice**: a voice-library id (install folder `voices/<id>/{ref.wav, ref.txt}`); empty = use the reference audio wired into the port
- **Capability**: auto / voice clone / voice design / voice direction
- **Instruction** / **cfg_scale** (default 1; the official guidance is 4 when an instruction is set) / **seed** (default 42)
- **Format**: `.wav` / `.flac` / `.mp3` · **Output path**: destination (relative to workspace / super subfolder). **Empty is fine once a Save node is wired** — the path then belongs to that Save node: the file lands in the app-managed folder first and the Save node writes it (see the Save node guide). Without a Save node it is required, and ▶ warns “Generation cannot start until an output path is set”.
- **Attempts**: gacha rolls (1–10); keep one result

## Notes
- **License**: the inference code is Apache-2.0, but **model weights, derivative models and self-hosted output fall under the BreezeBlue Research and Non-Commercial License — research and non-commercial use only** — Apache-2.0 grants no commercial rights to the weights, and a paid subscription only covers output from the breezeblue.ai hosted platform, never self-hosted output; unauthorized voice cloning and impersonation are forbidden.
- **Which reference wins**: the reference audio / text wired into the ports come first; only when those ports are empty does the node fall back to the voice picked in its settings (voices are maintained in the **Plugins › Breeze TTS 2 Local TTS** console — one voice = the reference clip plus transcript in `voices/<id>/` under the install folder). **Both audio ports count** — port 1 (audio file URL) and port 2 (an audio / video input node, whose own audio file is used); with both wired, port 1 wins. **A reference audio must always come with its reference text** (the official API requires the pair: fill in the “Reference text” box, or wire the audio node's **transcript output** into port 2 — if that node has not been transcribed yet, click Transcribe on it first), otherwise the node stops locally with a clear pointer instead of wasting an engine run. The node's status line states which source this run actually used.
- **The three capabilities (official semantics)**: reference audio and no instruction = **voice clone**; an instruction is present = **voice direction**; no reference audio = **voice design**.
- **mp3 needs ffmpeg**: wav / flac are wrapped by soundfile, mp3 goes through the portable ffmpeg the installer downloads to `tools/ffmpeg/` in the install folder; when it is missing the node spells out what to do and suggests wav / flac.
- Runs on the same **serial chain** as music / video (one generation task at a time) **and holds the app-wide audio/video mutex** — the engine needs about 7.7 GB of VRAM just to load eagerly, so it competes with music / video for VRAM; SoVITS (`tts_gen`) is a separate process and does **not** hold that lock.
- Requires an **NVIDIA GPU, 12 GB VRAM to start** (about 7.7 GB eager); it runs natively on Windows (the official README only covers Linux — this plugin takes the default eager path and does not enable the CUDA Graph fast path).
- **The backend stays resident**: the management service and the engine are resident singletons and **do not exit with MTNode**; closing the console window does not stop the backend. To stop the services / free VRAM use the plugin card or the console's “Stop”, or the tray menu's **Stop services and exit**.
- **Backend errors pop a dialog**: when the install or the running backend breaks, the main window shows an **error report** (error code, error body, console log tail, the node that failed) and offers **🤖 Auto-repair** — a visible session that works in the `breeze-tts-local-install` skill's self-repair mode inside this plugin's **INSTALL_DIR** and, on success, **restarts the backend** and refreshes this node's status. Cancelled-by-you / busy / out of disk / no NVIDIA GPU / driver too old / invalid install directory get the report only, never an auto-repair (see "Plugin error dialogs and auto-repair" in the manual).
