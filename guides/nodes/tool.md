# 工具节点（Agent 可调用）

把画布上的一段处理流程（文本处理 / 智能任务 / 函数 / 保存等任意子图）打包成 **Agent 可直接调用的工具**：给它一个工具名、用途描述和入出参数，智能会话里的模型就能像调用函数一样调用它，参数从端子进出，结果回传会话。

工具节点 = **类节点层的容器形态**：把要执行的处理流程作为它的**内部子图**（子节点挂在本节点下，机制与节点层一致），点 ▶ 或 Agent 调用时按拓扑执行；配置统一存在 `toolConfig`（`name` / `description` / `inputs` / `outputs`）。

创建：画布空白处右键 → **其他节点** → **工具（Agent 可调用 · 入参出参端子）**。

## 设置（参数即端子）
点头部 **「设置」** 打开设置窗口（参数全部在窗里改，工具卡片上只留名称 / 描述与「入参 / 出参」只读摘要）：

- **工具名 name**：也是给 Agent 的调用名。标题默认跟随工具名；手动改过标题后两者独立。
- **描述 description**：写清楚「做什么 / 何时用 / 注意什么」——Agent 据此判断是否调用本工具。
- **输入参数类型（文本 / 图像 / 视频 / 音频）**：每一条 = 一个输入端子，参数名即端子名；文本端子的值是字符串，图像 / 视频 / 音频端子的值是 `{kind, path, text}` 路径对象（本机绝对路径）。
- **输出参数类型（文本 / 图像 / 视频 / 音频）**：每一条 = 一个输出端子，**出参和入参一样要声明类型**——把某个输出结果改成「图像」，它就是一条图像端子（值 = 图片路径）；视频 / 音频同理。

增删参数 = 增删端子；删参数时对应连线一并失效；改类型 = 改端子类型（端子会重新着色、下游按新类型取数）。
**调整参数顺序**：拖动参数行左侧的 ⠿ 把手可把该参数插到任意位置，或用行尾 ▲▼ 逐格移动——参数顺序即端子顺序，已连的数据线会跟着参数一起移位（不会漂到别的参数上）。

## 描述自足（让 Agent 一次调对）
Agent 调用工具时，模型**只看得到这个工具自己给出的信息**（名称 / 描述 / 参数表 / 每格说明 / 调用示例 / 限制），看不到你的内部图。信息不全，它就只能反复试错。工具「设置」里备好了这六格，补齐即可：

1. **用途 description**：做什么、什么时候用、注意什么。
2. **每个入参的说明**：这一格该填什么（格式、从哪来、要不要带扩展名）。
3. **每个出参的说明**：返回值是什么（尤其「字节数」这类容易误解的名字）。
4. **可选性**：真正可省的参数勾「可选」（不勾 = 必填）；「正文 / 源文件路径」这类二选一写在 **「至少给一个」**（一行一组，组内用 `/` 分隔）。
5. **调用示例 example**：一份能跑通的最小 JSON（键 = 参数名）。失败回执会把它一起发给 Agent；「测试」台也能「按调用示例填入」。
6. **限制与失败情形 limits**：什么情况下会失败（输出必须是绝对路径、落在应用安装目录内会被拒绝、文件不存在会报错…）。

- 描述 / 示例 / 参数说明里都可以写 `{{outDir}}`：调用时会被替换成本机真实可写的**用户输出目录**——模型不用猜该往哪儿写文件。
- 卡片上出现黄字「描述不自足（缺 …）」= 还有格子没填；补齐后黄字消失。**只提醒，不阻挡保存与运行**。
- 随应用发版的内置工具都按这六项写全；以前插入到画布上的内置工具副本，**打开画布时会按内置最新自动刷新描述与参数说明**（参数个数与顺序不动，已连的线不受影响）。
- 两个内置工具（「Markdown 转 PDF」「PDF 转 Markdown」）是最小范例：正文 / 路径二选一、输出路径必填、限制写清哪些目录写不进去。

## 开发（绑定该工具的会话）
工具节点同样支持**「开发」**（卡片下方按钮，与函数节点同一机制）：

- 点「开发」→ 弹窗展示现状（工具名 / 描述 / 入出端子 / 内部子图 / 会话工作区），填写本次要改或扩展的内容；
- 确认后新建一条**绑定该工具**的会话并后台运行（标题「开发 · 工具名」· 工作区 = 画布目录）；
- 会话只改**这一个工具节点**：可改 `toolConfig` 的 name / description / inputs / outputs（参数即端子，动参数表要提醒你复核端子连线），也可在**工具内部**新建 / 删除 / 调整节点与连线来重建行为——工具的行为就是它的内部子图；
- 会话清单 / 左下角队列可看进度，改完点卡片再「开发」可接着上一轮要求继续迭代。

## 端子类型有什么用（用户可见收益）
端子声明的类型是**连线校验、保存选型、连线着色**的唯一依据：

- **从图像 / 视频 / 音频输出端子把线拖到保存节点，会自动按对应媒体保存（扩展名自动变 `.png` / `.mp4` / `.wav`）**；从文本输出端子拖过去则按文本保存。不必再手动挑。
- 四类端子各接各的：图像线只能接进图像端子、视频线只能进视频端子、音频线只能进音频端子、文本线只能进文本端子；接错了会直接点名「哪个端子是什么类型、去哪儿改」，不会把媒体悄悄塞进文本端子（真拿媒体值喂文本端子时按路径取文本，并在节点摘要上提示一句）。
- 图像 / 视频 / 音频端子与相应连线单独着色，一眼看出哪条线走的是什么媒体。

## 端子排布
- **输入**：端子 0 = 控制入（固定），之后每个输入参数一个端子。
- **输出**：每个输出参数一个端子（0..n-1），**末位 = 控制出**（固定）。
- 每个数据端子都带声明类型（文本 / 图像 / 视频 / 音频）；控制端子不带类型，仍按实际值判定。
- 工具节点也有「**参数**」端子（9001）：它是内部图的共享参数，工具内的函数节点自动继承（自己那份同名键优先），见「函数节点」指南的「参数端子」一节。
- 端子固定排布：断开连线不重排、不自动增减；Agent 调用时只走数据端子，控制口不动。

## 内部图（决定工具做什么）
工具执行的是它的内部子图（子节点挂在本节点下）：

1. 准备内部子图——壳层形态（节点层 + 工具变体）下像节点层一样展开 / 进入内部画布编排；从工具库**插入**的工具自带内部图，展开即可查看调整。
2. 外侧输入端子（含控制入）自动作为内部节点的取值来源——接线方式与节点层的内外侧桥接一致。
3. 内部节点的输出接回外侧输出端子（内侧汇流），运行后写回对应输出参数——值会**按该输出端子声明的类型**归一：图像端子拿到路径文本会补成图像值，文本端子拿到图像则按路径取文本（节点摘要上会提示一句，数据不丢）。外侧输出端子上的徽标 / 颜色与内侧汇流端子的提示同一口径。

## AI 调用（模型 · 预设 · 思考强度）
节点头部的 🤖 小按钮（或板身「开发」旁的「AI 调用」）选出本工具需要借助 AI 时用的模型 / 预设 / 思考强度：

- 选中的模型就是**内部子图里那些 AI 节点的默认**（按 run 下发 providerId / provider / model 与思考强度）。
- 内部节点**自己选过**模型 / 服务商的以内部为准（就近优先，不打断既有配置）；宿主从上层功能块继承来的值不下发。
- 改选后下一次运行即按新选择走；本节点自己没选的格会在运行时就地落定，随画布保存。

## 运行
- 点 ▶（或控制 ▶ 触发）：先补跑上游，再按拓扑执行内部全部可运行节点（proc / 智能 / 函数 / 保存等，含级联），结果写回输出端子并继续执行下游。
- 工具节点整体可被下游 @ 引用 / 全局广播（文本口径照旧）；**接给下游什么类型看的是那个输出端子**：图像输出端子连到保存节点会自动按图像保存（`.png`），见上文「端子类型有什么用」。批量请走其内部或下游节点的 batchMode（batch 模式每次运行只处理单条输入）。

## 跨画布复用与「随时可调用」
顶栏 **工具库**（按钮用的就是程序自己的图标）打开的对话框列出**已保存的工具 / 函数包**与**应用内置条目**（内置条目带灰徽「内置」，随应用发版，可直接插入 / 试跑，但不能改名或删除），不在这里建节点（建节点走上面的右键菜单）：

- **保存到工具库**：把本节点连同内部图快照存成工具包（名称 / 描述 / 入出参数（含每个参数的类型）+ 内部图 JSON）。
- **搜索**：对话框里常驻搜索框，按名称 / 描述 / 入出参数名过滤（不区分大小写），右侧显示命中数；清空即回全量。
- **单行清单 + 分页**：每条工具一行（徽标 / 名称 / 摘要 / 开关 / 插入 / 改名 / 删除），每页最多 20 条，底部翻页。
- **插入**：任意画布可重复插入该工具包（克隆为新 id，内部父子与连线按新 id 重建）。
- **会话随时可调用**（默认关）：开关打开后，Agent 会话里**无需画布副本**即可直接调用本工具；画布上的工具节点默认就在可用清单里。改名 / 覆盖保存会保持同一份库记录，开关随之延续。

### 内置条目：屏幕 / 窗口截图
开箱即用的内置条目之一：一条内置**函数包**（单节点 JS），把「别的屏幕 / 别的窗口」拍成 PNG 图像：

- 端子：`target`（`screen` 某个屏幕 / `window` 某个窗口 / `all` 整块桌面，默认 screen）、`screen`（屏幕名 `\\.\DISPLAY1` / `"x,y"` / 序号，留空 = 主屏）、`window`（窗口标题关键字，只写一部分也行）、`x` / `y` / `w` / `h`（可选，限定被拍对象内的区域）→ 输出 **图像路径**（图像端子）。
- 它是一条**函数包**，所以没有「会话随时可调用」开关（那个开关只对工具节点有效）；要在会话里用，把它插入画布后点 ▶、或让 Agent 通过画布上的副本调用。
- 它跑的是主进程的桌面截图（`mtnode.screenShot`，Windows 上 PowerShell + GDI）：被遮挡的窗口用 `PrintWindow` 拍自己的内容，自绘窗口（播放器等）回退复制屏幕，最小化的窗口会**明确拒绝**而不是给一张黑图。截图落在应用数据目录的 `captures/` 下。
- 插入画布后点 **「测试」** 就有预填样例值，可直接试跑；想知道有哪些屏幕 / 窗口可选，先跑一次 `mtnode.screenList()` / `mtnode.windowList()`（函数节点里同样可用）。
- 输出是图像路径，接 **保存节点**会按 `.png` 落盘；要看懂图里内容，把路径交给 `mtnode_vision`（智能体工具）。

内置条目还有一条 **PDF 转 Markdown**（工具条目）：

- 作用：把**本机 PDF** 的文本层解析成 Markdown 正文，交给下游文本节点使用（Agent 会话里也能直接调用它读 PDF）。
- 端子：入参 `path`（本机 PDF 绝对路径，文本端子）→ 出参 `markdown` / `pages` / `formulas` / `warning`（皆文本端子；`pages` 是页数、`formulas` 是疑似公式清单、`warning` 是提示语，均可能为空）。
- 只读、不落盘：解析完只在内存里回传结果，不改动也不额外写出任何文件（与「拖入 PDF」同一条链的只读口径）；成功 / 失败与「拖入 PDF」用的是同一份内核，加密件 / 扫描件会给出明确错误或警告（失败时以错误文本回执，不中断会话）。
- 它是**工具条目**（不是函数包），所以带「会话随时可调用」开关，且**默认开**——不插入画布也能在会话里直接调用；想让它只走画布运行，到工具库里把开关关掉即可。
- 插入画布后点 **「测试」** 有预填样例路径，改成自己的 PDF 就能试跑；实现侧依赖函数节点桥 `mtnode.readPdf` / `pdfInfo`（见「函数节点」指南的 `mtnode` 能力表）。

内置条目还有一条 **音频转字幕（时间轴）**（工具条目 `audio-subtitle`）：

- 作用：把一段**音频 / 视频**转成「能直接做字幕」的结构化文本 —— 每条字幕的起止秒 + 整份 SRT + 整份 VTT，画布上就能跑（会话里的 Agent 侧同名能力是 `audio_subtitle`）。
- 外侧端子：入参 **音频**（音频类）、**视频**（视频类，内部自动抽音轨）、**原台词**（文本，可选）、**参数**（文本，可选），前两条接一条就够；出参 **字幕数据**（cues 的 JSON）/ **SRT** / **VTT**（皆文本端子）。
- **原台词端子**：接上一段原台词就走**切分模式** —— 字幕正文从台词里逐字截取（识别错字不进字幕），时间仍来自静音切句。台词按标点断句（换行也是强制断句点），再与识别段做单调对齐；对不上的句子进 `unmatchedScript` / `unmatchedAsr` 清单（跳过不报错，`asrText` 附识别原文供对照）。不接 = 照旧用识别文本。
- **参数端子**：接一份 JSON，**按键覆盖**壳内「转写参数」的同键（未写的键沿用壳内那份）。例如只写 `{"keepPunctuation": true}`。
- 参数在哪改：它是一颗**工具壳**，展开壳就能看到里面的 **「转写参数」文本节点**（正文接在内部函数的 9001「参数」端子上）—— 一份 JSON：`language`（auto / zh / en / yue / ja / ko）、`maxDurationSec`（单条最长秒数，默认 6）、`maxChars`（单条最大字数，留空 = 中文 18 / 英文 42）、`noiseDb`（静音阈值，默认 -35dB）、`minSilenceSec`（最小静音间隔，默认 0.4s）、`keepPunctuation`（保留标点：默认 `false` 只去掉句末句号；`true` = 标点一律原样不动，连句末句号也不裁）。改完存盘即生效；壳 ⚙ 里那份默认参数 JSON 与它内容一致（没接线时兜底）。
- **文件只认两个媒体端子**，参数 JSON 里写 `file` 不生效（日志会提一句）。
- 它**不写任何文件**：要落 `.srt` / `.vtt`，把对应端子接到**保存文本**节点（保存节点按端子类型自动挑后缀）。
- 识别走本机官方 SenseVoice（与「录音听写」同一份权重）：**全自动** —— 语音运行时按需拉起、权重首次使用自动下载（约 239MB，断点续传）、识别器刚注册时也会自己等，不需要先去设置里「启用」什么；切句用 ffmpeg —— 没装 ffmpeg 会提示去插件里装 Remotion；时间边界是切片级近似，不是逐字对齐。
- 它是**工具条目**，带「会话随时可调用」开关（清单里 `always: false` —— 默认关，只在画布 / 绑定画布时可用）；插入画布点 ▶ 即可跑，再挂一条「保存文本」就得到字幕文件。

## 工具运行出错
内部节点失败、或内部没有可执行节点时，工具节点显示 ✕ 错误并给出原因；被 Agent 调用失败时以错误文本回执，不会中断会话。
