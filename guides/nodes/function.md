# 函数节点（JS 计算）

在画布上写一小段 **纯 JS**，把输入算成输出——轻量计算节点。参数即端子，可跟任何节点连线、级联、批量、保存。

创建：画布空白处右键 → **工具** → **函数（JS 计算 · 自定义入参出参）**。

## 设置
点头部小「设置」按钮：

- **函数名 fnName**（可选，仅备注）
- **描述 description**
- **输入参数类型（文本 / 图像）**：每一条 = 一个输入端子（文本值为字符串；图像值为 `{kind:"image", path}` 路径对象）。
- **数组 · 可接多条线**（只在**输入参数**行上出现）：勾上后这个端子吃的是一**组**值，见下面「数组输入端子」。
- **输出参数类型（文本 / 图像）**：每一条 = 一个输出端子，**出参和入参一样要声明类型**——把某个输出结果标成「图像」，它就是图像端子。输出端子一律**一号一值**，没有数组档位。

参数行可以**调整顺序**：拖动行左侧 ⠿ 把手插到任意位置，或用行尾 ▲▼ 逐格移动——参数顺序即端子顺序，已连的数据线跟着参数一起移位（不会漂到别的参数上）。

## 数组输入端子（一条线不够用，就像图生图要多张参考图）
有些计算要的是**一组**输入：图生图想多喂几张参考图、批量文本想把 N 条线汇成一个数组处理。以前只能"加参数 1、参数 2、参数 3…"并把代码里的取参方式一起改掉；现在把这个输入参数勾上「**数组 · 可接多条线**」即可：

- **同一个端子可以连多条数据线**（和生图节点的参考图槽一样，想多加一张就再连一条），不再报「该输入端子已被占用」。
- 端子渲染成**可增长的槽位组**：徽标 = 参数名 + 每个已连线一个亮槽点（`参考图[1] [2] …`）+ 末尾一个空槽——每多接一条线就多一个槽，跟普通处理节点「连一个自动多一个输入」同直觉；悬停槽点显示这条来源，右键某个槽只断开那一条。引擎仍是「一个逻辑端子可收多条线」，所以 JS 拿到数组的口径不变。
- **代码里这个参数恒为数组**：一条线也没挂时是空数组 `[]`，只挂一条时也是长度为 1 的数组——所以可以无条件 `for` / `map`，不用先判断"到底是单个还是数组"。
- 数组**只改形状，不改类型**：标成「图像」的数组端子仍然只收图像来源，接错照旧点名去哪儿改。
- 元素顺序 = 你连线的顺序；每个元素仍按该端子声明的类型归一（图像端子拿到路径文本会补成 `{kind:"image", path}`）。

```js
// 输入参数：提示词（文本）· 参考图（图像 · 勾了「数组 · 可接多条线」）
const refs = input["参考图"];          // 恒为数组：没挂线是 []，挂三条就是三条
if (!refs.length) return "至少接一张参考图";
return { 清单: refs.length + " 张：" + refs.map((r) => r.path).join(" | ") };
```

不想连线也能一次试一批：点「**测试**」，数组参数那格会渲染成**可 ＋/－ 的多行输入**（一行一条值，留空的行不注入）。

## 端子类型有什么用（用户可见收益）
端子声明的类型是**连线校验、保存选型、连线着色**的唯一依据：

- **从图像输出端子把线拖到保存节点，会自动按图像保存（扩展名自动变 `.png`）**；从文本输出端子拖过去则按文本保存（`.yaml`），不必再手动挑「文本保存 / 图像保存」。
- 图像线只能接进图像端子、文本线只能接进文本端子（音视频文件路径算文本）；接错会点名「哪个端子是什么类型、去哪儿改」。
- 图像端子与图像连线单独着色；节点摘要上的输出也会标「（图像）」。

## 写代码
在节点上直接编辑 JS（默认给了注释模板）。**代码不在画布进程里跑**：每次运行函数节点，MTNode 主进程都会为它单独起一条**执行线程**（`fn-runtime.js`），画布只负责把代码交出去、等结果——

- 语言能力全开（可以写 `async` 函数体、可以直接 `await`），再长的等待或循环也**不会锁死界面**；
- 运行期间节点显示「运行中」并计入左下角**运行队列**，随时可停；
- 运行结束 / 被停止 / 超时（默认 10 分钟）：这条线程立刻终止，它拉起的外部进程也**连进程树一并回收**——函数节点只要不在运行状态，属于它的线程和进程就不存在；
- 代码抛错 / 超时都只写成该节点的 ✕ 错误，不打断画布上其它运行。

**入参对象 input**（每条接线同时给三套键，按方便取用）：
- `$<端子序号>`：端子 1 = 第 1 个输入参数，端子 2 = 第 2 个，依此类推（端子 0 = 控制入，不进来）
- 来源标题 / 参数名：接进来的文本节点标题等
- `values`：按接线顺序的数组

键名取的是**本节点的参数名**（参数即端子），`input.$1` 恒等于第 1 个输入参数端子的值——与连线挂载的先后无关。**数组端子（勾了「数组 · 可接多条线」的那个参数）拿到的是数组**，没挂线时是 `[]`，见上文「数组输入端子」。

代码体写 `return` 即输出；也可以写成 `(input) => ...` 的箭头 / 具名函数，返回函数时自动用 input 再调一次。

### 线程里能做什么（`mtnode` 桥）
函数体已经**不在渲染进程**，所以没有 `window` / `document` / `window.api.*`；要落地到本机，用注入的 `mtnode`：

| 写法 | 作用 |
| --- | --- |
| `const r = await mtnode.exec("git", ["status"], { cwd })` | **隐藏**启动外部程序并等它退出 → `{ ok, pid, code, signal, killed, stdout, stderr }`（不弹任何控制台窗口） |
| `const p = await mtnode.spawn("chrome", ["--headless=new"])` | 隐藏启动、**不等**退出，继续往下跑；返回 `{ ok, pid, id }` |
| `await mtnode.wait(p)` | 等这个 `spawn` 的进程退出，拿回退出码与输出 |
| `await mtnode.kill(p)` | 只杀这一个进程（连同它的子进程树） |
| `await mtnode.processes()` | 本次运行当前还活着哪些外部进程 |
| `await mtnode.sleep(1500)` | 等待（不占界面、不占 CPU） |
| `mtnode.log(...)` / `mtnode.progress(0.4, "第 3 批")` | 过程输出与进度（走事件帧回界面，不写 stdout） |
| `mtnode.readText(p)` / `mtnode.writeText(p, s)` / `mtnode.fileExists(p)` | 本机文件读写 |
| `mtnode.join(...)` / `mtnode.abs(p)` / `mtnode.cwd()` / `mtnode.platform` | 路径与平台 |

这些外部进程**全部记在本次运行名下**：函数 `return`、被停止或超时的那一刻，主进程按 runId 把它们连同子进程一起收走。`process.exit()` 之类能带走 MTNode 本体的入口在线程里被拦成抛错。

### 迁移示例：以前用 `window.api` 起程序
旧写法只能在渲染进程里成立，搬进独立线程后必然报 `window is not defined`（报错里会直接点名这段迁移说明）：

```js
// ❌ 旧：会弹出一个可见控制台窗口，而且窗口关了进程还在
window.api.shellOpenPathDetached("E:\\tools\\render\\run.bat");
return { started: true };

// ✅ 新：隐藏启动、等它跑完并拿到输出；出错就在节点上显示 ✕
const r = await mtnode.exec("E:\\tools\\render\\run.bat", [], {
  cwd: "E:\\tools\\render",
});
if (!r.ok || r.code !== 0)
  return "渲染失败（code " + r.code + "）：" + (r.stderr || r.error || "");
return r.stdout;

// ✅ 需要它在后台先跑一会儿？也照样交给本次运行回收（return 后自动杀掉）
const p = await mtnode.spawn("E:\\tools\\server\\app.exe", [], {
  cwd: "E:\\tools\\server",
});
await mtnode.sleep(2000); // 等 2 秒让它把服务起起来
mtnode.log("server pid =", p.pid);
const st = await mtnode.wait(p); // 拿退出码与输出
return { code: st.code, out: st.stdout };
```

同理，想读本地文件不要再指望 `window.api.readFileText`，直接 `mtnode.readText(路径)`。

返回值归一：
- 字符串 / 数字 / 布尔 → 文本
- `{kind:"image"|"audio"|"video"|"path", path}` → 对应媒体（引擎按扩展名判定）
- 其余对象 → 自动 JSON 序列化为文本

在此之上，**每个输出端子还会按它自己声明的类型再归一一次**（只换形状、不吞数据）：
- 端子标成「图像」、拿到的是路径字符串 → 自动补成 `{kind:"image", path}` 图像值（下游保存节点才认它是图像）。
- 端子标成「文本」、拿到的是图像值 → 取其路径作文本，节点摘要提示一句「图像已按其路径取文本」。

### 多输出分发
`return` 一个**普通对象**、且它的键命中**输出参数名**时，按键名分发到各输出端子（第 i 个输出参数 = 端子 i）：

```js
// 输出参数：主文本（文本）、摘要（文本）、附图（图像）
return {
  主文本: big,
  摘要: big.slice(0, 40),
  附图: { kind: "image", path: "E:/out/a.png" },
};
```

- 只命中几个就写几个端子；没命中的参数端子取不到值（下游为 null）。
- 标量 / 字符串 / 数组 / 一个键都没命中 → 仍按**单输出**兼容：只写端子 0。
- 一个输出参数都没有时，结果落在端子 0（下游仍可从端子 0 取）。
- 「附图」这类输出在「设置」里标成**图像**后，`return` 里就算只给路径字符串 `"E:/out/a.png"` 也会补成图像值，直接拖到保存节点即按 `.png` 图像保存。

示例（两个输入参数端子上各接一个数字文本源）：

```js
const x = Number(input.$1);
const y = Number(input.$2);
if (!Number.isFinite(x) || !Number.isFinite(y))
  return "请在两个输入参数端子上接入数字文本";
return "和：" + (x + y) + "；积：" + (x * y);
```

## 代码编辑器（高亮 / 行号 / 缩进 / 格式化）
**节点没被选中时只显示内容**（像其它节点那样直接看到函数名、描述、入参 / 出参、代码正文与上次结果，整块干干净净、不占屏幕），**点一下节点才出现可编辑的代码块**，光标自动落在代码里；点画布空白处取消选中，就又回到只读显示。编辑态下这块代码区就是为「几十行小函数」量身做的编辑器（与「测试」台里那个是同一份实现、同一个 `node.jscode`，两边改动即时互通）：

- **语法高亮**：注释 / 字符串 / 数字 / 关键字 / 字面值分别着色，函数调用名与属性名另色；契约词 `input`、`values` 和 `$1`、`$2` 这类端子键有专门颜色，一眼能看出你在读哪个端子。
- **行号槽**：左侧逐行编号，光标所在行高亮；横向 / 纵向滚动都与代码同步。
- **缩进**：`Tab` 插 2 空格；选区跨行时 `Tab` / `Shift+Tab` 整块加一层、减一层；`Enter` 继承上一行缩进，行尾刚开括号会自动补一层，光标夹在空的一对括号里则撑开一块并把光标停在内层。中文输入法组字时回车不会被劫持。
- **格式化**：代码区上方工具条点「**格式化**」——按 2 空格缩进**就地重排**，不合并也不拆分任何一行、不改一个字的内容；`switch` 的 `case` 体多算一层；连续空行折成 1 行、去行尾空格、末尾不留空行（再点一次不会变样）。模板串与未闭合块注释内部的行原样保留（那里的空格是内容）。代码已是格式化后的样子时会直接告诉你。
- 工具条右侧常显「行 X / 共 N 行」；点「生成脚手架」写进来的代码也过同一份格式化，第一眼就是排好的。

## 开发（绑定该函数的会话）
节点卡片下方有「**开发**」按钮（旁注「用会话改造 / 扩展本函数」，鼠标悬停会显示已绑定几个开发会话）。它就是**绑定这一个函数节点的会话**：

- 点击先弹窗回显现状（函数名、节点标题、描述、入参端子、出参端子、JS 行数、会话工作区、最近一次要求），你在文本框里写**本次要修改 / 扩展的内容**；边写边留存，取消或 Esc 都不丢，下次打开原样回填；`Ctrl+Enter` 提交。
- 确认 = **新建一条绑定该函数的会话并在后台运行**：标题「开发 · 函数名」、工作区 = 该节点所属画布目录、预设 / 模型 / 思考强度跟随你当前默认；人留在画布上，进度看左下角运行队列与会话列表。
- 这个会话**只改这一个函数节点**：改的就是节点上的 **JS 代码（jscode）与参数表（inputs / outputs）**，必要时同步描述与函数名；不会新建 / 删除 / 改动其它节点，也不会增删连线。
- **改参数要复核连线**：参数即端子，动 `inputs` / `outputs` 参数表就是动端子，端子数一变、已连的线可能改指别的端子。会话只要动了参数表，就会在回复里明确提醒你回画布复核该节点的连线——别跳过这一步。
- 需求不明确时它会先问你再动手；改完用一句话汇报改了什么、有没有动参数表。函数还没有代码时也能用：会话会按现有入出参从零写出函数体。

## 测试（不参与画布运行）
点头部「**测试**」按钮开独立对话框（与「设置」分开）：上半整块 JS 代码区，中部**每个输入参数一个字段**（文本 = 多行框，图像 = 路径 + 选文件；**数组参数 = 可 ＋/－ 的多行，一行一条值**），点「▶ 运行测试」后**逐输出端子**展示结果与错误。

- 测试输入记在节点上（下次打开还在），但**仅测试用**：不写节点输出、不级联下游、不进撤销历史。
- 数组参数留空的行不注入，全空 = 空数组（与画布上一条线都没挂时同一个形状），底部回显「当前注入 N 条」。
- 想知道某个端子实际会传什么值，用测试台最省事；确认无误再点 ▶ 真跑一次。

## 端子与运行
- **输入**：端子 0 = 控制入（固定）+ 各输入参数端子（**勾了数组的那个参数端子可挂多条数据线**）
- **输出**：各输出参数端子（0..n-1）+ 末位控制出（固定）；输出端子恒是一号一值
- 每个数据端子都带声明类型（文本 / 图像）；控制端子不带类型，按实际值判定
- 点 ▶：自动补跑上游 → 代码在主进程的独立线程里执行（界面不卡，节点显示「运行中」、进左下角运行队列）→ 结果按上面的规则分发到输出端子并级联下游；代码抛错显示 ✕ 错误（同时写错误端子），不中断其它运行。
- 被停止 / 超时：这一次运行的线程立刻终止，它拉起的外部进程连同子进程一并回收，节点写成「已手动停止」——不会留下任何脱离运行的窗口或进程。
