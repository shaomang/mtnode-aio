# 开发节点（软件项目架构）

开发节点是一种**特殊超级节点**（`dev:true`），把软件项目拆成**多层功能块树**（模块 → 文件 → 类 / 接口 / 枚举），直接在画布上做架构设计与开发管理。每个开发节点都绑定真实项目，头部有「建议 / 开发 / 细化」三个按钮。

## 元素层级（不同外框颜色）

| 类型 | 外框 | 说明 |
| --- | --- | --- |
| **模块（功能块）** | 绿色 | 项目中的一个模块 / 子系统；概述（note）说明它在项目中的作用 |
| **文件** | 蓝色 | 细化产物，指向某个源码文件 |
| **类 / 接口 / 枚举** | 橙 / 紫 / 粉 | 类图元素，通常由「文件」再细化而来 |

默认外框色（元素类型）：模块 `#6fe3a5` · 文件 `#6db4ff` · 类 `#ffb454` · 接口 `#c792ea` · 枚举 `#ff8fa3`。

创建：画布空白右键 → **开发节点（项目架构 · 功能块）** → 选元素类型（模块 / 文件 / 类 / 接口 / 枚举）。同一菜单内还有 **执行节点**，可绑定项目的启动脚本 / 可执行文件，方便一键跑起来。

## 功能色卡（按功能自动上色）

创建功能块时，引擎会按**功能分类**自动给它选一个边框颜色——一套色卡对应一类功能，架构图打开就按功能分区，不用你一块块调色。

| 功能分类 | 边框色 | 典型关键词（标题 / 概述） |
| --- | --- | --- |
| **核心运行时** | `#6db4ff` 蓝 | 主进程 · 启动 · 窗口 · 菜单 · 快捷键 · 编辑器 · 引擎 · `main` `runtime` `electron` `core` |
| **画布与交互** | `#45cfe6` 青 | 画布 · 连线 · 排版 · 面板 · 视图 · 缩放 · 拖拽 · `canvas` `layout` `ui` `css` |
| **AI 与 Agent** | `#c792ea` 紫 | 智能体 · 会话 · 助手 · 提示词 · 模型 · 推理 · `agent` `llm` `model` `prompt` |
| **数据与存储** | `#4dd0c4` 青绿 | 数据库 · 存储 · 缓存 · 配置 · 导入导出 · 副本 · 迁移 · `db` `storage` `json` |
| **媒体与本地后端** | `#ff8fa3` 粉 | 文生图 · 音乐 · 视频 · 音频 · 语音 · 显存 · 后端 · 权重 · `music` `video` `tts` `gpu` |
| **插件与生态** | `#f0c14d` 黄 | 插件 · 技能 · 扩展 · 商店 · 云端 · 服务端 · `plugin` `skill` `store` `server` |
| **构建与诊断** | `#ff9d5c` 暖橙 | 构建 · 打包 · 发布 · 脚本 · 更新 · 日志 · 崩溃 · `build` `npm` `updater` `ci` |
| **测试与质量** | `#a8e05f` 黄绿 | 测试 · 冒烟 · 断言 · 覆盖率 · 用例 · 回归 · `test` `smoke` `lint` `e2e` |

- **依据**：只看功能块的**标题 + 概述**做关键词匹配（中文按子串、英文按整词，`ai` 不会误命中 `chain` / `detail`）；标题命中权重是概述的 2 倍，分数最高的分类胜出。**一个关键词都不命中就不上色**，保持模块默认的绿色。
- **只管功能块**：功能色只作用于 `模块` 这一层；`文件 / 类 / 接口 / 枚举` 仍用各自的元素类型默认色，所以层级靠颜色照样一眼可辨。
- **优先级：你手选的颜色 > 功能色 > 元素类型默认色。** 自动上色只在**创建那一刻**写一次，之后你随时可以在色板里改；想让某块回到类型默认色，点色板里的「恢复元素类型默认色」（这也会去掉当初自动写入的功能色）。
- 助手（Agent）创建的开发节点同样会自动上色；你也可以直接让它「把这几块按 XX 功能色上色」，改色前它会先问你。

## 关键设置

- **概述 note**（必填，合计 ≤200 字）：**两段式**，各占一行、顺序固定、不可只写一段——
  - **【功能】≤80 字 · 面向非技术读者**：用业务语言说清该模块「做什么、给谁用、解决什么问题」；禁止出现文件名、函数名、框架名。示例：「让用户像搭积木一样编排工作流：在画布上摆节点、连线、点运行就能看到每一步产出」。
  - **【实现】≤120 字 · 面向工程师**：实现方案梗概——技术栈 / 语言、关键文件或目录、数据流向与对外接口、依赖与边界（本块不负责什么）。示例：「Electron 渲染层，对应目录：renderer/。app-canvas.js 负责节点与连线绘制，app-nodes.js 负责增删改与批量编辑，状态单向渲染」。
  - 旧画布里的单段概述仍正常显示，下一次「细化 / 开发 / 建议」时自动升级为两段。
- **项目根目录 devPath**：设在**顶层功能块**上（绝对路径）；子块自动继承最近祖先的项目根。它同时决定这张画布上 Agent 文件写到哪儿——见下文「项目根 = Agent 工作区」。
- **状态 devStatus**：pending（待开发）/ wip（开发中）/ done（已完成）。
- **嵌套**：**细化按深度**（不是「一次只剥一层」）——默认**深度细化到无法再细**（拆出的子块继续判断能否再拆，一路下钻，一般到文件级；文件还可继续拆类 / 接口 / 枚举），也可选**只展开本层**（仅建 1 层，之后到各子块上分别点「细化」）；产物应为**多层功能块树**。
- **节点颜色 devColor**：元素类型徽章旁的**颜色小按钮**（圆点 = 当前色）→ 展开 **HSV 色板**（S×V 方块 + 色相条，也可直接输入 Hex），改的是该功能块的**外框与运行呼吸灯**颜色；点「恢复元素类型默认色」回到类型配色。色板里还有一行**功能色卡**：8 个分类色块（悬停看分类名），**点一个就把本块设成该功能色**（等同于在 HSV 里选到同一个值，可撤销）；不想用色卡就照常拖 HSV 或输入 Hex。
- **Agent 模型 / 预设 / 思考强度 devModel · devPreset · devEffort**：头部 🧠 按钮展开「**Agent 设定**」弹层，顶部**三格**并列——**预设 / 模型 / 思考强度**，与智能会话里那个 Agent 菜单是**同一张档位表、同一套语义**（交互也一致：点哪一格只看那一格的清单）。选定后，**本功能块的「建议」只读调研、「开发 / 细化」绑定会话与「问询」会话都按这三项下达**；三格全未指定时按应用默认档运行（**默认档 = 极简模式** + 标准思考档 `high`）。
  - **预设 `devPreset`**：`AGENT_PRESETS` 的档位——**极简（默认）** / 标准 / 思维精简 / PTC 模式 / 创造（清单顺序就是档位表顺序，第一档即默认档；悬停有该档说明；旧名 sketch 自动认成 思维精简）。
  - **模型 `devModel`（+`devProvider`）**：按服务商分组的模型清单（`devProvider` 可省，应用会按模型反查路由）。
  - **思考强度 `devEffort`**：档位词汇表（与新建会话 / 助手思考强度菜单同一张表）内的值——`low`=轻 / `medium`=中 / `high`=标准（默认）/ `xhigh`=强 / `max`=最强。弹层里露出**四档：轻 / 标准 / 强 / 最强**（`medium` 是合法词汇，但默认 DeepSeek 路由会把它夹到 `low`，所以不在 UI 露出），选哪档就按哪档跑；不在词汇表内的值一律不记录。
- **三档各自就近向上继承**：模型 / 预设 / 思考强度**分别**沿父块向上找**第一个已选值**，互不牵连——可以在顶层块一次统一整棵树的模型与预设，再单独给某个子块换思考档；子块自己选过就以子块为准。**空 = 跟随默认**（不是「继承不到就不跑」）。弹层里继承来的值标「（继承）」与 ↩，格子下方一行写清它继承自哪个块；节点按钮文字为 `模型 · 预设 · 思考档`（虚线 = 模型来自上层，三格全未指定 = 自动）；「**建议**」「**问询**」两个确认框各列出「Agent 模型 / Agent 预设 / 思考强度」三行，「**开发**」对话框列出生效 Agent 模型（预设与思考强度同样下达），折叠卡 body 保持精简、不常驻显示。**清除**：切到那一格点底部「跟随默认（不指定）」，只退这一格，可撤销。
- **思考档只看设置**：格子里的档位（轻 / 标准 / 强 / 最强，对应 `low` / `high` / `xhigh` / `max`）就是本轮实际下发的那一档——**预设不再改写思考强度**（早先「思维精简」会把标准自动压到 low，现已取消），所以界面不再有「名义档 / 生效档」两套写法。路由能力不足时网关把请求夹到同侧最近低档并回传 effort 事件（界面回显「所选档 → 实际生效档」）。点「建议」时作业日志会打一行「本轮：服务商 · 模型 · 预设 · 思考档」（只点名真正选过的项），继承自上层的会点名来源块。
- **AI 读写**：`mtnode_canvas_get` 会返回 `devPreset` / `devEffort`；`mtnode_canvas_edit` 的 create / update 补丁可直接设置（与 `devModel` 同规则：传空串 = 清除回跟随默认；未知预设 id 会被拒绝并回报，思考强度只认档位词汇表内值 `low` / `medium` / `high` / `xhigh` / `max`，集合外值一律丢弃并回报）。
- **核心文件列表 devFiles**：折叠卡「**文件 N**」按钮展开本模块最关键的源码文件（**最多 10 个 · 相对项目根**），点任意一行在资源管理器中定位该文件；由开发 / 细化会话回写、可手工编辑，都为空时自动兜底收集。**最外层（项目）节点不列举**。详见下文「核心文件列表」。
- **共识文件 AGENTS.md**：生成开发节点架构时（用内置技能扫描建图 / 新项目搭建），会在**项目根目录**同步产出一份 `AGENTS.md`（目录约定 + 「不要修改」清单），作为本项目所有开发 / 细化 / 建议会话共享的核心共识——新会话先读它再动手：文件放哪、哪些路径（如 `dist/`、迁移、密钥）绝对不能改。架构图最外层会放一个 **`agent.md` 入口节点**（文件类型）：点它的「打开」即可用**应用内 Markdown 阅读器**查看 / 编辑 / 保存这份共识文件（项目根没有 agent.md 时自动打开既有 AGENTS.md）。
- **阅读器（Markdown / YAML）**：应用内两个文本阅读器都支持**查看、大纲跳转、编辑与保存**——打开 `.md` / `.yaml` 文件（保存节点「打开」、开发文件节点「打开」、系统里打开这类文件）即弹出；点「编辑」进入全文编辑，`Ctrl+S` 或「保存」写回文件。

## 三个按钮（都先弹对话框确认）

- **建议**：确认后 AI 做**只读**调研（读项目真实代码 + 该模块开发进度），返回**恰好 4 条**下一步方案。你在同一对话框里**任意多选 + 补充说明**，再点对话框里的「开发」＝按所选方案开工。结果会缓存（查看上次建议不重跑；「换一批」才重跑）。
- **开发**：显示模块标题 / 概述 / 状态 / **Agent 模型**，填写本次要开发或迭代的内容，确认后在**新建的绑定会话**里运行（工作区 = 项目根，会话标题「开发 · 模块名」，历史保留；模型 / 预设 / 思考强度都沿用该功能块所选或就近继承的生效值）。
  - **绑定会话不读画布，收尾按 id 回写**：这条会话本轮**没有** `mtnode_canvas_get` / `mtnode_app`（宿主不注册，调用即失败）——它改的是项目根里的真实文件，整张画布快照对它没有信息量，画布现状一律以**开发任务书**为准。任务书自带**本节点的 id**，收尾时直接用 `mtnode_canvas_edit` 的 `update` 按这个 id 点名**本节点**，回写**概述（note）· 状态（devStatus）· 核心文件列表（devFiles）**，**不为了拿 id 先去读一遍图**（省下这一步整份读图负载、每轮重发）。因此 `mtnode_canvas_edit` 是这条会话唯一保留的画布工具，且**只动本节点这一个对象**；想让 AI 顺带改图上别的节点，请到**智能会话**里做，并确认那条会话没开「与画布无关」——那个开关连改画布的工具一起关掉，见 [智能任务与智能会话](#agent-nodes)。「细化」用的是同一份任务书，口径一致。
  - **「先拷问需求（grill-me）」勾选**：勾上后这条会话**第一轮不动手**，而是用内置技能 `mtnode-grill-me` 把需求映射成一棵决策树、**按轮**问完整个「前沿」——**每轮都走 MTNode 自己的询问窗**（屏幕下方的「🐋 模型等待你的回应」卡片）：一次把该轮全部问题弹出来，每题给候选项、**推荐的那一项排在第一位并标「（推荐）」**，你在卡片里点选（也可在「其他」里补自己的答案），不用在输入框里打字作答；需要查的事实它自己查、不问你。直到前沿问空、你在询问窗里明确选中「确认无歧义」才开始实现。**这个开关粘在该功能块上**（记在节点的 `devGrill`，随画布保存），下次打开「开发」仍然勾着，可随时取消；不勾时与以往**逐字一致**。「细化」与「建议 → 开发」用的是同一份任务书，因此同样生效；「**问询**」（只读会话）不受这个开关影响。
- **细化**：确认是否继续展开子元素。**「细化」指的是深度，不是本层建几个子块**：对话框里有**「细化深度」单选**——「深度细化到无法再细」（默认：拆出的子块继续判断能否再拆，一路下钻到无法再细，一般到文件级）／「只展开本层」（仅在本块内建 1 层，之后到各子块上分别点「细化」）；另有一行**深度统计**告诉你现状（如「当前已 3 层 · 5 个块未到文件级（如 A、B、C）」「当前已 4 层 · 已细化到文件级」「当前 0 层（尚未展开下层元素）」）。细化前先给出**多层规划树（内容梗概清单）**，经你**一次确认**才逐层创建节点；无需或无法细化（含**已细化到无法再细**）时会明确告诉你原因。
- **已结束轮次遗留的询问 / 确认会自动消失**：开发 / 细化 / 建议各跑各的一「轮」，只有**本轮**自己发出的提问、审批与画布 / 数据库确认才会弹到你面前。上一轮遗留的后台任务、或新运行时预热轮迟到的询问，会在网关侧被直接挡掉（那边的那个工具以失败收场，AI 继续往下走）；万一确认框已经弹在屏上而它所属的那一轮已经结束，它会**自动关闭**并说明「发起轮已结束，未执行」——不会再出现「跑着跑着突然多出一个询问窗、回答后执行无效」。

## 核心文件列表（「文件 N」按钮）

每个功能块都能记下**本模块最关键的几个源码文件**，直接点着跳到磁盘上看，不必先展开壳层再去项目树里翻。

- **在哪**：折叠卡 body 下方按钮组里，「打开」之后、「会话 N」之前多一个 **「文件 N」** 按钮（N = 条数，一条都没有时只显示「文件」）。**点它展开列表**，再点一下收起。
- **点任意一行 = 打开该文件所在的文件夹**（在资源管理器中定位该文件）；列表里每行显示文件名 + 灰色相对路径，文件已不存在会标「不存在」。面板头部另有「**打开项目根**」，直接打开本块所属项目的根目录。
- **最多 10 个**：超出上限时只保留前 10 条，并提示多余部分已忽略；相对项目根和绝对路径都能写，落在项目根内的绝对路径会自动折成相对路径显示。
- **最外层（项目）节点不列举**：整棵架构最外面那一块（项目节点）代表的是整个项目，列「核心文件」没有意义，因此它**不显示「文件」按钮**，也不接受会话回写。
- **列表从哪来（三条来源）**：
  1. **会话回写**——该模块的「开发 / 细化 / 建议」会话收尾时，会顺手把真实核心文件写回这里（任务书已内置这条要求），这是列表长期准确的关键；
  2. **你手工编辑**——点列表头部的「**编辑**」，每行填一个路径（相对项目根，如 `renderer/app-devnode.js`），可点「自动收集」取应用的分析结果、或「清空」，**点「确定」才写入**（可撤销）；
  3. **自动兜底**——前两者都为空时，应用从本块下层「文件」块的标题与本块概述【实现】里出现的路径**自动收集**一份，此时面板会标「**自动收集 · 点『编辑』确认**」，看过一眼、确认无误后点「确定」就转成你确认过的列表。
- **前提**：相对路径靠**本块解析到的项目根（`devPath`）**才能定位；没设项目根时列表照样能保存，但点开文件会提示你先到顶层功能块设置项目路径。
- **给助手用**：`mtnode_canvas_get` 能读到这份列表（纯自动收集时另标 `devFilesAuto`），`mtnode_canvas_edit` 用 `devFiles` 补丁写入或清空（传 `[]`）——所以你可以直接说「把这几块的核心文件补上」。

## 项目根 = Agent 工作区

画布上只要有开发节点设了 **devPath**，这张画布就是「项目画布」：**上面所有 Agent 运行的生效工作区都会变成项目根**，不再是顶栏那个画布目录。这是 AI 能直接读写你真实代码的前提，也是最容易让人以为「文件写错地方了」的一处，所以单独讲清。

### 每个入口的生效工作区（从左到右，先命中先用）

| 入口 | 生效工作区优先级 | 说明 |
| --- | --- | --- |

### 项目根怎么解析（只有一个真源）

- 只看画布上的**开发节点**（`dev:true`；数据库超级节点不算）。
- 每块**就近取 devPath**：自己没有就沿父链向上找最近一个设了 devPath 的开发块——所以按约定**只在顶层功能块填一次**，整棵树共用。
- **顶层功能块优先**；空值与相对路径一律忽略（必须绝对路径）。
- 解析出**多个不同的根**时：若它们同属一个上层目录，就取那个**共同祖先**（一个根覆盖全部）；覆盖不了则取排在最前的那块，并提示「本画布有多个项目根，已用第一个」——想换另一根：改顶层功能块的 devPath，或在该入口**手填**工作目录。
- 画布上有开发节点但**一块都没设 devPath**：工作区照旧（画布目录 / 默认目录），助手会提示「在顶层功能块设 devPath 后，工作目录会优先用它」。

### 副作用：相对路径的文件到底落在哪

- **落到项目根，不会落到画布目录。** 在项目画布上说「写个 notes.md」，它会出现在**项目根**下，而不是你顶栏选的那个文件夹里。找不到文件时先想到这里。
- 想写到画布目录或别处，三选一：**给绝对路径**；在助手 / 会话 / 节点里**手填工作目录**（手填永远压过项目根）；或到**没有开发节点**的画布上操作。
- **保存节点与超级节点「子文件夹」是另一套口径**：它们的相对路径始终相对**顶栏画布工作目录**（再拼祖先链上的子文件夹），**不受项目根影响**。所以同一张项目画布上，保存节点写画布目录、Agent 写项目根，两处互不重叠——这是「文件怎么找不到」的头号来源。详见 [工作目录与存档](#workspace)。
- 想确认到底在用哪个目录：助手与会话的工作目录框显示的都是**生效值**（不是原始手填值），把光标停在上面看「来源：手填指定 / 画布项目根 / 画布工作目录 / 应用默认目录」，或点 📂 直接打开那个文件夹。

## 关系线（rel）

元素之间用**关系线**表达依赖 / 调用 / 实现等（右键连线时选「关系」，可带文字标签与箭头方向）。关系线是**一条普通直线**（不走直角折线）、**不参与执行**，纯架构表达；箭头方向可选 **→ 正向 / ← 反向 / ←→ 双向 / — 无箭头**，双击线或线上文字可改标签。

展开的功能块里关系线很多时，引擎会**整体规划**同一层内的所有关系线：每条线的进出点取「中心连线与方块边框的交点」，同一节点同一侧的多条线**扇形散开**接在不同锚点；散开的顺序先按对端方块中心，再按**对端真实来向**收敛一两趟——只有让直线互相交叉**确实变少**时才采纳，否则保持原样（不会来回抖动）。两条几乎重合的直线会**沿各自的边滑开**直到可分辨，线上文字自动避让。

展开壳层的端子排**不再写「输入 / 输出」这两个标题**（谁进谁出由端子上的参数名自己说话）；工具 / 函数节点的端子名平时按宽度收省略号，**鼠标移到该节点上或选中它时自动放开，显示完整名称**。

**点击任意节点**（含展开壳层里的功能块）：与它相关的关系线立刻亮起（青色 + 光晕，箭头同步变色），与它无关的关系线淡出退到背景；点线本身仍是**橙色 = 选中这条线**，点空白处取消。

## 排版（架构图不再糊成一团）

- **关系线参与自动排版**：顶栏「一键排版」以及开发节点右键的**「按关系线整理内部排版（分层 · 可撤销）」**会按箭头方向给功能块**分层排布**（左 → 右），并做减交叉重排；成环的关系线会自动降级为「只影响顺序、不参与分层」的软约束，因此双向 / 回环引用也不会把布局绕死。
- 分层图会**自动加宽列 / 行间距**（列间约 196px、行间约 92px），让直线少穿过无关方块、彼此也不叠在一起。
- **展开的壳层会按内部内容自动撑大**：细化 / 批量创建 / 收纳子块后，壳层尺寸跟着内容走，不会再被默认的 720×480 舞台裁掉。
- 反过来，**开发节点的「整理内部排版」会按内容收紧壳层**（排版后尺寸贴合架构范围）。

## 建议从哪开始

- 已有项目：让 AI 用内置技能 **mtnode-dev-architect** 扫描项目文件夹，生成覆盖全项目的开发节点架构图。
- 新项目：先搭架构（顶层模块 → 细化文件 / 类），你确认后按画布逐块开发。
- 不确定处（加不加插件、技术选型）AI 会先问你，不会擅自决定。
