# 开发节点：让 AI 写项目

> 一句话目标：用「模块 → 文件 → 类 / 接口 / 枚举」的功能块树描述一个真实项目，再让绑定会话按块把代码写进项目根。

![开发节点](img/mtnode-agent-10-ui.svg)
*图 1：开发节点——头部「建议 / 开发 / 细化」三个按钮，折叠卡里有「打开 / 文件 N / 会话 N」*

## 目标

读完这一页，你能在一张画布上搭出覆盖整个项目的**多层功能块树**，给顶层块绑定项目根 `devPath`，用 🧠「Agent 设定」给每块指定模型 / 预设 / 思考强度，用「建议 / 开发 / 细化」三个按钮把设计一层层落到真实代码，并在项目根产出所有会话共享的 `AGENTS.md`。

## 前置条件

- 已在 [服务商与 API](#providers) 配好服务商与模型。
- 一个真实项目的**绝对路径**（顶层功能块要填 `devPath`）。
- 已了解 [超级节点](#super-nodes)：开发节点是一种特殊超级节点（`dev:true`），对外的输入 / 输出端子只有边界端子。
- 已了解 [审批与权限](#approvals)：开发会话会读写你项目里的真实文件。

## 步骤

1. **建块**：画布空白右键 → **开发节点（项目架构 · 功能块）** → 选元素类型。同一菜单里还有 **执行节点**，可绑定项目的启动脚本 / 可执行文件，方便一键跑起来。
2. **填概述**：概述 note 必填、合计 ≤200 字，**两段式**、各占一行、顺序固定、不可只写一段：
   - **【功能】≤80 字 · 面向非技术读者**：用业务语言说清该模块「做什么、给谁用、解决什么问题」；禁止出现文件名、函数名、框架名。
   - **【实现】≤120 字 · 面向工程师**：技术栈 / 语言、关键文件或目录、数据流向与对外接口、依赖与边界（本块不负责什么）。示例：「Electron 渲染层，对应目录：renderer/。app-canvas.js 负责节点与连线绘制，app-nodes.js 负责增删改与批量编辑，状态单向渲染」。

   旧画布里的单段概述仍正常显示，下一次「细化 / 开发 / 建议」时自动升级为两段。
3. **绑项目根**：在**顶层功能块**上填 **devPath**（绝对路径）；子块自动继承最近祖先的项目根。它同时决定这张画布上 Agent 的文件写到哪儿，见下文「项目根 = Agent 工作区」。
4. **细化**：点「细化」→ 选**细化深度** → 看**深度统计** → 确认**多层规划树（内容梗概清单）**。默认「深度细化到无法再细」：拆出的子块继续判断能否再拆，一路下钻，一般到文件级；文件还可继续拆类 / 接口 / 枚举。
5. **记核心文件**：用折叠卡的 **文件 N** 按钮展开本模块关键源码文件（**最多 10 个 · 相对项目根**），点任意一行在资源管理器中定位该文件；面板头部另有「打开项目根」。
6. **开发**：点「开发」→ 填本次要开发或迭代的内容 → 确认后在**新建的绑定会话**里跑（工作区 = 项目根，会话标题「开发 · 模块名」，历史保留）。
7. **建议**：点「建议」→ AI 做**只读**调研（读项目真实代码 + 该模块开发进度），返回**恰好 4 条**下一步方案；你在同一对话框里**任意多选 + 补充说明**，再点对话框里的「开发」＝按所选方案开工。结果会缓存，「换一批」才重跑。

### 层级与颜色

| 类型 | 外框 | 说明 |
| --- | --- | --- |
| **模块（功能块）** | 绿色 | 项目中的一个模块 / 子系统；概述（note）说明它在项目中的作用 |
| **文件** | 蓝色 | 细化产物，指向某个源码文件 |
| **类 / 接口 / 枚举** | 橙 / 紫 / 粉 | 类图元素，通常由「文件」再细化而来 |

默认外框色（元素类型）：模块 `#6fe3a5` · 文件 `#6db4ff` · 类 `#ffb454` · 接口 `#c792ea` · 枚举 `#ff8fa3`。

**功能色卡**：创建功能块时引擎按**标题 + 概述**做关键词匹配自动上色——核心运行时 `#6db4ff` 蓝、画布与交互 `#45cfe6` 青、AI 与 Agent `#c792ea` 紫、数据与存储 `#4dd0c4` 青绿、媒体与本地后端 `#ff8fa3` 粉、插件与生态 `#f0c14d` 黄、构建与诊断 `#ff9d5c` 暖橙、测试与质量 `#a8e05f` 黄绿。标题命中权重是概述的 2 倍，一个关键词都不命中就不上色（保持模块默认绿）。功能色**只管模块这一层**；优先级是**你手选的颜色 > 功能色 > 元素类型默认色**，自动上色只在创建那一刻写一次。改色走元素类型徽章旁的颜色小按钮（字段 `devColor`）→ HSV 色板（也可直接输入 Hex），或直接点色卡里的分类色块；点「恢复元素类型默认色」可退回类型配色。

### 🧠 Agent 设定：模型 / 预设 / 思考强度

头部 🧠 按钮展开「**Agent 设定**」弹层，顶部**三格**并列——预设 / 模型 / 思考强度，与智能会话里那个 Agent 菜单是同一张档位表、同一套语义。选定后，本功能块的「建议」只读调研、「开发 / 细化」绑定会话与「问询」会话都按这三项下达；三格全未指定时按应用默认档运行（**默认档 = 极简模式** + 标准思考档 `high`）。

- **预设 `devPreset`**：`AGENT_PRESETS` 的档位——极简（默认）/ 标准 / 思维精简 / PTC 模式 / 创造；清单顺序就是档位表顺序，悬停有说明（旧名 sketch 自动认成 思维精简）。
- **模型 `devModel`（+`devProvider`）**：按服务商分组的模型清单；`devProvider` 可省，应用会按模型反查路由。
- **思考强度 `devEffort`**：`low`=轻 / `medium`=中 / `high`=标准（默认）/ `xhigh`=强 / `max`=最强；弹层里露出**四档：轻 / 标准 / 强 / 最强**（`medium` 是合法词汇，但默认 DeepSeek 路由会把它夹到 `low`，所以不在 UI 露出）。**思考档只看设置**：格子里选的那一档就是本轮实际下发的那一档，预设不再改写思考强度（早先「思维精简」会把标准压到 low，现已取消），路由能力不足时网关夹到同侧最近低档并回显「所选档 → 实际生效档」。
- **三档各自就近向上继承**：模型 / 预设 / 思考强度**分别**沿父块向上找**第一个已选值**，互不牵连——可以在顶层块一次统一整棵树的模型与预设，再单独给某个子块换思考档；子块自己选过就以子块为准。**空 = 跟随默认**（不是「继承不到就不跑」）。弹层里继承来的值标「（继承）」与 ↩，格子下方写清继承自哪个块；清除时切到那一格点底部「跟随默认（不指定）」，只退这一格，可撤销。
- **AI 读写**：`mtnode_canvas_get` 会返回 `devPreset` / `devEffort`；`mtnode_canvas_edit` 的 create / update 补丁可直接设置（传空串 = 清除回跟随默认；未知预设 id 会被拒绝并回报，思考强度只认 `low` / `medium` / `high` / `xhigh` / `max`，集合外值一律丢弃并回报）。

### 核心文件列表（「文件 N」按钮）

- **在哪**：折叠卡 body 下方按钮组里，「打开」之后、「会话 N」之前；点它展开列表，再点收起。
- **列表从哪来（三条来源）**：① **会话回写**——该模块的「开发 / 细化 / 建议」会话收尾时会顺手把真实核心文件写回这里，这是长期准确的关键；② **你手工编辑**——点列表头部「编辑」，每行填一个相对项目根的路径（如 `renderer/app-devnode.js`），可点「自动收集」或「清空」，**点「确定」才写入**；③ **自动兜底**——前两者都为空时，应用从本块下层「文件」块的标题与本块概述【实现】里的路径自动收集，此时面板标「自动收集 · 点『编辑』确认」。
- **上限与例外**：超出 10 条只保留前 10 条并提示多余部分已忽略；相对路径与绝对路径都能写，落在项目根内的绝对路径会自动折成相对显示。**最外层（项目）节点不列举**：它不显示「文件」按钮，也不接受会话回写。
- **前提**：相对路径靠本块解析到的项目根（`devPath`）定位；没设项目根时列表照样能保存，但点开会提示你先到顶层功能块设置项目路径。助手侧用 `mtnode_canvas_get` 读（纯自动收集时另标 `devFilesAuto`）、`mtnode_canvas_edit` 用 `devFiles` 写入或清空（传 `[]`）。

### 三个按钮与绑定会话

- **开发 / 细化**确认后都在**新建的绑定会话**里运行：所属画布 = 该功能块所在的画布，工作区在创建那一刻就写成项目根（等同于已手填，之后改顶层 `devPath` 也不会回头改老会话）；模型 / 预设 / 思考强度沿用该块所选或就近继承的生效值。
- **绑定会话不读画布，收尾按 id 回写**：这条会话本轮**没有** `mtnode_canvas_get` / `mtnode_app`（宿主不注册，调用即失败），画布现状一律以**开发任务书**为准；任务书自带**本节点的 id**，收尾用 `mtnode_canvas_edit` 的 `update` 按 id 点名回写**概述（note）· 状态（devStatus）· 核心文件列表（devFiles）**，不必为了拿 id 先读一遍整图。想让 AI 顺带改图上别的节点，请到 [智能会话](#agent-nodes) 里做。
- **「建议」/「问询」**只读：不建会话、不改文件、不改画布，只认这一块的项目根。
- **「先拷问需求（grill-me）」开关**：勾上后这条会话第一轮不动手，而是用内置技能 `mtnode-grill-me` 把需求映射成决策树、**按轮**用「🐋 模型等待你的回应」询问窗一次问完整个前沿（推荐项排第一位并标「（推荐）」），直到前沿问空、你在询问窗里确认才开始实现。开关记在节点的 `devGrill`，随画布保存。
- **状态 `devStatus`**：pending（待开发）/ wip（开发中）/ done（已完成）。
- **已结束轮次遗留的询问会自动消失**：只有本轮自己发出的提问、审批与确认才会弹到你面前；确认框所属的那一轮已结束时，它会自动关闭并说明「发起轮已结束，未执行」。

### 关系线与排版

元素之间用**关系线**（`rel:true`）表达依赖 / 调用 / 实现等：右键连线时选「关系」，可带文字标签与箭头方向。关系线是一条**普通直线**（不走直角折线）、**不参与执行**，纯架构表达；箭头可选 → 正向 / ← 反向 / ←→ 双向 / — 无箭头，双击线或线上文字可改标签。展开的功能块里关系线很多时，引擎会整体规划同一层内所有关系线的进出点与扇出顺序；两条几乎重合的直线会沿各自的边滑开，线上文字自动避让。**点击任意节点**：与它相关的关系线立刻亮起（青色 + 光晕），无关的淡出退到背景；点线本身仍是橙色 = 选中这条线。

**排版**：顶栏「一键排版」以及开发节点右键的「按关系线整理内部排版（分层 · 可撤销）」会按箭头方向给功能块**分层排布**（左 → 右）并做减交叉重排；成环的关系线降级为「只影响顺序、不参与分层」的软约束，所以双向 / 回环引用不会把布局绕死。展开的壳层会按内部内容自动撑大，开发节点的「整理内部排版」则会按内容收紧壳层。

### 项目根 = Agent 工作区

画布上只要有开发节点设了 **devPath**，这张画布就是「项目画布」：**上面所有 Agent 运行的生效工作区都会变成项目根**，不再是顶栏那个画布目录。这是 AI 能直接读写你真实代码的前提，也是最容易让人以为「文件写错地方了」的一处。

各入口的生效工作区（先命中先用）：

- **助手**（画布右侧 ✦）：手填工作目录 > 画布项目根 > 画布工作目录（顶栏）> 应用默认目录（工作范围是「仅当前画布」时手填无效）。
- **智能会话**：会话手填 / 📂 选的 > **所属画布项目根** > 应用默认目录（这一档里没有画布工作目录）。
- **功能块「开发」/「细化」**：该块解析出的项目根 > 画布通用解析（该块没设到项目根时退回，对话框顶部有黄条提醒）。
- **功能块「建议」/「问询」**：同上，只认这一块的项目根，界面上写作「未设置 · 用默认工作区」。
- **画布上的智能节点**：节点手填工作目录 > 画布项目根 > 画布工作目录（顶栏）> 应用默认目录。

**项目根怎么解析（只有一个真源）**：只看画布上的开发节点（`dev:true`，数据库超级节点不算）；每块就近取 `devPath`，自己没有就沿父链向上找最近一个设了它的开发块；空值与相对路径一律忽略（必须绝对路径）；解析出多个不同的根时，若它们同属一个上层目录就取共同祖先，覆盖不了则取排在最前的那块并提示「本画布有多个项目根，已用第一个」。

**副作用：相对路径落到项目根，不会落到画布目录。** 在项目画布上说「写个 notes.md」，它会出现在项目根下。想写到画布目录或别处，三选一：给绝对路径；在助手 / 会话 / 节点里手填工作目录（手填永远压过项目根）；或到没有开发节点的画布上操作。注意**保存节点与超级节点「子文件夹」是另一套口径**：它们的相对路径始终相对顶栏画布工作目录，不受项目根影响。想确认在用哪个目录，把光标停在助手 / 会话的工作目录框上看「来源」。

### 共识文件 AGENTS.md

生成开发节点架构时（用内置技能 `mtnode-dev-architect` 扫描建图 / 新项目搭建），会在**项目根目录**同步产出一份 `AGENTS.md`（目录约定 + 「不要修改」清单），作为本项目所有开发 / 细化 / 建议会话共享的核心共识——新会话先读它再动手：文件放哪、哪些路径（如 `dist/`、迁移、密钥）绝对不能改。架构图最外层会放一个 **`agent.md` 入口节点**（文件类型）：点它的「打开」即可用**应用内 Markdown 阅读器**查看 / 编辑 / 保存这份共识文件（项目根没有 `agent.md` 时自动打开既有 `AGENTS.md`）。

## 结果

- 画布上出现一棵多层功能块树，模块按功能色分区，元素类型靠外框颜色一眼可辨。
- 顶层块绑定了项目根；「开发 / 细化」跑完后，项目根里的真实文件被改写，节点的概述、状态、核心文件列表按 id 回写。
- 项目根多出 `AGENTS.md`，最外层有 `agent.md` 入口节点可打开阅读。
- 关系线画清依赖方向，一键排版后架构图左 → 右分层、不再糊成一团。

## 常见错误

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 文件写到项目根，不在顶栏画布目录 | 画布有开发节点设了 `devPath`，Agent 工作区变成项目根 | 设计行为；要写画布目录就手填工作目录、给绝对路径，或换一张没有开发节点的画布 |
| 点核心文件提示先设项目路径 | 该块没解析到项目根 | 到顶层功能块填 `devPath`（绝对路径） |
| 「文件」按钮不见了 | 那是**最外层项目节点**，不列举核心文件 | 在下层模块上看；项目节点不接受会话回写 |
| 子块的思考档和父块不一样 | 三档各自就近继承，子块自己选过就以子块为准 | 到该子块的 🧠 里点「跟随默认（不指定）」退掉这一格 |
| 细化没把结构建完 / 只建了一层 | 细化深度选了「只展开本层」 | 改成「深度细化到无法再细」重跑，或到各子块上分别点「细化」 |
| 想让绑定会话顺手改画布上别的节点，失败了 | 绑定会话不注册 `mtnode_canvas_get` / `mtnode_app`，只保留 `mtnode_canvas_edit` 且只动本节点 | 到 [智能会话](#agent-nodes) 里做，并确认没开「与画布无关」 |
| 助手写文件写到别处 | 手填工作目录或绝对路径优先于项目根 | 清掉手填目录，或用绝对路径明确指定 |
