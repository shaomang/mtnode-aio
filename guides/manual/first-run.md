# 第一条工作流

> 一句话目标：从空画布走到「屏幕上出现模型输出」，只做四步：加节点 → 连线 → 写 `@` → 点 ▶。

![四步上手](img/mtnode-start-03-flow.svg)
*图 1：加节点 → 连线 → 写 `@` 引用 → ▶ 运行；上游没跑过会自动递归执行*

## 目标

读完并照着做一遍，你会得到一张有两个节点、一条连线的画布，并且**亲手跑出一次真实的模型输出**。

## 前置条件

- 已经有一个能用的文本服务商与 API Key（见 [配置服务商与 API](#providers)）。没配 Key 时画布照常编辑，但 ▶ 会报错。
- 电脑可以联网（模型调用走网络）。

## 步骤

1. **加输入节点**：在画布**空白处右键** → 「输入节点」→ **文本**。标题点一下就能改名。
2. **填内容**：点选这个节点，在正文框里输入一段材料；点到别处即离开编辑态。
3. **加处理节点**：空白处右键 → 「处理节点」→ **文本处理**，放在输入节点右侧。
4. **连线**：从文本输入节点**右侧的输出端子**按住拖到文本处理节点**左侧的输入端子**，松手即连上。连不上通常是端子类型不匹配。
5. **写提示词并引用上游**：点选文本处理节点，在提示词里输入 `@` → 从候选里选中刚连上的文本节点 → 再补要求（例如「把 @文本 总结成三点」）。运行时上游内容进「背景信息」，提示词进「内容」。
6. **选模型**：点节点头部 **⚙ 设置**，选服务商与模型；不选则用全局默认。
7. **运行**：点文本处理节点上的 **▶**。上游还没跑过时会**自动先执行上游**；这一步结束后下游会**自动接着跑**。

> 💡 技巧：点 **◈ 预览完整请求** 可以先看清这次到底把什么发给了模型，确认无误再花钱跑。

> ⚠️ 危险：处理节点跑完会**自动执行下游**；若下游已有内容会弹出询问（覆盖 / 不继续）。批量链路上尤其要先看清这个询问，选错会把已有结果冲掉。

## 结果

- 文本处理节点的输出面板出现模型返回的正文（Markdown 会渲染），节点从「运行中」变回空闲。
- 底部状态栏的保存状态显示已保存；关掉应用再打开，这张画布与内容都还在。

## 常见错误

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| ▶ 报「未配置服务商 / 缺少 Key」 | 还没配文本服务商 | 去 [配置服务商与 API](#providers) |
| 线拖不过去 | 端子类型不匹配（如图像输出接只收文本的输入） | 换成能吃该类型的节点，或先把内容转成文本 |
| 输出里没有上游内容 | 忘了写 `@`，或没从候选里确认 | 重新输入 `@` 并确认选中条目 |
| ▶ 之后没反应 | 上游在跑，或正在等你的审批 / 提问 | 看左下角运行队列与屏幕下方的询问窗 |
| 结果被覆盖了 | 自动执行下游时选了「覆盖」 | 用输出面板的 Tab 回看其它次结果，必要时重跑 |
| 报路径相关错误 | 保存节点没设路径，或越出了工作目录 | 见 [工作目录与存档](#workspace) |
