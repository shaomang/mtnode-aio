# 上架应用到云端（多版本）

> 一句话目标：把本机做好的应用打包传到云端，让别的用户能在「应用中心」看到它、下载使用或二次开发；同一个应用可以有很多版，别人自己选下哪一版。

## 入口在哪

顶栏「应用」→ 左导航「开发」→ 顶部那一行菜单条，在「启动」右边点**「上架」**。
入口与「应用」本身同一份白名单（见 `renderer/app-apps.js` 的 `APPS_USER_WHITELIST`）；没登录会先提示登录。

## 二次开发（fork）：声明你基于哪个应用改的

对别人的应用二次开发后再上架时，在上架窗「**基于哪个应用二次开发（可选）**」里选上源应用即可：

- 默认自动带出：本机 `app.json` 里已声明过的来源 → 没有就带出「本机这份是从哪个云端条目装下来的」。
- 可以改成目录里别的条目，也可以选「（原创：不声明来源）」表示原创 —— **不声明不影响上架**。
- 声明会记在云端条目上（源应用 id + 原作者 uid），目录里对外可见；本机也会写进 `app.json` 并随包走，
  以后再上架会自动带回。
- 效果：别人打开这个应用时会看到「**切换分支 ▾**」，可以在你的版本与源应用的版本之间选一个装 / 启动。
  各分支装在自己的 id 目录里，互不覆盖。

应用的身份 = **应用 id + 作者 uid**：同一个应用被不同作者二次开发会各自上架成不同 id 的条目，
靠上面的声明归成「同一应用的多个分支」。

## 上架前先「启动」一次

上架窗默认要一张**应用窗口截图**：点「拍应用窗口」抓的是这个应用**自己的窗口**，所以要先点「启动」把窗口打开。
窗口没开、或最小化了，都会明确告诉你（不会偷偷帮你开窗、也不会拍成桌面）。

也可以「从本机选图」，最多 8 张、可删可排序，**第一张是封面**。

## AI 生成 + 人工核对

- 打开上架窗就自动生成一次元信息（标题 / 描述 / 版本号 / 标签），不满意点「重新生成」。
- AI 能看到的只有该应用的 `app.json` 与入口页的可见文本；生成结果只是**草稿**，一定要自己核对着改完再提交。
- 没有配置文本服务商时会如实提示，字段留空让你手填 —— 不会编一份假元信息出来。
- **版本号**：第一次上架 `1.0.0`；同一个应用再上架默认「上一版小版本 +1」（`1.2.0` → `1.2.1`），可以手改。
- **应用 id** 由英文标题自动生成（小写、2–64 位字母 / 数字 / `._-`），可手改。它同时是别人本机的**安装文件夹名**，尽量短。

## 声明（必须勾选）

上传前必须勾选：

> 本人保证该应用符合中华人民共和国法律法规，不含违法有害内容，不侵犯他人知识产权；因该应用产生的全部责任由上传者承担。

服务端会为每一次上传留痕：**时间 · 账号 · IP · 应用 id · 版本号**；不勾选就传不上去（服务端也会拒绝，不是只在前端拦）。

## 限额

| 限额 | 口径 |
| --- | --- |
| 每个账号最多 **5 个应用** | 给**已有**应用追加新版本不计入 |
| 每个账号云端已存包总量 ≤ **50MB** | 名下**所有应用的所有版本**加起来 |

超限时界面会显示当前用量，并让你在上架窗里勾选删除旧版本。删除某一版 = **那个包与那条版本记录一起下掉**（不留灰行），配额当场释放。

## 多版本怎么收纳

同一个应用 id 的所有版本收在**一个应用**里：新版本带上「上一版版本号」（`parentVersion`），
在「应用」页展开详情就是一棵**版本树**：

- 每行 = 版本号 · 时间 · 大小 · 上传者 · 版本说明，并标出「最新」「本机已装」。
- 点某一行的「下载这一版」= **只下那一版**（已装过就覆盖载荷；你的数据文件夹与该应用自己的画布不动）。
- 作者删掉某一版后，它的下一版在树里挂在「根版本（已删）」占位行下面 —— **版本不会从树上消失**。
- 「更新」按钮恒指向最新版，**只在同作者时出现**（别人的分支走「切换分支 ▾」）；
  卡片上已装 = 显示「启动」而不是「下载」；正在开发中的应用点更新会先提醒会覆盖 `app.json` / 入口页 / `assets`。

## 下架 / 重新发布

作者在「应用」页自己的条目上可以**下架**：目录里不再显示，但**包与所有版本仍留在云端**；
再点「重新发布」就回来。下架后的条目仍只对你自己可见（带「已下架（仅自己可见）」标记），所以不会失联。

## 上传后多久能被别人看到

接口侧**立即**生效，但客户端读的是**静态目录**（`http://mt-agent.com/mtnode/apps/catalog.json`）。
发布端要把 `apps/catalog.json` 与每一版的包一起同步上去，别人才能看到与下载 ——
口径见 `docs/apps-market.md` 的「五、部署」与「七、上架与多版本」。

## 服务端开关（运维）

- 环境变量 `MTNODE_APP_VERSIONS=1` 打开多版本；**不设（默认）时保持旧的覆盖式行为**（一个应用一个包）。
- 版本接口、配额错误码（`QUOTA_BYTES` / `QUOTA_APPS`）与声明字段见 `docs/apps-market.md` §七。
- 命令行也可上架 / 追加版本：`python store-saas/upload-app.py --accept-declaration …`（见该文档 §四与 §七）。

## 传不上去时先看这四件事

1. **没登录** —— 先登录再上架。
2. **没勾声明** —— 勾上再传。
3. **配额满了**（提示带当前用量）—— 在上架窗里删掉不再需要的旧版本。
4. **包不合法** —— 应用缺少入口页（`index.html`）或不在本机；先回开发页确认应用能「启动」。
