# 上架应用到云端（多版本）

> 一句话目标：把本机做好的应用打包传到云端，让别的用户能在「应用中心」看到它、下载使用或二次开发；同一个应用可以有很多版，别人自己选下哪一版。

## 入口在哪

顶栏「应用」→ 左导航「开发」→ 顶部那一行菜单条，在「启动」右边点**「上架」**。
上架统一叫「上架」：**新上传与更新都叫上架** —— 第一次上架会在云端新建一条，已经上架过就是给
同一条**追加一版**；按钮文案不再变，是新建还是追加由云端按「应用 id + 作者 uid」判定，
结果里会如实标出「（新建应用）」或「（追加版本）」。换一个账号登录后会上架成**另一条**应用。
入口与「应用」本身同一份白名单（见 `renderer/app-apps.js` 的 `APPS_USER_WHITELIST`）；没登录会先提示登录。

## 二次开发（fork）：声明你基于哪个应用改的

对别人的应用二次开发后再上架时，在上架窗「**基于哪个应用二次开发（可选）**」里选上源应用即可：

- 默认自动带出：本机 `app.json` 里已声明过的来源 → 没有就带出「本机这份是从哪个云端条目装下来的」。
- 可以改成目录里别的条目，也可以选「（原创：不声明来源）」表示原创 —— **不声明不影响上架**。
- 声明会记在云端条目上（源应用 id + 原作者 uid），目录里对外可见；本机也会写进 `app.json` 并随包走，
  以后再上架会自动带回。
- 效果：别人打开这个应用时会看到「**切换分支 ▾**」，可以在你的版本与源应用的版本之间选一个装 / 启动。
  各分支装在自己的 id 目录里，互不覆盖。

应用的身份 = **应用 id + 作者 uid**：同一个应用被不同作者二次开发会各自上架成不同 id 的条目，
靠上面的声明归成「同一应用的多个分支」。

## 截图：点「拍应用窗口」才拍

上架窗**不会**在开窗时替你启动应用、也不会自动拍照：点「**拍应用窗口**」才动手 ——
这一下会启动这个应用（窗口没开就替你开、最小化也会被还原）并拍下当前窗口，
不必再回开发页点一次「启动」。也可以「从本机选图」，最多 8 张、可删可排序，**第一张是封面**。

每张截图**单张最大 5MB**（长边收到 2560）：超过 1MB 的图会自动转成 WebP 再传，画质基本看不出差别。
**封面图标仍是 ≤500KB**（图标口径没跟着放宽）；没有单独选图标时，第 1 张截图会**压到 512 长边 / ≤500KB**
来顶图标位。

同一张图再次上传时**不会重复占用云端空间、也不会重复推字节**：客户端按内容指纹认出「云端已经有这张」
就只发一个引用（重开上架窗也记得，云端别人传过的同一张图同样算命中）。你在截图卡片上能直接看到
每张图这一轮压了多少、哪几张是「云端已有，只发引用」。

一张截图都不加就点上传时会先拦一句：商店卡片与详情头部会**没有封面**（没有单独选图标时，
图标本来也取自第 1 张截图），确认后才继续传。

## AI 生成 + 人工核对

- 打开上架窗就自动生成一次元信息（标题 / 描述 / 版本号 / 标签），不满意点「重新生成」。
- AI 能看到的只有该应用的 `app.json` 与入口页的可见文本；生成结果只是**草稿**，一定要自己核对着改完再提交。
- 没有配置文本服务商时会如实提示，字段留空让你手填 —— 不会编一份假元信息出来。
- **版本号**：第一次上架 `1.0.0`；同一个应用再上架默认「上一版小版本 +1」（`1.2.0` → `1.2.1`），可以手改。
- **应用 id 默认锁定**：它是云端那条应用的身份，也是别人本机上的**安装目录名**。默认锁在本机应用 id
  （有上架记录时锁在**上次上架那个云端 id**，旁边标出本机目录名）；标题怎么改都不动它。
  真要改就点 id 右边的**「修改 id」**：先弹一次确认，说明**改 id = 在云端新建一个应用**
  （以后就是另一条，不再追加版本），确认后本次窗内才能编辑，改回原值自动恢复锁定。
  首次上架同样锁定 —— 不再由英文标题自动生成 id。

## 声明（必须勾选）

上传前必须勾选：

> 本人保证该应用符合中华人民共和国法律法规，不含违法有害内容，不侵犯他人知识产权；因该应用产生的全部责任由上传者承担。

服务端会为每一次上传留痕：**时间 · 账号 · IP · 应用 id · 版本号**；不勾选就传不上去（服务端也会拒绝，不是只在前端拦）。

## 限额

| 限额 | 口径 |
| --- | --- |
| 每个账号最多 **5 个应用** | 给**已有**应用追加新版本不计入 |
| 每个账号云端已存包总量 ≤ **50MB** | 名下**所有应用的所有版本**加起来（截图与图标也算在内；同一张图全站只算一份） |

这两个数是**默认值，管理员可以在后台给单个账号单独调**（放宽，或设成「不限」）。上架窗页脚一直显示
你的「**已用 / 上限**」，所以不用猜 —— 上限被调过就按调过的走。**已存的内容不会因为上限被调小而丢失**：
超额只是不能再新增（会被拒并告诉你当前用量）。

超限时界面会显示当前用量，并让你在上架窗里勾选删除旧版本。删除某一版 = **那个包与那条版本记录一起下掉**（不留灰行），配额当场释放。
删完**结果留在「⑤ 线上版本」那一行**（成功写「已删除 vX，配额已释放」；失败写服务端原话并给一颗「重试」），
版本区同时按服务端**重读**刷新 —— 删掉的版本不会还挂在列表里。
勾到**最后一版**时确认框会多一句：删完这个应用就被**彻底删除**（云端记录与包一起移除，不可恢复）。

## 多版本怎么收纳

同一个应用 id 的所有版本收在**一个应用**里：新版本带上「上一版版本号」（`parentVersion`），
在「应用」页展开详情就是一棵**版本树**：

- 每行 = 版本号 · 时间 · 大小 · 上传者 · 版本说明，并标出「最新」「本机已装」。
- 点某一行的「下载这一版」= **只下那一版**（已装过就覆盖载荷；你的数据文件夹与该应用自己的画布不动）。
- 作者删掉某一版后，它的下一版在树里挂在「根版本（已删）」占位行下面 —— **版本不会从树上消失**。
- 「更新」按钮恒指向最新版，**只在同作者时出现**（别人的分支走「切换分支 ▾」）；
  卡片上已装 = 显示「启动」而不是「下载」；正在开发中的应用点更新会先提醒会覆盖 `app.json` / 入口页 / `assets`。

## 删除 = 云端彻底移除

**删除 = 云端彻底移除，不可恢复**：点「删除」并手动输入应用标题后，这一条分支的记录、全部版本包、
图标与截图一起从云端下掉，目录里立刻不再显示，也没有「恢复 / 重新发布」的回头路。
**删单个版本不是删应用**：只删某一版时，只要这条分支还有别的版本，应用照旧在线上（最新版指向剩余最高版）。

## 管理已上架的应用：「我的应用」页

应用中心左导航第 2 页**「我的应用」**专管你上架到云端的条目（含你从别人 fork 后上架的）：
搜索框按标题 / 描述 / 标签过滤，条目多时用底部「加载更多」（接口一页 50 条）。
每张卡片右下角两枚图标 = **编辑 / 删除**（点卡片本身仍是详情窗，详情里也有带文案的同款按钮）。

- **编辑**：改标题、描述、标签、封面图标与上架截图（最多 8 张，可单张删除、可拖动排序）；
  「保存」前必须勾选那条与上架时**逐字相同**的声明。编辑**不发新版本** —— 版本号不动，
  只是所有人都立刻看到新的说明与图。保存成功后，本机同 id 的应用（下载根与项目根各一份）
  的标题 / 描述 / 标签会**一起写回** `app.json`，库页卡片跟着变；图标不写本机文件
  （库页封面取的就是云端图标）。
- **删除**：真删**你这一条分支**（记录、版本包、图标、截图一起下掉，云端**彻底移除、不可恢复**）。
  要手动输入应用标题才能点「删除」。别人基于你的应用 fork 出来的分支与包**一个都不动**，
  确认框会写明「另有 N 位作者的派生分支会保留」；本机已下载的副本也不会被删
  （要删去「库」页卸载）。
- 截图编辑需要**新版服务端**：旧服务端会忽略这次改动，客户端会明确提示
  「截图没生效：云端服务端需要升级后生效」，其余修改照常保存。

## 上传后多久能被别人看到

接口侧**立即**生效，但客户端读的是**静态目录**（`http://mt-agent.com/mtnode/apps/catalog.json`）。
发布端要把 `apps/catalog.json` 与每一版的包一起同步上去，别人才能看到与下载 ——
口径见 `docs/apps-market.md` 的「五、部署」与「七、上架与多版本」。

## 服务端开关（运维）

- 多版本**默认开**（2026-10 起；此前默认关，线上因此一直回 `409 APP_VERSIONS_DISABLED`）。
  要回到「一个应用一个包」的旧覆盖式行为，才在 `/etc/mtnode-store.env` 里显式写
  `MTNODE_APP_VERSIONS=0`（或 `false` / `no` / `off`）并重启服务。
- 版本接口、配额错误码（`QUOTA_BYTES` / `QUOTA_APPS`）与声明字段见 `docs/apps-market.md` §七。
- 命令行也可上架 / 追加版本：`python store-saas/upload-app.py --accept-declaration …`（见该文档 §四与 §七）。

## 传不上去时先看这四件事

1. **没登录** —— 先登录再上架。
2. **没勾声明** —— 勾上再传。
3. **配额满了**（提示带当前用量）—— 在上架窗里删掉不再需要的旧版本。
4. **包不合法** —— 应用缺少入口页（`index.html`）或不在本机；先回开发页确认应用能「启动」。

> 若提示是「**第 N 张截图压缩后仍超过 500KB**」，那是**云端服务端还是旧版**（旧版单张只收
> 500KB / 长边 1280）；客户端这边已经把图压到 5MB 档也救不了，需要先部署新版服务端
> （见 `docs/apps-market.md` §五「发布顺序纪律」）。自查一次就知道线上是新版还是旧版：
> `GET /api/apps/<id>/shots-diag` 回的 `maxShotBytes` 是 `512000` 就是旧版、`5242880` 就是新版。

> 若是「**截图传上去了、应用中心的卡片却没有封面**」（连图标也是空的），那是**客户端版本**的问题
> 而不是云端：旧客户端的内容安全策略只放行了裸域 `mt-agent.com`，而线上图片会被 301 到
> `https://www.mt-agent.com` —— 每一次取图都在那一跳被拦掉。升级到含该修复的客户端版本即可
> （2026-10 修复）；自查 = 打开开发者控制台，看到
> `Loading the image 'https://www.mt-agent.com/…' violates the following Content Security Policy directive: "img-src …"`
> 就是它。
