# 工作目录与存档

> 一句话目标：搞清楚「相对路径到底相对谁」「画布存在哪」「为什么数据绝不写在应用文件夹里」。

![工作目录](img/mtnode-edit-03-state.svg)
*图 1：顶栏的工作目录输入框决定本画布所有相对路径的落点；存档、备份与日志则统一落在本机数据目录。*

## 目标

这一页回答三个具体问题：

1. **相对路径相对谁**——顶栏给当前画布指定的**工作目录**。
2. **东西存在哪**——本机数据目录（Windows 默认 `%APPDATA%\pipeline-console\`）下的 `save/` 与 `save-backups/`。
3. **为什么不能存进应用文件夹**——升级 / 卸载会带走或覆盖它，所以应用会主动拦截并做启动体检。

工作目录同时也是智能节点读写文件的默认根目录，因此它和 [智能任务与智能会话](#agent-nodes)、[保存、导入导出与工坊](#workflows) 强相关。

## 前置条件

- 准备一个**已存在**的文件夹当工作目录（新建画布时会强制要求，且路径必须真实存在）。
- 想改数据目录的话先关掉正在跑的智能任务——改完需要重启应用。
- 不需要管理员权限；工作目录可以是任意用户可写目录。

## 步骤

### 1. 给当前画布指定工作目录

顶栏有一个**工作目录**输入框，右边跟着浏览按钮。填一个文件夹路径即可。

设置生效后：

- 本画布**智能节点与保存节点的相对路径**都相对该目录解析；
- **改目录即统一换落盘位置**——保存节点若写的是相对路径，换个工作目录就整体搬走；
- **留空**则各节点单独设置，或使用应用默认数据目录。

> 💡 技巧：保存路径的规则是「绝对路径原样使用；相对路径相对于顶栏工作目录解析」。有工作目录时新建保存节点默认写相对路径，便于日后统一切换。若一个绝对路径正好落在工作目录内，会被自动存成相对路径，换目录时能跟着走。

**路径无效时会自动清空并提示**，以免助手写到错误位置：提示是「工作目录无效 / 该路径不存在或不是有效文件夹，已自动清空。请重新选择有效的工作目录。」

### 2. 新建画布时一并指定

**新建画布**对话框里有「**工作目录（必填）**」一栏，提示写明：「新建画布必须指定工作目录。智能节点与相对保存路径都相对该目录，缺少目录会导致读写失败。」

不填会直接拦住（「请选择工作目录」），填了一个不存在 / 不是文件夹的路径也会被拒（「工作目录不存在或不是有效文件夹」）。

### 3. 超级节点子文件夹会拼在中间

超级节点可以设**子文件夹**（相对工作目录）。它的内部节点的相对路径会自动落在：

```
<工作目录> / <子文件夹> / …
```

嵌套超级节点会**拼接祖先链上的子文件夹**。把已有节点移入超节点、或修改子文件夹时，会给已有相对路径**补前缀**；**绝对路径不变**。详见 [超级节点](#super-nodes)。

### 4. 找到存档位置

工作流 JSON 存在本机数据目录的 `save/` 下，Windows 多为：

```
%APPDATA%\pipeline-console\save\
```

设置对话框里有 **打开存档位置**，一键在资源管理器里打开它。

### 5. 用画布备份找回旧版本

画布另有**每 5 分钟一次**的自动备份：把各工作流的最新状态**只读复制**一份到同级的 `save-backups/`，内容无变化不重复存，**每条工作流保留最近 72 份**（约 6 小时）。

设置 →「**画布备份**」里有 **打开备份文件夹**。误删或改坏时可从这里手工找回，细节与撤销路径见 [撤销与回滚](#rollback)。

### 6. 认住「数据不落应用文件夹」这条红线

数据目录、事实库、素材库、`save` / 日志等一切用户数据，只允许写进 `%APPDATA%`（默认 `%APPDATA%\pipeline-console`，可在设置里改）或**你选定的项目文件夹**。

任何解析结果如果**等于或位于** `app.getAppPath()` / exe 同目录之下一律**拒绝**——因为升级 / 卸载会带走或覆盖应用文件夹。启动时 `main.js` 的 `auditAppDirData()` 会做一次**只读**体检：

- 命中就写日志并弹出警告，列出「哪些数据落在了应用目录内」，并提示把它们移到项目文件夹后重启；
- 开发态（未打包）只打印一次结论，不弹窗。

> ⚠️ 危险：不要为了「整洁」把事实库、素材库根目录指到 MTNode 的安装目录里。升级后这些数据会一起消失。

### 7. 隐私口径

**不会默认上传任何工作流。** 只有你主动跑节点时，提示词与输入才发往**你自己配置的服务商**；创意工坊上传是你明确选择的模板。API Key 等凭据只存在本机数据目录里。

## 结果

- 顶栏工作目录一栏显示的就是当前画布所有相对路径的根；各节点产物落在预期位置。
- 存档在 `save/`、备份在 `save-backups/`，都能从设置一键打开。
- 启动体检没有告警，说明没有用户数据落在应用文件夹里。

## 常见错误

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 提示「相对路径需要先设置工作目录（顶栏），或改用绝对路径」 | 保存节点用了相对路径，但画布没设工作目录 | 在顶栏填一个已存在的文件夹，或把该节点改成绝对路径 |
| 工作目录被自动清空了 | 路径不存在或不是有效文件夹 | 重新选一个真实存在的目录（新建画布时也会强制校验） |
| 超节点里的保存路径跑到了画布根目录 | 超级节点没设**子文件夹** | 给超级节点设子文件夹；内部相对路径会自动挂到该前缀下 |
| 改了工作目录，旧产物没跟着搬 | 该节点写的是绝对路径，或文件早已落盘 | 绝对路径不随目录变化；需要搬就手工迁移，或改用相对路径重跑 |
| 启动时弹窗「数据保存在应用文件夹内」 | 某项数据（事实库 / 素材库 / save 等）被指到了应用目录下 | 按弹窗列出的路径逐项移到项目文件夹，再重启应用 |
| 设置里改了「配置数据目录」但没生效 | 该改动需要重启 | 按提示立即重启应用；若数据目录由环境变量 `MTNODE_DATA_DIR` 指定，则设置里改不了 |
| 备份文件夹是空的 | 还没到 5 分钟，或内容一直没变化 | 等一次自动备份；内容无变化不重复存属正常 |
| 找不到旧版本存档 | 备份只保留最近 72 份 | 在 `save-backups/` 里按时间戳找；更早的版本无法找回 |
