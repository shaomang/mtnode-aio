# 智能任务与智能会话

> 一句话目标：在画布上放一个「会自己干活」的节点，并用全屏智能会话或右侧全局助手，把一句话需求变成可复跑的工作流。

![智能任务节点](img/mtnode-agent-02-ui.svg)
*图 1：智能任务节点——提示词就是任务描述，头部 💬 可切成会话模式*

## 目标

读完这一页，你能建起一个智能任务节点并让它读写真实文件、执行命令、联网、识图；能把它切成会话模式做多轮追问；能说清「会话属于哪张画布」以及什么时候该关掉「与画布无关」；最后还能让会话或助手直接替你在画布上搭出一条工作流。

## 前置条件

- 已在 [服务商与 API](#providers) 配好可用的服务商与 Key——模型调用按它走。
- 已选定工作目录：节点上用文件夹窗口选择；画布上有开发节点设了项目根时，优先用项目根（见 [开发节点](#dev-nodes)）。
- 已了解右上角 [审批与权限](#approvals)：智能节点的读文件、写文件、命令、联网都受四档预设与工具许可约束。
- 想用技能与 MCP，先到 [插件、技能与 MCP](#plugins-skills) 装好。

## 步骤

1. **建节点**：画布空白处右键 → **智能节点**。开启「🐋 智能」的文本处理节点（`proc_text` 的智能模式）能力相同。
2. **写任务**：在提示词框里写清目标与验收口径——**提示词就是任务描述**，一次运行里模型会自己拆成多步去做。
3. **接输入**：需要上游内容时把端子连进来，或在提示词里写 `@节点标题` 引用；输入 `/` 呼出技能候选。
4. **选模型与目录**：在节点上选服务商 / 模型；工作目录用文件夹窗口选择。
5. **点 ▶ 运行**：节点自行多步推理，中途的思考、正文与 🔧 工具调用按发生顺序分段显示。

> 💡 技巧：智能节点**不做「多次尝试」**——那是生成类节点的抽卡次数。它的一次运行本来就包含多步执行，不是并行抽卡。

### 批量与聚合

- **批量（batch）**：每个输入项各跑一次，**每次只看这一项**——适合「有 N 条素材，各写一篇」。
- **聚合（agg）**：整批只跑一次、一次看全部——适合「把这 N 条汇总成一份报告」。
- 逐条批量时优先用普通处理节点，智能节点只用于聚合；否则每次运行都重发整批内容，调用量会平方级膨胀。

### 会话模式（💬）

1. **切模式**：点节点头部 **💬**，节点切成**会话模式**。
2. **对话**：微信风格多轮气泡（助手在左、用户在右），**历史随节点保存**，追问就在节点里进行。
3. **打开旧节点**：独立的「文本对话」节点已移除——旧画布上的对话节点打开时会**自动迁移**成带会话模式的智能任务节点。
4. **扩展为会话**：需要全屏与更长上下文时，一键**扩展为智能会话**（节点与会话内容同步）。
5. **删除**：删除节点时会提示一并删除关联会话。

### 智能节点允许做的事

智能节点在工作区里完成任务，**不改画布**。具体包括（仍受顶栏「审批」与权限预设约束）：

- 按任务描述多步推理并给出结果
- **读 / 写 / 编辑**工作区文件
- 在工作区执行命令
- 联网搜索与抓取网页
- 使用已安装技能与已连接的 MCP 工具
- 识图（`mtnode_vision`）
- 使用连入的 `@` 引用、批量 / 聚合、所选模型

智能节点**不能**：读取或编辑画布、修改工作流、创建任务图或节点/连线、重命名或删除工作流。需要搭图时用智能会话或全局助手。

## 智能会话

顶栏 **会话** 切到智能会话：多会话、按工作目录分组、归档、分支、斜杠命令（输入 `/` 呼出技能与 `/new` `/compact` `/plan` `/help` 等）。除读写文件、联网、命令外，还可以查看并修改**本会话所属的那张画布**。

### 会话属于哪张画布

会话在**建立的那一刻**就认下一张画布：你当时正看着哪张，它日后就读写哪张；在开发节点上点「开发 / 细化 / 问询」建的会话，所属画布就是那个功能块所在的画布。之后**你可以随意切去其他画布继续干活**，会话本轮的读写图、工作目录、数据库接地全部精准落在它自己那张图上，**不会串到你此刻正看着的画布**，也不会误改、误删你正在编辑的那张。侧栏每条会话标题下的 ▣ 与悬浮说明写的就是它的所属画布（该画布已删除会标出来）。

会话**不跨画布**读写：要参考或切换其他画布，用画布右侧的**全局助手**（✦），并把它的「工作范围」切到「全局」。

### 「与画布无关」开关

会话输入区下方的 **与画布无关** 小按钮（画布右侧助手栏顶部还有一个同名开关，管助手自己）是**由你手动声明**的一档：开启后这一轮**不注册任何画布与应用工具**——`mtnode_canvas_get` / `mtnode_canvas_edit` / `mtnode_app` 都不存在，也**不再注入整张画布快照**，只剩文件读写 / 联网 / 命令（识图仍按工具许可开放）。画布类任务用不上它的时候，它把每一步重发的前缀削掉一大截，**长会话明显省 token**。代价是它从此**真的看不见画布**：**要让它总结或搭建工作流，先把这个开关关掉再重跑**；开着时它会直接回你「需要改画布请先关掉」，不会假装改过图。这个开关随会话落盘、分支会话沿用，与「纯净模式」不是同一档。

开发节点「开发 / 细化」建的**绑定会话**则是**宿主自动判定**的另一档：它**不读画布**（`mtnode_canvas_get` 与 `mtnode_app` 不注册，画布现状一律以开发任务书为准），但 `mtnode_canvas_edit` **保留**——任务书自带**本节点的 id**，收尾时按这个 id 点名回写本节点的概述 / 状态 / 核心文件列表，**不必为了拿 id 先读一遍整张图**。详见 [开发节点](#dev-nodes)。

## 运行中：思考与输出分开显示

运行时按**发生顺序**分段：**「◉ 思考 · N 字」** 是折叠起来的模型内部推理（N 只统计思考字数），正常字号的段落是模型说出来的**正文**（中间步骤说的话也算正文），**🔧 工具**调用就近插在它发生的位置，错误以 ⚠ 附在正文里。每调用一次工具或进入新一步推理就另起一段。

智能任务节点（含会话模式）、智能会话、右侧全局助手口径一致；节点上的「思考中」大窗上半是思考、下半是输出。输出端子给下游的仍是完整正文，旧会话存档按原样显示。详见 [智能能力是什么](#dsh)。

## 让助手搭工作流

在**智能会话**或全局助手里说「实现 xxx 的工作流」，模型会在**它自己那张画布**上**创建节点、改标题、连线、写 @引用**并自动排版（会话 = 所属画布；右侧助手 = 你正看着的这张）。你再改提示词与保存路径后点 ▶。画布上的智能节点不会改图。

全局助手（画布右侧 ✦）也能看状态、搭图，但改画布会先确认。**文档答疑助手不会改画布。**

## 结果

- 画布上多了一个能自己跑完多步任务的智能节点；切到 💬 会话模式后，追问历史留在节点里。
- 顶栏「会话」里能看到这条会话，标题下 ▣ 标出它所属的画布；切到别的画布再回来，它仍只动自己那张图。
- 说一句「实现 xxx 的工作流」后，画布上出现成型的节点、连线与分区，改完提示词即可点 ▶ 复跑。

## 常见错误

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 让它改画布，它回「需要改画布请先关掉」 | 开了「与画布无关」，画布工具没注册 | 关掉该开关后重跑，或改用智能会话 / 全局助手 |
| 它读了别张画布、或改错了图 | 你切了画布，但以为它会跟着切 | 会话锁定建立时的画布；要跨画布用全局助手并把工作范围切「全局」 |
| 文件写进了项目根，不在顶栏目录 | 画布上有开发节点设了 `devPath`，Agent 工作区变成项目根 | 这是设计行为；要写画布目录就手填工作目录，或给绝对路径 |
| 批量任务调用量暴涨 | 逐条批量时用了智能节点，每次重发整批 | 逐条场景改用普通处理节点，只把聚合交给智能节点 |
| 旧画布上的「文本对话」节点不见了 | 该节点已移除，打开时自动迁移 | 直接打开它，即变成带会话模式的智能任务节点 |
