# 批量、拆分与合并

> 一句话目标：让一条输入节点带 N 条内容，按「每条一次」或「一次看全部」两种方式跑完，并知道哪种接法不会把调用量炸开。

![批量 vs 聚合](img/mtnode-flow-04-flow.svg)
*图 1：批量（逐条一次运行）与聚合（全部一次送入）的区别*

## 目标

读完这一页，你能开批量、选对批量 / 聚合模式、用拆分节点只抽一项、用合并节点把多路并成一批，并让保存节点按条目分别命名。

## 前置条件

- 已有一条能跑通的「输入 → 处理 → 保存」链路，见 [输入 / 处理 / 保存](#io-proc)。
- 知道处理节点上可以调参数、抽卡与预览请求，见 [参数与运行调试](#params-runs)。

## 步骤

### 1. 在输入节点上开批量

1. **点输入节点右上角的「批量」**。
2. **文本用三种方式加条目**：**＋** 逐条添加 / **导入**文件 / **粘贴 YAML**。YAML 一行一条，格式是 `标题: 内容`：

```yaml
开场白一: 今天下雨了，写一句开场白。
开场白二: 今天是晴天，写一句开场白。
开场白三: 今天刮风了，写一句开场白。
```

3. **图像批量**：多选图片，或一次把多张图拖进节点。
4. **记住条目标题**：YAML 的键就是该条的标题；图像条目按载入时记住的源文件名取名。标题会用在 `@` 引用与保存文件命名上，**重名会被去重**。

### 2. 在处理节点上选「批量」还是「聚合」

处理节点头部有两种模式：

- **批量**：每条目一次运行，每次只看该条，输出多条。
- **聚合**：所有条目**一次送入**，输出一条。

> ⚠️ 危险：`batch` 模式是**每条一次运行、每次只喂该条**。绝不能把整批 N 条又全部塞进每次运行——那会变成 ≈N² 次调用、token 爆炸、账单翻好几倍。要一次看全部才用 `agg`。

> 💡 技巧：逐条跑时优先用普通（非智能）处理节点；智能节点只在确实要「一次看全部」的聚合场景用，省 token 也更可控。

### 3. 只跑其中一项：拆出单条

不想整批重跑时，接一个**拆分**节点：从批次里抽出某一项，生成一个只读节点，让重活（长提示词、生图、识图）只作用在这一条上。

![拆分与合并](img/mtnode-flow-05-flow.svg)
*图 2：拆分节点抽单项；合并节点把多路汇成一批*

### 4. 把多路并成一批：合并节点

**合并**节点把多个输入汇成一个批次，下游按批量处理——适合「三份素材合成一轮遍历」这种场景。

### 5. 让保存节点按条目分别落盘

- 保存节点在批量链上按 **`{文件名}_{输入节点标题}`** 命名，**每条目一个文件**；勾选「输入变化时自动保存」时也是同一套命名（YAML 项取输入节点标题）。
- 文本批量落盘的是 YAML；多路且都有条目字段名时会写成 YAML 映射，否则做多文档拼接。
- **聚合**模式只产出一个文件，键 = 条目 field，不再用节点标题。

![批量逐条与聚合](img/mtnode-flow-04-demo.svg)
*图 3：左边 3 条输入依次触发 3 次运行；右边切聚合后 3 条合成 1 次（3–8 秒循环动效；慢网或降级时回落静态图 `img/mtnode-flow-04-demo-static.svg`）*

## 结果

- 一条输入节点承载 N 条内容，处理节点按你选的口径跑一遍，产出 N 条或 1 条。
- 保存目录里得到 N 个按条目命名的文件，或 1 个聚合 YAML。
- 需要重跑时，改条目再 ▶ 即可，链路结构不用动。

## 常见错误

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 调用次数 / token 翻了好几倍 | 在 batch 模式下又把整批内容塞进每次运行 | 每次只喂该条；确需一次看全部再切 `agg` |
| 只想要其中一条却跑了整批 | 重活直接接在批量输入下游 | 先接拆分节点抽出该项，再连处理节点 |
| 聚合模式只出一条 | `agg` 本来就是一次运行出一条 | 想要每条一条就切回 `batch` |
| 保存文件互相覆盖 | 条目标题重复，去重后仍重名 | 让 YAML 键 / 图像文件名唯一 |
| 批量图像顺序和预期不一致 | 标题来自文件名，载入顺序决定条目顺序 | 落盘前统一命名，或改用文本条目引用图像 |
| 粘贴的 YAML 只进来一条 | 行格式不是 `标题: 内容`，或缩进 / 冒号用了全角 | 按上面的示例逐行写，键与内容用半角冒号分隔 |
