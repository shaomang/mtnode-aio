# 网络与执行节点

> 一句话目标：用 net_recv / net_send 在两台机器或两张画布之间传文本，用执行节点在画布上一键启动本机程序。

![网络节点](img/mtnode-flow-09-flow.svg)
*图 1：net_send 与 net_recv 通过同一通道号互通*

## 目标

读完这一页，你能搭起一条跨机器 / 跨画布的文本通道（TCP / UDP），并让执行节点成为画布上的「一键启动」按钮。

## 前置条件

- 知道右键菜单的**其他节点**里有 `net_recv` / `net_send`，**开发节点**下有**执行**，见 [加节点、连线与 @ 引用](#nodes-wires)。
- 做跨机器传输时，两台机器网络可达，且防火墙放行所用端口。
- 想在画布上启动项目脚本，脚本文件已存在于本机。

## 步骤

### 1. 放好网络节点

1. **右键画布空白处** → **其他节点** → **net_recv（接收）** 或 **net_send（发送）**。
2. **两台机器各放一个**：一边收、一边发；同一台机器的两张画布之间也可以这么传。

### 2. 把通道对齐

1. **选协议**：TCP 或 UDP，两端必须一致。
2. **设地址与端口**：填 `host:port`；端口填 **0** 表示用**全局设置里的默认端口**（接收 40999 / 发送 41000，可在 设置 · 网络 里改），也可以逐节点覆盖。
3. **选通道号**：同一端口按**通道号（0–65535）**多路复用；发送与接收**同通道即互通**，不同通道互不干扰。

### 3. 接接收端

1. `net_recv` 监听 `host:port`，收到文本后**异步转发下游**：端口 0 = 数据，端口 1 = 控制。
2. 默认**自动监听**；想手动控制就关掉「启动即监听」，用控制线触发。

### 4. 接发送端

1. `net_send` 把数据输入端口的文本推到目标 `host:port`：端口 0 = 数据，端口 1 = 控制触发。
2. 它是**末端节点**：只负责把内容送出去，不再往下游传数据。

### 5. 放一个执行节点

1. **右键** → **开发节点（项目架构 · 功能块）** → **执行**。
2. **绑定文件**：`.exe` / `.bat` / `.cmd` / `.lnk`，或任何系统可以打开的文件。
3. **双击节点运行**（或连点两下播放键），即通过**系统默认方式**启动；执行节点**没有数据端子**，不接数据线。
4. **设图标与主题色**，方便在架构图旁边一眼定位启动入口。

![执行节点](img/mtnode-flow-10-flow.svg)
*图 2：执行节点绑定 .exe / .bat / .cmd / .lnk，双击即启动，无数据端子*

## 结果

- 一台机器上 ▶ 触发发送，另一台机器的接收节点收到同一通道的文本并继续跑下游。
- 画布上多了一个双击即启动的程序入口，适合放在开发节点的项目架构旁边。
- 通道、端口、协议都能逐节点覆盖，同一端口可以并行跑多个互不干扰的通道。

## 常见错误

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 接收端一直收不到消息 | 两端协议 / 端口 / 通道号不一致 | 逐项对齐 proto + port + channel，端口 0 时以 设置 · 网络 的默认值为准 |
| 点了发送没反应 | 控制端口没有触发 | 用控制线或 ▶ 触发 net_send 的控制端口 |
| 提示端口被占用 | 目标端口已被其它进程监听 | 换端口，或改 设置 · 网络 里的默认端口 |
| 双击执行节点没启动 | 绑定路径失效，或文件不是系统可打开的类型 | 重新选绑定文件，确认扩展名在 `.exe / .bat / .cmd / .lnk` 之内 |
| 想把数据从执行节点接出去 | 执行节点没有数据端子 | 用网络节点或保存节点承载数据流；执行节点只负责启动 |
| 在本页找不到媒体生成节点 | 媒体生成已并入独立页面 | 去 [出音乐 / 语音 / 视频](#media-gen) |
