# MCP 服务端（第三方接进来）

MTNode 平时是 **MCP 客户端**：它去连别人写的 MCP 服务器，给会话里的 Agent 加工具（见「智能能力是什么」）。这一页讲的是**反过来那一半** —— MTNode 自己开一个 MCP 服务端，让别的客户端（Claude Code、Cursor、自研 Agent）连进来操作这台机器上的 MTNode：读改画布、查数据库副本与 AI 事实库、看素材库、识图。

## 它在哪、怎么开

顶栏「插件」对话框右上那条路走不通 —— 入口在**设置 → 扩展能力 → 管理…**，切到「服务端」页。默认**已经开着**（首次启动即监听），页面里有：

- **总开关**：关掉 = 停止监听（端口消失，已经连着的客户端下一次调用会拿到明确错误）。
- **地址**：`http://127.0.0.1:<随机端口>/mcp`，只绑本机回环，局域网里别的机器连不上。
- **令牌**：一串随机 Bearer 令牌，客户端必须带上。可随时**重置**（重置后已配置的客户端要重新复制一次配置片段）。
- **stdio 客户端配置片段**：Claude Code / Cursor 这类客户端要用的那一段 JSON，一键复制。
- **自检**：不接任何外部客户端，自己走一遍「初始化 → 列工具 → 真读一次画布」，绿了就说明这条链路通。
- **最近调用（审计）**：谁、什么时候、调了哪个工具、动了哪张画布、成功还是失败。日志落在数据目录的 `mcp-audit/`（按天轮转，保留 7 天）。**数据目录**默认是 `%APPDATA%\pipeline-console\pipeline-console`（端口与令牌也记录在它下面的 `mcp-server.json`）；在设置里改过「配置数据目录」的话，就是那个目录。
- **原始 JSON-RPC 抓包**：排障用，需显式打开，只留最近 200 条、只在内存里。

## 怎么接到客户端上

两种传输都给，同一个服务端：

**① stdio（多数本地客户端用这种）** —— 把这段合并进客户端的 MCP 配置：

```json
{
  "mcpServers": {
    "mtnode": {
      "command": "<MTNode 安装目录>\\MTNodeAIO.exe",
      "args": ["<MTNode 安装目录>\\resources\\mcp-stdio.js"],
      "env": { "ELECTRON_RUN_AS_NODE": "1" }
    }
  }
}
```

面板上的「复制配置片段」复制出来的就是这个（两处路径都已经填好，`env` 那一段也一起给了）。`command` 用的是 MTNode 自己的可执行文件 —— 它是 Electron 二进制，**必须连 `env` 里的 `ELECTRON_RUN_AS_NODE=1` 一起给**才会以 Node 模式跑这个桥脚本；漏了这条它会当主程序再开一个 MTNode 实例、一条 JSON-RPC 都不吐（第三方客户端表现为一直连不上）。这么配**不用另外装 Node**；你也想用系统 `node`，就把 `command` 换成 `node` 并**把 `env` 那一段删掉**（要求 Node ≥ 18）。桥脚本会自己从数据目录读端口与令牌，所以你**不用手填地址，也不用把令牌粘进配置文件**。MTNode 没开着时，客户端会看到一句「连不上 MTNode MCP 服务端，请打开 MTNode 后重试」。

**② 本机 HTTP** —— 自己写客户端或远程工具时用：`POST http://127.0.0.1:<端口>/mcp`，头带 `Authorization: Bearer <令牌>`，体是 MCP 的 JSON-RPC（`initialize` / `tools/list` / `tools/call` / `resources/list` / `resources/read` / `prompts/list` / `prompts/get`）。

## 第三方能做什么

工具名与参数和 MTNode 自家 Agent **完全同名同义**（`mtnode_canvas_get`、`mtnode_canvas_edit`、`mtnode_app`、`mtnode_db`、`mtnode_facts`、`lt_state`、`mtnode_assets`、`mtnode_vision`），所以现有那些节点指南与技能文档对第三方一样适用。

另有一个只在 MCP 这一侧提供的工具 **`mtnode_gui`**：它让第三方客户端**真的操作 MTNode 的窗口** —— 认元素、点按钮、填输入框、按键、滚动、等某个文字出现、读窗口里的文字与结构，以及给任意一只窗（主窗 / 插件安装窗 / 各插件控制台）**拍一张静帧**存成 PNG。用途例如：无人值守地走一遍「打开插件对话框 → 开始安装 → 等安装完成 → 在控制台点测试生成 → 截图留证」。

它点的是页面里真实存在的元素（不是屏幕坐标），所以窗口不必在最前面；反过来，**原生菜单、系统文件选择框、托盘菜单它够不着**（那些不在页面里，会明确报错），被最小化的窗口也拍不到图。密码这类凭据它不会替你输入 —— 需要凭据的步骤仍由人在窗口里完成。

除工具之外还开了两类 MCP 能力：

- **资源（resources）**：画布清单、画布快照、单节点正文、内置技能正文 —— 客户端可以先「浏览」再动手。
- **提示词（prompts）**：三份模板 —— 接手画布、建工作流、审阅画布；把 MTNode 自己的硬规则（先读图再改、批次安全）直接写进模板。

## 三条硬规矩

1. **改画布前先读图**：`mtnode_canvas_get` 的回执里带 `contentHash`，把它作为 `baseHash` 原样传给 `mtnode_canvas_edit`。哈希对不上（期间有人改过这张图）→ 本次修改被拒，重新读一遍再改。这条是为了防「两个客户端互相盖掉」。
2. **一次只跑一笔写**：第三方连接之间、以及第三方与你自己之间，画布写是排队串行的；读是并发的。
3. **默认操作当前画布**：要动别的画布就带 `canvas` 参数（画布 id 或精确名称）。一次连接可以操作本机全部画布。

## 权限与审计

- **首次连接授权后即可全量读写**：服务端开着、令牌对，就能改画布 —— 不再逐笔弹确认框（否则第三方自动化寸步难行）。想收回：关掉总开关，或重置令牌。
- 你**自己的**会话、助手、智能节点完全不受影响：它们的确认框、审批档、许可面板照旧。
- 每一次调用（含被拒的）都写进 `mcp-audit/`：时间、会话、客户端标识、工具、画布、耗时、成功/失败、错误原因、参数摘要。

## 有哪些事第三方做不到（如实说明）

- **长任务不能替人点「确认交付」**：MCP 能读长任务的定义与运行状态、能读改本轮共享状态，但「启用运行 / 推进 / 审批」由你在条带上操作。
- **媒体生成不是单独的工具**：文生图 / 音乐 / 语音 / 视频都是画布**节点**，第三方能做的是在画布上建好这些节点并连线；要让它们真跑起来，用 `mtnode_gui` 点那个「运行」按钮（与自家 Agent 的口径一致）。
- **`mtnode_gui` 够不着的地方**：原生菜单、系统文件选择对话框、托盘菜单（不在页面里）；最小化 / 隐藏的窗口拍不到图；密码与其它凭据不会替你输入。
- **dsh 引擎自带的通用工具**（文件读写、命令执行、联网搜索）**不开**给第三方：那些能力客户端自己就有，不必经过 MTNode。
- **会话自己的浏览器控制面**（13 个 `browser_*` 工具）**不开**：那是你的浏览器会话，不交给外部客户端。

## 排障

| 现象 | 先看哪里 |
| --- | --- |
| 客户端连不上 | 面板里总开关是否「已监听」；客户端配置里的脚本路径是否存在（分两处：`command` 指向应用可执行文件或 `node`，`args` 指向 `mcp-stdio.js`）；用应用可执行文件时 `env` 里必须有 `ELECTRON_RUN_AS_NODE=1`（漏了它会再开一个 MTNode、不吐 JSON-RPC），用系统 Node 时把 `env` 去掉并 `node --version` ≥ 18 |
| 客户端报「找不到 MTNode MCP 服务端的运行信息」 | 先看这句报错里**逐个候选探活的结果**（列了每个候选的路径、端口与连不上原因）：MTNode 没开着；或数据目录不是默认那个（默认就在 `%APPDATA%\pipeline-console\pipeline-console`，设置在「配置数据目录」里改过就是它指向的那个目录）。仍不一致：给客户端加环境变量 `MTNODE_DATA_DIR`，或直接给 `MTNODE_MCP_URL` + `MTNODE_MCP_TOKEN` |
| 调用返回 401 | 令牌不对（重置过？）—— 重新复制配置片段 |
| 调用返回「画布已被改动」 | 有人在你读图之后改过这张图：重新 `mtnode_canvas_get` 再改 |
| 调用**卡住不返回**（一直转圈到超时） | MTNode 主窗口是不是被关掉了（执行在渲染层，窗口不在就没人执行）；若是必现，把这条现象连同当时调用的工具名记下来报给我们（渲染层没回执属于缺陷） |
| 想看清客户端到底发了什么 | 打开「原始 JSON-RPC 抓包」再复现一次 |

接口的机器可读契约在仓库里：`mcp-tools.json`（由 `node scripts/build-mcp-contract.mjs` 从 `dsh/gateway/*-plugin.mjs` 生成，禁止手改）；接入指南与各客户端配置样例见 `guides/mcp-server.md`。
