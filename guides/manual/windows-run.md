# Windows 提示「未识别应用」怎么办

> 一句话目标：双击 MTNode 时弹出「Windows 已保护你的电脑 / 发布者未知」时，知道为什么、按哪两下、以及开发者该怎么一次性少弹。

## 你会看到什么

第一次双击从网上下载 / 刚从源码编译出来的 `MTNodeAIO.exe`（或安装包）时，Windows 可能弹：

> **Windows 已保护你的电脑**
> Microsoft Defender SmartScreen 阻止了无法识别的应用启动。运行此应用可能会导致你的电脑存在风险。
> 应用: MTNodeAIO.exe　发行者: 发布者未知

这不是「检测到病毒」，也不是安装包坏了 —— 而是**这个 exe 还没有代码签名证书，Windows 不认识它**。

## 三步放行（普通用户）

1. 点弹窗里的 **「更多信息」**（有的版本是蓝色小字链接）。
2. 下面出现 **「仍要运行」** 按钮，点它。
3. 应用正常启动。**同一个文件只需放行一次**，之后不再提示。

如果只有「不运行」、没有「更多信息」：说明这台机器（或公司的安全策略）禁止覆盖，请联系你的管理员，或让开发者提供已签名 / 商店版本的安装包。

## 为什么旧版不弹、新版又弹了

SmartScreen 认的是**文件哈希的信誉**，不是应用名字：

- 已发布很久的那份 exe 被很多人下载、运行过，攒出了信誉 → 静默通过；
- **每次重新编译 / 每次新版本，都是一枚全新哈希的未签名二进制，信誉从零** → 第一次双击就弹。

所以这不是「最近几次源码更新把它弄坏了」，而是每个新产物的必经之路，直到项目上了代码签名或商店包。

## 开发者：让每次编译后少弹一次

仓库里已经带了处置脚本 `scripts/windows-unblock.mjs`，**编译链会自动调用它**，它做两件事：

| 步骤 | 做什么 | 要管理员吗 |
| --- | --- | --- |
| 1 | 删掉构建产物的 `Zone.Identifier`（Mark-of-the-Web 下载标记） | 不需要 |
| 2 | 把构建输出目录（`dist\win-unpacked`）加进 Microsoft Defender 排除项 | **需要**，会弹一次 UAC |

- 取消那次 UAC 没有任何副作用：只是第 2 步没做，产物照旧可用（第 1 步已经就位）。
- 排除项**只加这一条路径**，实时保护 / 云保护照旧开着，也不会降低其它目录的安全级别。
- 手动重跑（编译已经完成时）：

  ```
  scripts\rebuild-unblock.cmd
  ```

- 只想跳过这一步：`node E:\dev\tools\build.js --dir --no-unblock`
- 每次编译的结论留痕在 `dist\unblock.log`（哪一步做了、是否被取消、加了哪些路径）。

### 给下载用户的口径

发布页 / 说明书里请写明上面「三步放行」，并说明原因是**未签名**。要让所有用户都不需要这一步，唯一彻底的做法是给发布包加代码签名（或改走 Microsoft Store 的 MSIX 包，商店包不受 SmartScreen 拦）。
