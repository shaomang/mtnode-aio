# MOSS-Music：听懂一首歌

> 一句话目标：把一首歌（或一段带音轨的视频）丢给本机模型，拿回**逐句歌词与时间戳、曲风 / 情绪 / 配器、曲式与和弦、调式与速度**，
> 还能自由追问。全程不出本机。

MOSS-Music 用的是 OpenMOSS 的 **8B 音乐理解 Instruct 模型**：直接给答案（快）。Thinking 档已移除，只保留 Instruct。
它和「音乐生成」是两件事：**本节点只分析、不写歌**；要出歌用 Minimax Music 3 或 YuE2。

> 插件目前标着「**插件测试中**」：安装链比较长（要下 8B 权重），有可能失败；失败时用安装窗里的「交给 mtnode 会话修复」最省事。

## 一、装（一次就够）

1. 顶栏「**插件**」→「**MOSS-Music 本地音乐理解**」→「**安装（国内镜像）**」。
2. 在安装窗里选一个目录（默认在插件根目录下）。**别选盘根、系统目录或 MTNode 自己的安装目录**，会被拒绝。
3. 等 10 步跑完：磁盘检查 → Python 3.12（uv）→ CUDA torch → 推理依赖 → 官方源码 → 模型权重 → 文件校验 → 便携 ffmpeg → `.env` → 冒烟。
   权重约 **18GB**，加环境约 **12GB**，**建议预留 ≥60GB**，首次安装视网速要一段时间。
4. 装完卡片进入已装态（主按钮变「重装」、出现「启用」）。**不用**手工启动：节点点 ▶ 或卡片「启用」会静默拉起后端（端口 **8790**）。

装的过程中可以「关闭窗口」让它在后台继续；真要停就点「**取消安装**」；失败点「**重试**」会复用已下好的源码 / 权重分片。

**硬件门槛**：必须 NVIDIA 显卡。`int8`（默认）要 **16GB** 显存，`int4` 要 **12GB**（全精度档已移除）；
驱动太旧（cu128 要求驱动 ≥525，建议 550+）、显存或磁盘不够时不要硬装。
显存明显不够且没装过时，插件默认不出现在列表里 —— 需要找回就打勾插件窗底部的「**显示不支持的插件**」。

装不上时安装窗会停在失败那一步并给出中文原因，同一只窗里的「**交给 mtnode 会话修复**」会带上日志开一条会话，
按 `moss-music-install` 技能的【自我修复】处理；磁盘不够、没 N 卡、驱动太旧、目录不合法这几类只报告、不自动修。

## 二、用

画布右键 →「**处理节点**」→「**音频生成**」→「**MOSS-Music 音乐理解**」。

### 接线

```
音频输入 / 视频输入 ──→ 端子 0（音频 / 视频）
文本（可选追问）   ──→ 端子 1（自由提问）
控制节点           ──→ 端子 2（控制输入，触发分析）

节点 → 端子 0 结果文本 · 端子 1 JSON · 端子 2 产物路径（md）
```

- 端子 0 必接：接**音频**（wav / mp3 / flac / m4a…）或**带音轨的视频**，视频会先抽音轨。
- 端子 1 可以不接：节点上选了「任务预设」就按预设提问；接了文本或节点里写了字，就按你写的问。
- 端子 2 只是触发，不传内容。

### 选任务

节点 body 的「**任务预设**」：

| 预设 | 适合 |
| --- | --- |
| 完整分析 | 第一次听一首歌，想要歌词 + 曲式 + 和弦 + 情绪的全套 |
| 整曲描述 | 只要一段概述（风格 / 情绪 / 乐器 / 段落） |
| 时间戳歌词 | 只要逐句歌词与 `mm:ss` |
| 曲式与和弦 | 扒结构、调性、速度、和弦进行 |
| 情绪标签 | 做检索 / 配乐选曲，要 3~5 个标签 |

「**自由提问**」优先于预设，例：`副歌的和弦进行是什么？`、`第 2 分钟发生了什么？`、`这段适合什么场景？`

### 模型与显存

- **模型固定 Instruct**（Thinking 档已移除；老工作流里存着 thinking 的节点会自动按 Instruct 跑）。
- **量化档**：`int8`（16G，默认）· `int4`（12G）。显存不够就降档；全精度档已移除，只剩这两档。
- 同一时刻只驻留一个模型；全局同一时刻只跑**一个**音视频任务（与音乐 / 语音 / 视频节点共用一把锁），
  被占用时状态行会写清是谁在跑。

### 长音频

默认关闭。**超过 5 分钟**的整曲建议勾上「长音频」：按 **3 分钟一段、相邻段重叠 5 秒**切片，逐段分析后把时间戳拼回原曲并去重。
更慢，但不会因为太长被截断；单次分析最长 **45 分钟**。

### 结果在哪

每次分析写三份文件（同一个文件名主干）：

- **md**：元信息 + 提问 + 回答 + 时间轴；
- **json**：结构化结果（模型 / 量化 / 时长 / 分段 / 时间戳）；
- **srt**：时间戳字幕，可直接当草稿改。

产物落在**应用托管的画布资产目录**，节点没有「输出路径」参数；要归档就把「**产物路径**」端子给出的 md 路径交给下游取用 / 复制。
模型没给逐句时间戳时不会伪造对齐：按字数摊到句子上，JSON 标 `estimatedTimestamps: true`，md / srt 也会注明「估算」。

## 三、控制台

插件卡片「**控制台**」里能做的事：

- 看服务状态（服务关闭 / 运行中 / 就绪）与当前装载的模型；
- **启动并装载 / 停止服务**、切量化档；
- 看显卡与显存读数；
- 选一段音频**试听**，直接写自由提问跑一次「开始理解」，看时间戳表与产物路径；
- 看实时日志尾部（最近 2MB）。

**后端是有意常驻的**：关掉 MTNode 不会停它，下次启动直接复用；要停就在控制台点「停止服务」，或自己结束进程。

画布节点上的 **■** 是「终止这一次分析」：先让后端在分块边界停下（3 秒不退就结束进程），并把模型一起卸掉、显存立刻还回来；下次点 ▶ 会自动重新装载。

## 四、常见问题

| 现象 | 多半是 | 怎么办 |
| --- | --- | --- |
| 节点顶部「插件未安装」 | 插件没装 / 安装目录被移动 | 插件卡片里安装或「补装要件」 |
| 点 ▶ 报「没有音频 / 视频路径」 | 端子 0 没接 | 接音频 / 视频输入节点的输出 |
| 启动很久或失败 | 首次装载 18GB 权重；或显存不够 | 等 30~90 秒；看控制台日志；降 `int8` / `int4` |
| `vram_low` | 当前量化档超出显存 | 降档；int8 需 16G，int4 需 12G |
| `load_failed` / `load_timeout` | 权重残缺或显存不足 | 先降档；仍失败就重跑安装补齐权重（已完成的会复用） |
| `generate_timeout` | 音频太长 / 显存不足 | 开长音频分块、降档，或换短音频 |
| 长音频切片报 ffmpeg 错 | 安装时 ffmpeg 没下到（那一步允许跳过） | 重跑安装补 ffmpeg，或把 `ffmpeg.exe` 放进 `<安装目录>\tools\ffmpeg\` |
| 「全局锁被占用」 | 正在跑音乐 / 语音 / 视频任务 | 等它结束，或先去那边停止 |
| 切量化档很慢 | 正常：卸载 + 重新装载 18GB 权重 | 等 30~90 秒，别连点 |
| 权重想换盘 / 复用 | 换安装目录等于换一份完整后端 | 原目录重装会复用已完成的权重；换目录才会重新下 |

## 五、边界与数据

- 全部本机推理，不上传音频；产物默认落在应用数据目录，需要归档就在下游按产物路径取用 / 复制。
- 移除 / 停用插件**不删**已生成的 md / json / srt，也**不删**安装目录里的权重与环境——都要你自己清理；移除前先到控制台停掉常驻后端。
- 别把安装目录设在盘根、系统目录或 MTNode 应用目录；数据不允许写进应用文件夹。
- 上游源码 Apache-2.0；模型权重许可以官方模型卡为准，商用前自行核对。
