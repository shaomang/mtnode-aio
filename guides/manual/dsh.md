# 智能能力是什么

> 一句话目标：一次 AI 协作就是一个会话——先认会话是什么，再看它从哪来。

## 会话总览

会话 = 一次和 AI 的连续协作。侧栏助手、智能节点、开发节点按钮背后，跑的都是会话。

三条要点：

1. **会话有状态**：它记得之前说过什么，所以「接着改」比重新描述一遍更省事，但冗余的会话可能反而会浪费 Token 和时间。
2. **会话有开关**：模型、预设档、思考强度、工具许可，可根据需求进行配置。
3. **会话可以读写文件以及上网搜索**：会话可以拥有读写文件的权限，所以可以实现强大的功能，但同时也存在失误造成严重后果的风险。

画布中的「示例 · 智能任务（可运行）」就是一个会话入口：改一改任务描述，点 ▶ 就能看到它自己读文件、写文件、只回一个路径。

## 会话从哪来

### 四个入口

- **全局助手（✦）**：能看并改你眼前的画布——一句话搭工作流、整理排版、新建节点。助手主要用于画布方面的操作，一般会禁止对本地文件进行编辑。
- **智能节点（智能任务节点、开了智能模式的文字处理节点）**：每次运行在内部展开一个会话，适合「读文件 + 多步 + 写文件」的活，不会超出画布项目文件夹范畴。
- **开发节点的开发 / 细化**：在块绑定的新会话里运行，只服务于该块所属的项目文件夹，但允许读取项目外的内容，适用于绝大部分的开发任务。

### 怎么选

- 一次问答、结果要落盘 → 普通文字处理节点。
- 通过画布处理较为复杂的任务，并自动读文件写文件 → 智能节点。
- 要改画布本身 → 右侧栏助手。
- 程序、软件开发 → 直接使用会话（与 Codex 使用方式相近），或点击开发节点的「开发」按钮生成会话。

## 子代理（委派）：深度与开关

会话干活时可以「派活」给**子代理**：子代理有自己独立的上下文，跑完只把结论交回来，主会话不会被过程细节塞满。派活次数失控会成倍烧 Token，所以这里默认收得比较紧。

- **在哪设**：设置 → 智能能力（DeepSeek Harness / dsh）→ 「子代理（委派）」。
- **嵌套深度**：`0 · 禁止委派` / `1 · 只允许一层（默认）` / `2 · 允许两层`。它只约束「子代理再派子代理」，**不影响你自己发起的那一次委派**；默认只给一层，避免层层派活。
- **三个开关**：允许子代理委派（总开关，关掉后模型侧连委派工具都看不到）、允许后台并行委派（关掉后子代理只在前台同步跑，一次一个）、允许 fork 型子代理（复制当前上下文另起一个子会话）。
- **生效时机**：这几项写进 dsh 组合文件（`cordis.yml` 里 subagent* 那 8 行），保存后对**下一个新会话**生效；正在跑的会话沿用原设置（与权限预设、思考强度同一口径）。

> 排障：如果「设置里选了 0」但模型仍在派活，多半是当前会话早已起机 —— 新开一个会话即可。实际写入记录在数据目录的 `dsh-home\dsh.log`，搜 `subagent policy applied:` 一行能看到当前生效值。
