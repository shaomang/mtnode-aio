# 智能能力是什么

> 一句话目标：搞清「智能模式」到底能做什么、不能做什么，以及预设档与思考强度怎么选。

![智能引擎能力与边界](img/mtnode-agent-01-ui.svg)
*图 1：智能体在**工作区**里读 / 写 / 编辑文件、联网搜索、执行命令、派子代理，但它**不改动画布***

![Agent 预设](img/mtnode-agent-06-ui.svg)
*图 2：四处都能选预设——智能会话的模型菜单、右侧助手栏、智能节点 ⚙ 设置、设置 · 智能能力*

## 目标

读完后你能判断一件事该用普通处理节点还是智能节点，知道智能体在哪些地方被硬拦，并能按任务性质选对预设与思考强度。

## 前置条件

- 一个带 API Key 的**文本服务商**（见 [配置服务商与 API](#providers)）。智能任务、智能会话、文本处理的「🐋 智能」都走这条引擎。
- 智能体运行时随应用自带，**不用另装 Node**。
- 打算让它写文件时，先确认当前画布的 [工作目录](#workspace) 正确。

## 步骤

1. **认出入口**：智能任务节点、智能会话（顶栏视图）、文本处理节点开启「🐋 智能」后，都是同一套引擎。
2. **搞清楚它能干什么**：读 / 写 / 编辑工作区文件、联网搜索与抓取网页、在工作区执行命令、派子代理、使用已装技能与已连接的 MCP 工具、识图（`mtnode_vision`）、使用连入的 `@` 引用、批量 / 聚合与所选模型。它**不能**读取或编辑画布、创建节点与连线、改工作流——要搭图请用智能会话或全局助手。
3. **看过程**：运行中显示「◉ 思考中」，可展开思考与 **🔧 工具调用**。智能模式按任务完成计费，一次任务可能多次调用模型。
4. **选预设**（见下表）：在智能会话的模型菜单、右侧助手栏、智能节点 **⚙ 设置** 窗口、**设置 · 智能能力 · Agent 预设** 四处任一处切换。
5. **选思考强度**：界面上只有「标准 / 最强」两档，选什么就按什么跑——预设档**不会**再替你改写思考强度。
6. **核对权限**：智能体的实际授权只由运行时的工具许可决定，见 [审批与权限](#approvals)。

## Agent 预设：换一档说话方式

| 预设 | 干什么用 |
| --- | --- |
| **极简模式**（默认） | 省事档：最少步骤、最少废话，直接给结果 |
| **标准模式** | 通用档：画布编排、文件与内容任务兼顾，解释比较完整 |
| **思维精简** | **压缩思考表达**档：思考压成符号骨架，最省 token（思考强度仍按你的设置走，本档不再自动降档） |
| **PTC 模式** | 工程档：写代码 / 改文件 / 跑命令；先读再改，改完说明改动与验证方式 |
| **创造模式** | Cordis 插件开发档：遵循 Service / ctx.effect / 类型化事件的约定 |

> **默认档 = 极简模式**：新开的智能会话、新建的智能节点、以及设置里没动过这一项时，走的就是它。想要解释更完整的通用档，就在上述四处任一处切到**标准模式**（已经保存过的旧配置仍按原先选的档位走，不会被悄悄改写）。

### 思维精简为什么省 token

智能任务按模型输出计费，而**推理内容（思考）本身也是输出**——一个请求动辄上千 token 的内心独白，最后交付只有几行。思维精简从三头同时收：**先结构化**（动手前用一行把任务压成 `GOAL/GIVEN/DECIDE`）、**固定骨架**（思考只允许 `GOAL` → `APPROACH` → `EDGE` → `DO`，不许新增小节、不许复述原话与工具输出）、**剪掉废话**（凡不改变下一步决策的句子一律不写，缺事实就去读文件 / 搜索 / 查库）。

省下来的是**思考的表达量**：这一档只压思考的写法，**不动思考强度**。**交付不受影响**——工具授权仍由运行时的工具许可决定，输出端子与保存节点拿到的仍是完整正文。

> 本档早期叫「草图模式」（内部 id `sketch`），现统一为**思维精简**（内部 id `lean`）。旧会话与智能节点里存的 `sketch` 会自动归一到 `lean`，无需重设。

### 代价

- **可能少想一步**：骨架之外的分支不会被展开，越需要反复权衡的判断题越容易漏细节。
- **需要深推理时**：把思考强度选成 **最强**，或切回**标准模式 / PTC 模式**。
- **界面写的就是实际跑的**：模型 chip 与思考强度项只显示你选的那一档，不再有「名义档 / 生效档」两套说法。

## 运行中：思考与输出分开显示

一次运行按**发生顺序**分段显示，三类段各有各的样子：

- **◉ 思考 · N 字**：模型内部推理（reasoning），默认折叠；N **只统计思考的字数**，不含工具与正文。
- **正文**：模型真说出来的话，正常字号、Markdown 渲染，一段一块——中间步骤说的话也以正文出现。
- **🔧 工具**：调用轨迹就近插在它发生的位置，点开看参数与结果；出错以 **⚠** 附在正文里。

每调用一次工具、或进入新的一步推理（turn / step）都自动另起一段。智能任务节点（含会话模式）、智能会话、右侧全局助手用的是**同一套分段**；节点上的「思考中」大窗上半是思考、下半是输出。**下游数据不受影响**：输出端子给下游、以及存进保存节点的，仍是完整正文。

## 交流语言（Agent 口味）

顶栏 **中 / EN** 选定界面语言后，这份语言会作为「口味」随每次智能运行一起下发：**用该语言交流，并期望 agent 用该语言回答**——提问、计划、进度说明、最终回答都跟随界面语言，派生的子任务与功能块绑定会话同样沿用。设置 · 智能能力 区块会显示当前用的是哪种语言。

口味只约束**交流**。代码、路径、命令与 API 字段名保持原文；事实库记录、表格单元格与写回文件的正文沿用资料原本的语言，不会因为切换界面语言而被翻译。用户在一轮对话里明确指定别的语言时，以用户为准。

## 复杂任务先出计划（确认后逐项执行）

智能会话与智能任务节点接到要求时会先判断复杂度：说清楚了或很简单的直接开工；判为复杂任务则**本轮不做任何改动**，只回一份计划。应用随后响起提示音并弹出「计划确认」窗口——可拉伸、可 ⤢ 最大化，一条任务三列（标题 / 详情 / 执行模型），可增删、上下排序、给同名「并行组」的任务并发跑；确认后按清单逐项执行，每项单独一轮、用它自己选定的模型。会话底部的「计划」面板是这份清单的持久视图，中断后可「▶ 继续执行」。

**计划没弹出？应用会自动补一次。** 模型偶尔会在这一步生成失误（标记被写坏、漏闭合标记，或把 JSON 直接写在正文里）。每轮收尾时应用会做一次**关键词检测**：只有这一轮确实被要求交计划清单、且正文里又出现计划块标记或 `goal` + `tasks` 字段特征（两者同现才算）时，才判定为「漏弹」，随即自动回发一条纠错指令要求重新输出一次。边界很克制：一个用户轮次最多补一次；这一轮被你终止、或队列里还有你自己排的消息时一律不补。

## 出错自动重发 · 停止就是立即停止

智能运行失败（最常见是 429 限流、5xx、网络抖动）不再直接跳过：**等 5 秒原样重发本轮**，最多 5 次，仍失败才判失败。等待期间这一轮仍算「在跑」——计划不往下走、新输入照旧排队、运行队列仍挂着它。重发默认**优先从中断处续写**（沿用本轮引擎会话与已写出的正文，不重烧 token），续不上才整轮重发；整轮重发会先清掉上一轮残文，不会叠字。

**按 ■ 停止就是立即停止，绝不进入重发。** 会话、智能任务节点、全局助手、运行队列行、提问卡上的「稍后 / 中断任务」以及「全部终止」走同一道终止判定：这一轮一旦被判死，剩下的重发次数当场作废。终止按 runKey 精确生效——停掉一条会话不会牵连另一条并行会话的重发。

## 结果

你能说出「这件事该不该用智能节点」，能在四处任一位置把预设切到合适档位，并能在运行中读懂思考 / 正文 / 工具三段的分工。

## 常见错误

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 智能节点说「需要先关掉与画布无关开关」 | 会话开了「与画布无关」，本轮不注册画布工具 | 关掉该开关后重跑，见 [智能任务与智能会话](#agent-nodes) |
| 让它搭工作流却没反应 | 智能**节点**不改画布 | 改用智能会话或右侧全局助手 |
| 输出被压在「思考」里看不见 | 是模型的推理段落，本就折叠 | 展开「◉ 思考」查看；正文段才是交付 |
| 结果重复出现 / 像在叠字 | 整轮重发先清了残文，一般不会叠 | 若仍异常，停止后重跑一项 |
| 花的 token 比预期多 | 用了标准档或长上下文 | 长会话试 **思维精简**，并考虑开「与画布无关」省前缀 |
| 它把文件写到了别处 | 工作目录不对 | 顶栏设置当前画布的工作目录，见 [工作目录与存档](#workspace) |
