# 智能能力是什么

> 一句话目标：一次 AI 协作就是一个会话——先认会话是什么，再看它从哪来。

## 会话总览

会话 = 一次和 AI 的连续协作。侧栏助手、智能节点、开发节点按钮背后，跑的都是会话。

三条要点：

1. **会话有状态**：它记得之前说过什么，所以「接着改」比重新描述一遍更省事，但冗余的会话可能反而会浪费 Token 和时间。
2. **会话有开关**：模型、预设档、思考强度、工具许可，可根据需求进行配置。
3. **会话可以读写文件以及上网搜索**：会话可以拥有读写文件的权限，所以可以实现强大的功能，但同时也存在失误造成严重后果的风险。

画布中的「示例 · 智能任务（可运行）」就是一个会话入口：改一改任务描述，点 ▶ 就能看到它自己读文件、写文件、只回一个路径。

### 预设档

会话与智能节点共用的五个档位（默认极简模式；**预设只管人设与工具面，不改思考强度** ——
思考档只由界面上的「思考强度」这一项决定）：

| 预设档 | 定位 |
| --- | --- |
| **极简模式（默认）** | 省事档：最少步骤、最少废话，直接给结果 |
| **标准模式** | 通用档：画布编排、文件与内容任务兼顾 |
| **思维精简** | 需要展开想一想的活：保留推理结构，但压掉复述与散文 |
| **PTC 模式** | 多步串行编排：把流程拆成可核对的下一步 |
| **创造模式** | 开放式写作 / 发散：允许更大篇幅的发挥 |

「思维精简」这一档**不动思考强度**（它只管表达纪律：保留推理结构、压掉复述与散文）；
早些版本里「选思维精简就把思考档自动压到低」的那套自动压档**现已取消**，思考档只认界面上
「思考强度」这一项。

## 会话从哪来

### 四个入口

- **全局助手（✦）**：能看并改你眼前的画布——一句话搭工作流、整理排版、新建节点。助手主要用于画布方面的操作，一般会禁止对本地文件进行编辑。
- **智能节点（智能任务节点、开了智能模式的文字处理节点）**：每次运行在内部展开一个会话，适合「读文件 + 多步 + 写文件」的活，不会超出画布项目文件夹范畴。
- **开发节点的开发 / 细化**：在块绑定的新会话里运行，只服务于该块所属的项目文件夹，但允许读取项目外的内容，适用于绝大部分的开发任务。

### 怎么选

- 一次问答、结果要落盘 → 普通文字处理节点。
- 通过画布处理较为复杂的任务，并自动读文件写文件 → 智能节点。
- 要改画布本身 → 右侧栏助手。
- 程序、软件开发 → 直接使用会话（与 Codex 使用方式相近），或点击开发节点的「开发」按钮生成会话。

## 子代理（委派）：深度与开关

会话干活时可以「派活」给**子代理**：子代理有自己独立的上下文，跑完只把结论交回来，主会话不会被过程细节塞满。派活次数失控会成倍烧 Token，所以这里默认收得比较紧。

- **在哪设**：设置 → 智能能力（DeepSeek Harness / dsh）→ 「子代理（委派）」。
- **嵌套深度**：`0 · 禁止委派` / `1 · 只允许一层（默认）` / `2 · 允许两层`。它只约束「子代理再派子代理」，**不影响你自己发起的那一次委派**；默认只给一层，避免层层派活。
- **三个开关**：允许子代理委派（总开关，关掉后模型侧连委派工具都看不到）、允许后台并行委派（关掉后子代理只在前台同步跑，一次一个）、允许 fork 型子代理（复制当前上下文另起一个子会话）。
- **生效时机**：这几项写进 dsh 组合文件（`cordis.yml` 里 subagent* 那 8 行），保存后对**下一个新会话**生效；正在跑的会话沿用原设置（与权限预设、思考强度同一口径）。

> 排障：如果「设置里选了 0」但模型仍在派活，多半是当前会话早已起机 —— 新开一个会话即可。实际写入记录在数据目录的 `dsh-home\dsh.log`，搜 `subagent policy applied:` 一行能看到当前生效值。

## 会话视图里的标记（对着 DeepSeek 桌面端看齐）

会话区按 dsh 0.2 桌面端（DSH Desktop 内置的那套 Web 会话界面）的读法重做过一轮，
记号与它们的意思如下：

- **工具卡片**：一行读成「图标 + 中文标题 · 这一步干了什么」。标题按工具族固定
  （读取 / 写入 / 编辑 / 运行命令 / 搜索文件内容 / 查找文件 / 网页搜索 / 网页获取…），
  原始工具名留在 hover 与 `data-tool-name` 上。
  - **准备态**：参数还在流进来时先给一行「正在准备内容 N KB」（N 是参数字符数折算，不是文件体积）；
  - **运行中**：整行有一道从左到右的扫光，结果回来即停；
  - **失败 / 停止**：行内一句失败摘要（错误名 + 码 + 一句正文）或「已停止」，展开体里仍有全文。
- **文件改动 diff**：`write` / `edit` 这类调用会把「改前 → 改后」按行算成 `+` / `-` 块
  （超出 9 行先折叠，点「… 其余 N 行」就地展开）。改动数据来自调用参数本身，
  **不额外读盘**；超过 300 KB 的正文不画 diff（只保留原有参数 / 结果视图）。
- **上下文注入行**：只在**上下文真的变了**（工具被加入 / 移除）时留一行；
  普通上下文注入与系统提示按上游口径不显示。
- **轮次**：工具调用**不收纳** —— 思考 / 工具 / 上下文注入这些过程行一律按发生顺序逐段摊开，
  与它们的时间线位置一一对应（曾经折成一行「✓ 已完成 · N 次工具调用」，那样会让工具离开自己的位置）。
  复制 / 保存这类动作行收进**轮次页脚**（最新一轮常显，历史轮鼠标移到那一轮才现）。
- **逐项时刻**：每一项（思考 / 正文 / 上下文注入 / 工具调用）**左侧**都有一条恒显的时刻
  （精确到秒，等宽小字）；工具项再带上这次调用的耗时（`09:12:31 · 1.2s`）。
  时刻取自这一项**自己的**真实记录：工具调用的发起 / 结果回来时刻，其余段是它开始那一刻；
  老存档里没有段时刻的项会回落显示所属消息的时刻，并用点线下划线标出来（hover 有说明）。
  时刻本身**不在任何底色 / 竖条里面**：思考的灰轨与工具的青色竖条、淡青底都从时刻栏**右侧**
  才开始（颜色不把时间裹进去），四种项的竖条左缘与时刻右缘间距一致。
  整条消息左侧另有一条「整条消息」的时刻（用户消息只有这一条）。
- **对话 / 轨迹**：会话头部两枚标签。切到「轨迹」就把主区换成事件记录表：
  上方一条**整个会话**的时间轴（刻度按真实起止时间等距摊开，固定 3 条轨、一次调用一个色块，
  方块有 12px 高、点得中；轴脚下是本视窗读数与一族一色的工具图例），
  当前滚动视窗对应的那段时间另用一条半透明**滑窗带**标在轴上，随滚动实时移动；
  **按住这条滑窗带可以拖动平移时间**：左右拖它，视窗就平移到那一段时间（下方列表随之滚到
  对应位置），拖的只是「看哪一段」——**窗长不变**，带子不会被拖长 / 拖短；
  **在轴上滚滚轮可以横向拉伸**这条轴（以指针下的时刻为锚拉近 / 拉远，指针附近那一段变化最大：
  刻度、色块、滑窗带一起缩，读数末尾会显示当前倍数），**双击这根轴**或按 **Esc** 回到全轴，
  换会话也自动回到全轴；轴上「还在跑」的色块是**静态**的族色描边 + 一层柔光（不闪烁）；
  行按段型上色，**行的色块与左轨与对话一致**：左轨 **2px** + 行的**右侧圆角** + 对话同款淡底
  （思考灰轨 / 工具青轨 / 正文无轨 / 失败红轨），
  行内读数栏的 token 用「输入蓝（↑）· 输出绿（↓）」两色；长内容一行省略号截断，
  完整内容在右侧**检查器**里看（检查器铺满高度：轮·步 / 时间 / 耗时 / 结果规模 +
  带行号与高亮的参数与结果代码块）。双击某一行会跳回对话视图并高亮对应那一段。
  视图选择按会话记住。右栏那一格留给**浏览器活动**与文件预览，不再被轨迹占用。
- **输入卡片下方**：上下文占用圆环 + 百分比（拿不到模型窗口就不显示），点一下看用量分布。
- **会话区顶部**：一行「第 N 轮 · HH:MM」—— 第 N 轮 = 你在**这条会话里第几次发送**
  （与轨迹视图里的「第 N 轮」同一个号）。你发出新一轮的**那一瞬**，上一轮已经跑完的
  「计划」与「任务清单」会被自动清掉（数据一并删除，切会话 / 重启都不会再出现），
  免得上一轮的记录被当成这一轮要做的；上一轮还有**没跑完**的项则整份保留，面板头部
  会标一行「上一轮遗留 N 项未完」—— 要接着跑仍然点面板上的「继续执行」。
  计划正在跑或会话暂停时不动清单（在跑的进度与「继续」入口不会丢）。
- **输入卡片上方**：清单（agent 用 `todo_write` 建的）三态标记 —— 待处理空心圆、
  进行中旋转圈、已完成实心圆（未确认 / 失败另有描边与红点）；再往上是两段分区：
  「已插话 · 待本轮下一步生效」与「发送队列」（本轮结束后依次发送）。

### 显示思考 · 工作步骤展示（全局默认档）

**会话里那一枚开关叫「显示思考」**（输入区「模式」菜单第三枚）：点开 = 这条会话里出现模型的
思考；关闭 = **整条不显示**（不是折叠 —— 思考段整块不出现，工具调用与步骤照旧按时间线摊开）。
关的只是显示：思考内容始终随消息存档，任何时候再打开都还在。

新会话默认显不显示思考、思考与工具卡默认展不展开，由「设置 · 智能能力 → 工作步骤展示」的四档
决定（会话里那枚开关是逐会话覆写，点过就听它的）：

| 档位 | 表现 |
| --- | --- |
| **简洁** | 不显示思考块（工具仍按时间线逐段摊开） |
| **标准（默认）** | 思考块给折叠条（收起）；工具按时间线逐段摊开 |
| **详细** | 思考块默认展开 |
| **完全展开** | 思考块与工具卡都默认展开（不用手点） |

**工具调用在任何档位都不收纳**（用户口径：折起来就和它在时间线上的位置分离了），
四档只决定「思考显不显示」与「思考 / 工具卡默认展不展开」；你手点过的展开 / 收起始终以你那次为准。

## 全局语音输入（状态栏最左的 🎤）

状态栏**最左**那枚 🎤 是**全局**语音输入（就在「画布截图」左边）：它把语音变成**全局文字输入** ——
识别结果实时写进**当前有焦点的那个输入框**（会话输入框、助手输入框、画布上的节点正文与参数框、搜索框都算）。
会话输入框 / 助手输入框右端**不再各挂一枚话筒**，全局这一枚接管全部。

点一下在三态之间循环，按钮颜色就是当前状态：

| 状态 | 键面 | 说明 |
| --- | --- | --- |
| 关闭（默认） | 🎤 灰 | 不采集、不占用麦克风 |
| 持续转录 | ● 青 | 一直听，边说边写进当前 focus 的输入框；浮窗里显示这句话的临时字 |
| 按键转录 | F1 琥珀 | 只有**按住 F1** 时才听，松开即止 |

- **按键为什么用 F1，而不是反引号那类字符键**：字符键要先落进输入框、再被「吞键」抹掉，两件事有竞态，
  按住说话时常会先看到一个字符蹦进消息框；F1 不产出任何字符，天然不会被录进去，也不用跟输入框抢。
  按键转录状态下 F1 被这枚按钮完全接管（`keydown` / `keyup` 成对吞掉，不落字、不触发别的功能），
  长按产生的系统重复帧被忽略、不会反复起停；**Ctrl+F1 一律放行**，其它快捷键不受影响。
- **不上传**：识别跑在你自己机器的 CPU 上（dsh 官方的 SenseVoiceSmall，ONNX 运行时随包），
  音频只在内存里走到本机运行时，不发给任何服务商，也不需要额外的密钥。
- **首次使用要下载**：模型权重约 239MB（int8），下载源默认 `huggingface.co` 与 `hf-mirror.com`，
  落地在数据目录 `dsh-home\speech-to-text\sensevoice\`。没准备过时按钮显示 `↓` 或百分比，
  下载完成后回到 🎤。**切态 / 关面板都不会打断下载**，下载是运行时自己的准备任务。
  下载还没完就点了持续转录 / 按住 F1，会先说一句「语音模型还没下载完：先让它下完，就绪后会自动开始录音」，
  就绪那一刻**自动补起采集**，不用你关一次再开一次。
- **失败态与怎么重试（两类，别混在一起）**：
  - **① 语音服务不可用**（通道 / 服务商还没挂上，不是模型的问题）：按钮画成 `!` 错误态，tooltip 与浮窗给一句
    「语音识别服务不可用：请稍后重试，仍失败可在右键菜单里点『重新检查语音服务』」，并**每 5 秒自动重试一次**
    （只自动重试一次，手动点过之后额度重新给）；服务挂上后按钮自动回到 🎤。
  - **② 模型下载 / 准备失败**（运行时把准备相位标成 `failed`）：按钮当场从 `↓` / 百分比转成 **`↓` + 错误边框** ——
    不再挂着旧进度假装还在下；tooltip、右键菜单第一行
    与「设置 · 语音输入（全局）」的模型状态行都会给出**原因 + 下载源**（如「网络连不上下载源 · 下载源 hf-mirror.com」，
    带 HTTP 码时一并给出），浮窗补一句怎么重试。这一态**不自动重试** —— 免得「一直在转圈」把失败糊住。
  - **重试入口（同一枚动作，三处都有）**：右键这枚话筒 →「下载 / 检查语音模型」（照原样再来一次）或
    「重新检查语音服务」（重读服务商 / 模型状态并重发一次准备）；设置小节底部是同两枚按钮。上一次失败的原因是
    下载源的问题时，设置里的模型状态行还会列出官方广告过的**其它下载源**（下拉选一个 →「用这个源重试」），
    留「自动（官方顺序）」= 运行时自己按顺序探测。
- **启动 / 首次连接时的载入态**：应用刚起来、或语音服务还没挂上时，按钮显示**载入旋转**
  （转圈弧，不写任何文字），这期间它会自己按 400ms 退避重试几次 —— 这不是故障，别急着再点。
  真连不上时会**给一句明确提示**（「语音识别服务不可用：请稍后重试，仍失败可在右键菜单里点『重新检查语音服务』」），
  落一条到浮窗 / 提示条，并按 5 秒自动重试一次；服务挂上后按钮自动回到 🎤。
- **分段是「停在停顿上」，不是按时间切**：官方运行时只吃整段 16 kHz 单声道 WAV，没有原生流式接口，
  所以这里做的是**整句只在停顿那一刻交一次**：从你开口说到静音停顿之间的整段音频作为一个整段提交，
  识别拿到的是完整一句，上下文与准确率都比「按固定时长切片」好（旧口径每 1.2 秒切一片、每片单独识别，
  句子被拦腰截断、错字多）。代价是**文字在你说完（停顿）之后才出现**，说话过程中没有可显示的文字 ——
  浮窗改报「正在听… · 已录 3.2s」加一条音量条，让你知道麦克风确实在收音。
  - **一直不停顿怎么办**：**句长不再封顶**（旧口径是 15 秒封顶）。一直说就一直攒着，直到出现停顿、
    或你松手 / 关闭才提交；唯一的硬边界来自后端（单次请求 ≤ 4 MiB ≈ 131 秒），撞到它时会在**最接近的
    低能量点**切一刀并接着收（会提示一句「这句话很长…」），不会因为你不换气就一直不落字。
  - **提交前会裁掉尾巴上多余的静音**（只留约 300ms）：停顿判据要连续安静够久才成立，
    那串静音没必要一起送去识别。
- **断句停顿（全局项）**：连续安静到这一档（默认 **300ms**，范围 100–2000）就判「这句说完了」，
  整段提交、浮窗收起、下一句重新开始计数。**画布上的音频 / 视频节点转写读的是同一项**：那边按这个
  停顿逐句切分、每一句单独送一次识别，转写文本**每句一行**（行末没有句末标点时补一个「。」），
  句子本身不设长度上限（同样只在后端 ≈131 秒的硬顶处切一刀）。
  判据用**连续安静帧**（起音仍走滑窗稳定性）—— 单帧抖动攒不出整段停顿，而设置里写 300ms 就是 300ms。
- **未 focus 则无视**：焦点不在任何可输入框时**暂停落字** —— 音频照样录、照样识别，回来的文字先留住，
  焦点回到同一个框再接着写（音频不作废，也不会插到别的窗口里）。切画布会丢弃这一句还没定稿的临时字。
- **插入方式**：定稿用浏览器的原生文本插入，所以画布节点的 Ctrl+Z 撤销栈与你手敲一段字完全一致。
- **语言**：默认自动识别（也支持中文 / 英文 / 粤语 / 日语 / 韩语）；右键点这枚按钮有快捷菜单
  （语言 / 断句停顿 / 下载模型 / 打开设置），同一份设置也在「设置 · 语音输入（全局）」里 ——
  「断句停顿」是**全局项**：改一次，话筒与画布节点转写同时生效。
  「切片长度」那一行已随新口径退役（分段不再按时间切）。
- **权限**：应用只放行「麦克风」这一项系统权限（其它权限仍然按 Electron 默认拒绝）。
- **同一台引擎，三处入口**：状态栏这枚话筒、画布上「音频接进文字节点 → 自动转写并注入提示词」、
  以及应用窗口 footer 里的听写条，走的都是这条官方本地 SenseVoice 通道（模型权重共享一份）。
  画布节点那条路的音频整形（解码 / 重采样到 16 kHz / 按「断句停顿」逐句切 / 每句一行）在渲染层完成，
  不依赖 Python 与 ffmpeg；转写结果按音频路径缓存，你在节点上改过的错字会留住
  （换识别引擎、或改「断句停顿」阈值时旧缓存自然失效）。
  - **节点那条路的冷起**：语音运行时是按需冷起的（首次约 1~2 秒）。这段时间提供者名单是空的 ——
    节点上会标「语音服务启动中」并**自己退避重试**（4 次 × 400ms，与话筒同口径），
    说清「稍等一下再点运行」；重试完仍是空名单才报「语音服务不可用」。
    （旧版只看一眼名单，空就当场报不可用并拦下整轮 —— 那是假警报。）
- **识别不出来**：浮窗会说一句原因（转写失败 / 模型没准备好 / 连不上服务），草稿不动 —— 再说一遍或直接打字即可。
  环境很吵、离麦克风太远、一句话里混了太多语言时最容易出现。
- **说了却没落字**：两种情况都会当场给一句 toast，不会静默 —— 要写的输入框已经不在了（先把光标点进文本框再说话），
  或转写队列积压过多（先让它把已录的写完，或点回文本框）。

## MCP 资源（扩展能力管理里每台服务器）

「扩展能力管理」→ MCP 标签 → 选中一台服务器，详情里多了一块**资源清单**：

- 点「读取资源清单」才去连（**惰性**：stdio 类型的服务器会临时起一个进程，不点不连）；
- 列出来的是这台服务器用 `resources/list` 暴露的资源与资源模板（URI + 名称 + MIME）；
- 每条可以「查看」（`resources/read` 的内容，长文本在面板里展开）或「复制 URI」（粘进对话当上下文）；
- **只读**：宿主只发 `resources/list` / `resources/read`，**绝不会**调用这台服务器的任何工具；
  连接在 60 秒空闲后自动回收，应用退出时一并收干净；
- 读不到就说原因（找不到 `command`、超时、服务器已停用……），不会静默。
- 与模型侧的关系：dsh 0.2 的组合里本来就带 `@deepseek-ai/dsh-mcp-resources`（Agent 在任务里
  自己会读资源）；这里这块面板是给**你**看的，两者是两条通道，互不依赖。

## 定时任务（本版本未提供）

dsh 0.2 内核里的官方定时任务（`@deepseek-ai/dsh-schedule` + 时间上下文 + 任务页）在当前
MTNode 使用的 **SDK 组合里挂不起来**：行能插进组合、运行时也能起来，但 `ctx.schedule` 服务
始终不出现、模型工具表里也没有 `schedule_create`（上游 README 自己写明它需要 Web 组合的
Session 控制器才能投递，而 MTNode 跑的是 SDK 组合）。所以本版本**界面上没有定时任务入口**，
避免给你一个按下去没反应的按钮。

需要「到点自动跑」时，现在可用画布上的**定时器节点**（timer：到点 / 每隔一段时间触发一次），
或者直接跟会话说「每过一会儿提醒我」这类需要你在场的用法。
