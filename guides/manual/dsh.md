# 智能能力是什么

![智能能力](img/dsh.svg)

接入 DeepSeek Harness（dsh）后，模型不只生成文字，还能**读/写工作目录文件、联网搜索、执行命令、派子代理**。运行时随应用自带，**不用另装 Node**。

需要先配置带 API Key 的**文本服务商**。智能任务（含会话模式）、智能会话、文本处理的「🐋 智能」都走这条引擎。

引擎随应用自带一批**内置技能**，运行时自动同步、不用安装，AI 用 `skill` 工具按名字加载：`mtnode-dev-architect`（开发节点架构）、**`mtnode-grill-me`（拷问我：把需求映射成决策树、按轮用询问窗 `ask_user_question` 一次问完整个前沿并附推荐选项，达成共识并经你确认后才动手）**、`mtnode-canvas-batch-safety`、`mtnode-canvas-layout-ux`、`mtnode-db-facts`、`mtnode-media-gen-nodes`（音乐 / 语音 / 视频生成节点）。详见 [插件、技能与 MCP](#plugins-skills)。

## 过程可见

运行中显示「◉ 思考中」，可展开思考与 **🔧 工具调用**。智能模式按任务完成计费，一次任务可能多次调用模型。

写文件前请确认 [工作目录](#workspace) 正确。权限过宽或过严见 [审批与权限](#approvals)。

## 思考与输出分开显示

一次运行按**发生顺序**分段显示，三类段各有各的样子：

- **◉ 思考 · N 字**：模型内部推理（reasoning），默认折叠，点开才看；N **只统计思考的字数**，不含工具与正文。
- **正文**：模型真说出来的话，正常字号、Markdown 渲染，一段一块——中间步骤说的话也以正文出现，不会被埋进思考里。
- **🔧 工具**：调用轨迹就近插在它发生的位置，点开看参数与结果；出错以 **⚠** 附在正文里。

每调用一次工具、或进入新的一步推理（turn / step），都自动另起一段。智能任务节点（含会话模式）、智能会话、右侧全局助手用的是**同一套分段**；节点上的「思考中」大窗上半是思考、下半是输出（工具调用轨迹）。

**下游数据不受影响**：输出端子给下游、以及存进保存节点的，仍是完整正文。旧的会话存档按原样显示。

## Agent 预设：换一档说话方式

预设决定智能体用什么角色与风格干活。四处都能选：智能会话的**模型菜单 · 预设**、右侧助手栏的**预设**下拉、智能节点参数面板的**预设**下拉、**设置 · 智能能力 · Agent 预设**（开发节点 🧠 弹层的「预设」格同源）。目前五档（**菜单里的顺序就是这张表的顺序，第一档就是默认档**）：

| 预设 | 干什么用 |
| --- | --- |
| **极简模式**（默认） | 省事档：最少步骤、最少废话，直接给结果 |
| **标准模式** | 通用档：画布编排、文件与内容任务兼顾，解释比较完整 |
| **思维精简** | **压缩思考表达**档：思考压成符号骨架，最省 token（思考强度仍按你的设置走，本档不再自动降档） |
| **PTC 模式** | 工程档：写代码 / 改文件 / 跑命令；先读再改，改完说明改动与验证方式 |
| **创造模式** | Cordis 插件开发档：遵循 Service / ctx.effect / 类型化事件的约定 |

> **默认档 = 极简模式**：新开的智能会话、新建的智能节点、以及设置里没动过这一项时，走的就是它。想要解释更完整的通用档就在上述四处任一处切到**标准模式**（已经保存过的旧配置仍按你原先选的档位走，不会被悄悄改写）。

### 思维精简为什么省 token

智能任务按模型输出计费，而**推理内容（思考）本身也是输出**——一个请求动辄上千 token 的内心独白，最后交付只有几行。思维精简从三头同时收：

- **先结构化**：动手前用一行把任务压成 `GOAL/GIVEN/DECIDE`，之后只依据这一行推进。
- **固定骨架**：思考只允许 `GOAL`（一行）→ `APPROACH`（最多三步符号，写成 `A→B`、`{候选}/✔`）→ `EDGE`（一行）→ `DO`（下一步动作）；不许新增小节，不许复述你的原话和工具输出。
- **剪掉废话**：凡**不改变下一步决策**的句子一律不写；缺事实就去读文件 / 搜索 / 查库，不允许脑补推演。

这一档的提示文本本身就是一整段紧凑规则（不含方法标号，也不声明任何工具授权——授权始终只由运行时的工具许可决定），前缀同样按最省的方式写。

省下来的是**思考的表达量**：这一档只压思考的写法（骨架 + 符号 + 剪枝），**不动思考强度**——界面上选的「标准 / 最强」就是实际下发的那一档（早先版本曾把它自动压到 low，现已取消）。**交付不受影响**：工具授权仍由运行时的工具许可决定（思维精简不声称、也不改变任何权限），输出端子与保存节点拿到的仍是完整正文。

> 本档早期叫「草图模式」（内部 id `sketch`），现统一为**思维精简**（内部 id `lean`）。旧会话与智能节点里存的 `sketch` 会自动归一到 `lean`，预设文本照常生效，无需重设。

### 代价

- **可能少想一步**：骨架之外的分支不会被展开，越是需要反复权衡的判断题，越容易漏细节。
- **需要深推理时**：把思考强度选成 **最强**，或直接切回 **标准模式 / PTC 模式**——思维精简不再替你改这一档，选什么就按什么跑。
- **界面写的就是实际跑的**：模型 chip 与思考强度项只显示你选的那一档（标准 / 最强），不再有「名义档 / 生效档」两套说法。

## 交流语言（Agent 口味）

顶栏 **中 / EN** 选定界面语言后，这份语言会作为「口味」随每次智能运行一起下发：**用该语言交流，并期望 agent 用该语言回答**——提问、计划、进度说明、最终回答都跟随界面语言，派生的子任务与功能块绑定会话同样沿用。设置 · 智能能力 区块会显示当前用的是哪种语言。

口味只约束**交流**。代码、路径、命令与 API 字段名保持原文；事实库记录、表格单元格与写回文件的正文沿用资料原本的语言，不会因为切换界面语言而被翻译。用户在一轮对话里明确指定别的语言时，以用户为准。

## 复杂任务先出计划（确认后逐项执行）

智能会话与智能任务节点接到要求时会先判断复杂度：已经说清楚了的、或者很简单，就直接开工；判定为复杂任务则**本轮不做任何改动**，只回一份计划。应用随后响起提示音并弹出「计划确认」窗口——右下角可拉伸、⤢ 最大化，一条任务三列（标题 / 详情 / 执行模型），可增删、上下排序、给同名「并行组」的任务并发跑；确认后按清单逐项执行，每项单独一轮、用它自己选定的模型。会话底部的「计划」面板是这份清单的持久视图，中断后可「▶ 继续执行」。

**计划没弹出？应用会自动补一次。** 模型偶尔会在这一步生成失误：计划块的标记被写坏、漏掉闭合标记，或者干脆把 JSON 直接写在正文里。这种计划应用解析不出来，弹窗就不会出现，会话看起来「说完就没了」。现在每轮收尾时应用会做一次**关键词检测**：只有当这一轮确实被要求按计划格式交清单、而正文里又出现计划块标记或 `goal` + `tasks` 字段特征（两者同现才算，避免误伤普通答复）时，才判定为「漏弹」——随即自动回发一条纠错指令，要求模型**按原契约重新输出一次**。边界很克制：一个用户轮次最多补一次，补完仍不合法只在界面提示你重发要求；这一轮被你终止、或队列里还有你自己排的消息时一律不补，绝不与用户抢下一步。
