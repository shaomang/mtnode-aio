# 超级节点（收纳子图）

> 一句话目标：把一批相关节点收成一块子图，主画布只留一个壳，内部照常编辑，数据靠边端子隧穿。

![超级节点边界端子](img/mtnode-canvas-04-state.svg)
*图 1：外侧端子 ↔ 内侧桥接 / 汇流——数据与控制都从边端子隧穿，不再用内部代理节点*

## 目标

读完后你能把一坨节点收进超级节点、展开壳层或 ↪ 进入内部编辑、用边端子把内外数据接上，并用子文件夹约束内部相对路径。

## 前置条件

- 有一片想收纳的节点。超级节点与「任务」不同：任务强调控制流（起点 → 终点），超级节点强调**结构收纳与数据通道**。
- 创建 / 收纳常需 **canvas_super** 审批；智能会话或助手替你改画布时也会先询问。

## 步骤

1. **创建或合并**：空白处右键 → **超级节点**；或框选若干节点后点顶栏 **「超节点」**（按选区外框新建展开的超级节点并把选中节点收纳进去）。
2. **展开壳层**：点标题栏右侧的展开图标，在主画布上打开壳层内部舞台直接编辑子节点；再点一次收起。展开时内容会尽量贴齐舞台左上角。
3. **进入内部画布**：点 **↪ 进入**，画面只剩该超级节点内部，用工具条上的**面包屑**返回上层。壳层内可左键拖空白平移、滚轮缩放外层相机、右键加节点；把节点拖进 / 拖出即可移入移出。
4. **接边端子**：数据与控制都走**边端子**隧穿——外侧输入（收起时外部连入）、内侧输入（展开壳层左侧，或 ↪ 后画布左边缘）、内侧输出（内部节点连到壳层右侧 / 全屏右边缘）、外侧输出（连出到外部）。端子右键可移除该端子的内侧连线。
5. **让控制线过壳**：外侧某端子接了控制节点（金色指挥线）时，同号内侧桥接线也变为控制线（即使原先是数据线）；任务脉冲与「执行 / 清空」批控会经端子隧穿到另一侧，不会停在壳上。
6. **设子文件夹**：标题栏右侧可设**子文件夹**（相对顶栏工作目录）。内部保存 / 音乐 / 视频 / 监视等待等节点的**相对路径**会自动落在 `工作目录 / 子文件夹 / …`；嵌套时取祖先链上的全部子文件夹。移入超级节点或改子文件夹时会给已有相对路径补前缀，**绝对路径不改写**。
7. **嵌套与排版**：超级节点可嵌套；点顶栏「排版」整理主画布时，若存在已展开或含内容的超级节点，会询问是否**同时排版内部**。
8. **用边栏找**：☰ 边栏分两段——上半是当前画布的节点 / 标签 / 绘图（点击居中），下半是**超级节点树**（按嵌套层级列出，点击即进入该超级节点画布并适配内部节点）。筛选框同时过滤节点、绘图与超级节点标题 / 子文件夹。

### 两种特殊形态

| 形态 | 入口 | 作用 | 详见 |
| --- | --- | --- | --- |
| **开发节点** | 右键 → 开发节点（项目架构 · 功能块） | 软件项目架构：模块 → 文件 → 类 / 接口 / 枚举，绑定项目根目录，头部「建议 / 开发 / 细化」按钮，元素间用关系线表达依赖 | [开发节点：让 AI 写项目](#dev-nodes) |
| **数据库节点** | 设置开启「测试版本」后右键添加 | 事实收纳：内部「文件节点 / 表」→ ⚙ 编译 → 数据库副本，智能节点用 `mtnode_db` 查询 | [数据库节点与事实纪律](#database-nodes) |

> 💡 技巧：把一整条「输入 → 处理 → 保存」收进超级节点，只对外留一个数据入口和一个出口，主画布会立刻清爽；对外暴露的端子越少越好维护。

> ⚠️ 危险：给超级节点换子文件夹时，内部**已有相对路径会被补上前缀**——如果那些文件已经在磁盘上，先确认新路径是你想要的落点再保存。

## 结果

主画布上只剩一个壳，双击展开即可编辑内部；内外数据经边端子正常流动；内部节点的相对路径自动带上子文件夹前缀。

## 常见错误

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 内部节点拿不到外部数据 | 没把外部线接到外侧输入端子，或内侧桥接没连到内部节点 | 两侧都要接上，超级节点不做隐式透传 |
| 数据线进了壳变控制线 | 该端子在外侧接了控制节点 | 这是设计行为；需要纯数据就换一个端子 |
| 内部相对路径跑到了别的目录 | 子文件夹设置与预期不符 | 检查祖先链上的子文件夹；要固定位置请用绝对路径 |
| 进到内部出不来 | 迷路了 | 用工具条面包屑返回上层 |
| 收纳后画布更乱 | 壳层展开着 | 收起壳层，或点「自动排版」重排 |
| 提示需要 canvas_super 审批 | 权限预设较严 | 在审批面板放行，或改用更宽的预设 |
