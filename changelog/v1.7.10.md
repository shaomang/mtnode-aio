# v1.7.10（2026-11-21）

会话多了「白话简报」：一边跑，一边用一句话一步告诉你它干到哪儿了

## 新增

* 输入补全改成**两种用法**：一边打字就一边给出半透明的补全建议（自动），或者在输入框里按 Tab 现场要一次（手动）—— 手动那一下以及等模型的时候，光标后面会转一圈「补全中 ⋯」，补全回来再按一下 Tab 就采纳；Shift / Ctrl + Tab 照旧留给上层自己的快捷键
* 输入补全成了基础功能：默认开着，应用里也带上了 —— 新建应用默认打开「输入补全」，应用窗口里的每个输入框都能边打边补、按 Tab 现场要一次；存量应用可以在「应用设置」里勾上
* 「输入补全」设置面板里加了一行状态：就绪时用的是哪个模型，还是卡在「没有可用的服务商 / 当前服务商没有模型」，上一次失败是因为超时还是请求出错 —— 以前只能看到「什么都没发生」
* 会话的「模式」菜单里新增「简报模式」（默认关闭）：打开后，助手每办完一步就顺手写一页白话简报 —— 一句总述加一行一步，只说做了什么、到哪儿了，不写文件名、不贴命令与参数
* 打开简报模式后，「对话」里多出「原始 / 简报」两枚子标签：想看完整过程点「原始」，想看进度点「简报」，底部输入框一直能用，随时接着聊
* 简报里每一行都能点开，就地看这一步的原文
* 简报那次额外调用可以单独指定模型（默认跟着这条会话现有的模型走），它的花费在 Token 报告里单列一条「简报模型」，用了多少一眼可见
* 简报模式打开前跑过的旧会话，进简报页会自动补写最近几轮
* 更早的轮在卡上点「补一份」，一次补一轮
* 底部状态栏多了一枚「AI 工作中」呼吸灯：只要有 AI 在干活，它就一直亮着并显示「有几个」；点开是一张「AI 工作台」，上半列出所有正在跑的 AI 任务（是会话、画布节点、应用里的 AI、还是自动修复，用什么模型，已经跑了多久，卡在哪个阶段），下半是选中那件的逐步过程（几点几分、做到哪一步、用了哪个工具、写到什么内容），失败的那步标红
* 「AI 工作台」底部的「跳过去」直接带你到那件事发生的地方（那条会话 / 那枚节点 / 那个应用窗口），「终止」跟原来那些停止按钮是同一个入口 —— 没有取消方式的（比如应用里的文本生成）按钮会变灰并写明原因，不会给你一颗点了没反应的按钮
* 没有 AI 在跑时点它也不空着：显示「最近一次」是哪个任务、什么时候跑完的、当时的过程，随时回看

## 改进

* 简报模式记得你上次的选择：在任意一条会话里打开它，之后新建的会话就默认开着；关掉它，之后新建的会话就默认关着 —— 但**之前已经开着的会话不会被一起关掉**，各记各的
* 简报只写结论，不再出现「正在读取…」这类过程旁白
* 没拿到结论的步骤不占行，简报不再一步一句地刷
* 简报一轮最多问两次：跑到一半一次、收尾一次，不会越跑越贵
* 进简报页时，还没简报的那几轮先摆原文摘录与补写进度
* 正在跑的那一轮当场出现在简报页，不用等整轮跑完
* 「简报模型」这一格只在简报模式开着时出现
* 模型一时用不了（超时、限流、没有输出）时，保留上一版简报并提示一句「简报暂不可用」，会话照常继续跑
* 应用里的 AI 改为在**应用自己的窗口底部**报进度：应用调 AI（AI 编辑、文本生成、跑一轮助手）时，它自己界面下方出现一条「AI 工作中」——在做什么、跑到哪一步、已经多久、走了几步，点一下展开逐步过程（时刻 · 阶段 · 正文摘要，出错那一步标红），这一条跑完自己淡出消失。主窗口那枚呼吸灯不再替应用报（它只报会话、画布节点、识图、变体与自动修复），应用里发起的任务不会再跑到 MTNode 的状态栏里去
* 应用界面里的这条对应用零改动：独立窗口与画布内嵌两种形态都由宿主注入，应用不用声明任何能力位、也不用改一行代码

## 修复

* 输入补全不再是「配了也不生效」：以前它只认 DeepSeek 家名字里带 flash 的模型，服务商里没有 flash（只配了 pro 档、或者走中转）时整件事一声不响 —— 现在模型格列出全部模型、flash 排在最前并标「推荐」，没指名时也按「flash 优先、其次该服务商第一个模型」自己挑
* 「本次统计」里的请求数与采纳数不再是永远的 0 / 0：现在真的在发请求与按 Tab 采纳时各记一次
* 应用窗口左下角显示的版本号现在永远和应用中心里的一致：以前上架了新版本，窗口左下角还写着第一次的那个号（应用中心是 v1.0.3、左下角还是 v1.0.0）—— 现在上架成功会把版本号写回本机应用，已经漂了的老应用打开就直接显示上架那一版

* 简报更新时不再自己挪滚动条：以前每刷新一次简报（比如又补上一份、或正在跑的那一轮有新进展），简报页会把正在看的位置弹走一次 —— 现在更新只把位置原样放回去（当时贴在底部就还留在底部，翻上去读历史就一个像素都不动），之后怎么看、滚到哪由你自己决定
* 多轮会话里「前面几轮」真的进上下文了：以前每轮重发的上文只留最近约 4000 字，轮次一多较早的回复就被整段丢掉 —— 于是对前几轮的回复加批注时，模型在上下文里找不到那段原文，只能回「找不到这段内容」。现在前面所有轮都随新的一轮一起发过去（预算真源 = `renderer/app-db.js` 的 `AGENT_HIST_MAX_CHARS`，按网关声明的 1,000,000 token 窗口给到 200,000 字符）；只有几百轮的极端长会话真被砍时，才会在段首写明「本次上下文省略了更早的 N 条上文」，模型不至于以为自己看全了
* 右侧助手栏的历史段同一处修正：原先另截到最近 16 条，现在与会话侧共用同一份预算与同一套裁剪实现
* 本地模型插件安装不再可能「彻底卡死」：某个下载源不回话时会自己超时换下一个；整个安装脚本长时间没有任何输出时，安装窗会当场收尾并把原因说清楚，同时把「让 Agent 兜底修复」摆在第一位 —— 以前这一步会一直停在「安装中」，点重试也只会回「忙」
* 安装失败时，日志区上方会显示「接下来怎么做」的建议（以前这句建议算出来了，但窗体不显示）
* 引擎二进制已经下好时，重跑安装不再重新下载那 100MB+
* 下载到一半被掐断的半截文件不会再被当成「下好了」（坏包会在下一步炸开）
* 本地模型插件装完会自己验一遍再算装好：venv 里真 import 一次、`bin\llama-server.exe` 在位且不是半截、`models\` 与 `.api-key` 齐（缺的就地补）。任一项不过就在安装窗里如实报失败，不再出现「窗口说装好了、点启动却回『后端尚未安装』」
* 控制台「在线模型」列表改成固化口径：第一次拉取后整页落盘冻结（连每个仓库的真实体积与架构一起），之后再打开只按时间问一次最新增量，其余沿用固化结果 —— 列表秒开，镜像不可达时也有内容可看
* 装完能打上「安装完毕」标识的插件补齐了：本地模型（llama.cpp）、MOSS-Music、Paseo 手机接管、桌宠这四个插件原先没有登记安装后自检，装完那次自检根本不会启动，卡片封面左上角那个勾也就永远触发不了。现在它们装完会各自真验一遍（llama：要件核查 + venv 内真 import；MOSS-Music：要件齐不齐 + venv 内真 import；Paseo：CLI 真能报版本 + provider 已注册；桌宠：形象包装齐了没），通过就打勾；另外加了一道回归闸，凡是走安装窗的插件都必须登记自检，不再可能出现「装完永远没有标识」
* 在画布上打开应用（盖住画布的那种形态）现在也有底部那条宿主工具条了：以前只有把应用弹成独立窗口才看得见听写条这些底部工具，盖在画布里的应用什么都没有 —— 现在两种形态一致，听写条这些底部工具都会出现
