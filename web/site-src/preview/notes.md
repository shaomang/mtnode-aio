## 四、视觉母题：坐标系与端点数值（改位置时的维护口径）

画布 `700×340`（SVG `viewBox` 与节点 `--x/--y/--w/--h` 用同一组数字）。语汇取原版：节点卡＝原版 `.card` 的「1px `var(--bd)` + 5px 圆角 + `var(--panel)` 底」。

| 节点 | `--x/--y/--w/--h` | 端口 | 连线 |
| --- | --- | --- | --- |
| 文本输入 | 16/30/158/60 | 右 `out` 青 | `w1` 青 → 文本处理 |
| 素材 | 16/140/158/60 | 右 `out` 青 | `w2` 青 → 文本处理 |
| 图像输入 | 16/250/158/60 | 右 `out` 青 | `w3` 青 → 文本处理 |
| 文本处理 | 251/140/158/60 | 左 `in` 橙 · 右 `out` 橙 | `w4` **黄** → 保存 |
| 保存 | 486/140/158/60 | 左 `in` 黄 | — |

**语义分工**（`design-tokens.md` §1.1 原文口径）：青＝读 / 橙＝改 / 绿＝跑 / 黄＝落在哪儿。故三路上游＝青（被读走），指向落盘的那条＝黄。红（失败）本样张未出现。

**实测几何（1280 视口探针读真实计算值）**

| 项 | 值 |
| --- | --- |
| 端口圆心（母题坐标 px） | 文本输入.out `234,81` · 素材.out `234,228` · 图像输入.out `234,375` · 文本处理.in `337,228` · 文本处理.out `549,228` · 保存.in `652,228` |
| 四条线端点 | `w1 234,81→337,228` · `w2 234,228→337,228` · `w3 234,376→337,228` · `w4 549,228→653,228` |
| 端点 vs 端口圆心 | **误差 ≤ 1px**（唯一 1px 来自百分比定位的取整） |
| 端口配色 | 三个 `out`＝`rgb(56,214,255)`（青）· 文本处理 in/out＝`rgb(255,143,46)`（橙）· 保存.in＝`rgb(255,209,102)`（**黄**） |
| 四条线是否真的画出来 | **painted=True × 4**，描边 2px |

⚠️ **改一个节点位置，必须同步改它的 `--x/--y` 与对应 `path` 的端点**；改画布尺寸还要同步 `.graph` 的 `aspect-ratio` 与三处 `calc(.../700)`、`calc(.../340)`。

## 五、反模式检测器：7 项，与原版**逐条相同**

## 七、本轮修掉的两个真 bug（都潜伏自 v2，肉眼很难发现）

1. **`w1` 端点错位**：v2 的 `w1` 是 `M174,60 L251,60`，终点落在 `(251,60)`——而文本处理节点的左端口在 `(251,170)`。它**不是"连到文本处理"，而是水平伸到半空**。v2 的 notes 却写着"端口圆心与连线端点误差 < 1px"（那句只对当时抽查的那条成立）。
   → 改为 `M174,60 C215,60 210,170 251,170`，与 `w3` 对称收敛。
2. **`w4` 根本没被画出来**：CSS 只给了 `.w1,.w2` 与 `.w3` 描边，`w4` 没有 `stroke` 规则——**SVG 里 `stroke` 的初值是 `none`**，所以"文本处理 → 保存"这条线在页面上是空的。同时语义也接错了：黄色（落在哪儿）本该给落盘那条（`w4`），v2 给成了读路（`w3`）。
   → 改为 `.w1,.w2,.w3{stroke:var(--cyan)}` + `.w4{stroke:var(--yellow)}`，并在注释里写明"每条 wire 都必须给到 stroke，漏掉就整条不画"。

3. **顺带补的 `--yellow`**：**原版 `:root` 里没有 `--yellow`**（原版页面用不到它）。所以 `border-color:var(--yellow)` 在计算期取不到值、静默退成 `currentColor`，保存节点的端口实测是 `rgb(216,222,232)`（＝ `--ink`）而不是黄色。→ 在 PART B 补 `:root{--yellow:#ffd166}`，值取 `design-tokens.md` §1 的实测值（该文件 §2.1 已证实三套主题语义色同值，是品牌恒量），不是新造色。

> 这三条都是**数值探针与识图交叉**才暴露的：探针量出"端点坐标 vs 端口圆心"与"端口实际颜色"，识图看"线上到底有没有东西"。只靠截图目测会漏掉。

## 九、维护口径（钉死，避免下次改错）

1. **样式真源只有两个**：`web/index.html`（原版，PART A 的唯一来源）与 `design-tokens.md`（令牌语义与实测值）。**PART A 不许改值**；要改先想清楚是不是又变成"自造一套"。
2. **增东西一律加到 PART B**，并且只用原版已有的令牌与手法；需要新令牌（如 `--yellow`）必须在 PART B 顶部补定义并注明出处。
3. **语义色不得重排分工**：青＝读 / 橙＝改 / 绿＝跑 / 黄＝落在哪儿 / 红＝失败。
4. **母题每条 wire 都必须给到 `stroke`**——SVG 的初值是 `none`，漏一条就整条不画（§七 第 2 条）。
5. **改版本号**：`<script>` 里 `VER_DOC`（显示用，＝应用真源）与 `VER_FILE`（下载文件名用，＝实际存在的包）分开；这是原版「改版本只改一处」做法的扩展。
6. **改母题位置**：同步改 `--x/--y/--w/--h` 与 `path` 端点，改完用探针量"端点 vs 端口圆心"（应 ≤1px）。
7. **新增卡片**：复制一个 `<div class="card reveal" style="--d:Nms">`，用原版结构（`h3 > .ico + 标题`、`p`、`p.facts > code`）。
8. **每条事实必须能在 `content-facts.md` 指到出处**；查不到的不写（`PRODUCT.md` Product Principles 1）。
