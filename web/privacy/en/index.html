MTNode Privacy Policy

This page explains what information MTNode AI Orchestrator (below, "the app") and its companion online services process on your computer and in network traffic, why it is processed, how long it is kept and how it can be deleted. It is written in everyday language rather than legal jargon; every statement below about collecting / not collecting / transmitting / retaining is grounded in this project's source code and in measurements taken on our own server.

Effective: 2026-09-04 Policy version v1.0 No telemetry · no analytics · no ads API keys kept on your machine MIT open source

1. Scope and effective date

This policy applies to: (1) the Windows desktop app — the NSIS installer offered on the download page and the MSIX build distributed through the Microsoft Store; (2) the companion online service mt-agent.com operated by this project, namely in-app automatic updates, the application-plugin catalogue, the extension catalogue (plugins / skills / MCP), the Creative Workshop (template and skill sharing), the Forum, and delivery of the desktop-pet and local back-end install packages; (3) this privacy policy page itself.

This policy does not apply to the third-party AI provider APIs that you configure yourself in "Settings · Providers" and pay for with your own account (the built-in default is the DeepSeek official API; the sample configuration you can paste in includes SiliconFlow; any other OpenAI-compatible provider is one you add yourself), to the MCP servers you add yourself, or to the third-party sites that serve dependencies and model weights when you install a local back-end (PyPI mirrors, ModelScope, Hugging Face and its mirrors, the npm registry, GitHub, Alibaba Cloud OSS, and so on). Those parties publish and enforce their own privacy terms — please read them as well.

This policy takes effect on 2026-09-04. Continuing to use the app after an update means you accept the version then in force; material changes are recorded in section 14 below.

2. The short answer

In one sentence

The app does not require an account to be used (an account is needed only for uploading to / liking items in the Creative Workshop and for posting topics / replies in the Forum, and is entirely optional); it contains no telemetry, no usage tracking, no advertising SDK and no third-party analytics script; your canvases, assets, configuration and API keys all stay on your machine; prompts and input content are sent to the model provider that you yourself configured only when you click "Run" yourself.

Three things must nevertheless be stated plainly. They do not contradict the "we do not collect" wording above, but they do involve your data or your machine's permissions:

  • Running nodes, starting conversations, checking for updates, browsing the store and installing back-ends all issue network requests to the corresponding servers; the web server behind mt-agent.com keeps access logs (including IP address and User-Agent).
  • mt-agent.com currently offers HTTP (port 80) only — HTTPS is not enabled. Whether traffic to a third-party provider is encrypted depends on the address you configure (the built-in DeepSeek official endpoint defaults to https://api.deepseek.com).
  • The agent gateway may, within the authorisation you grant, read and write local files and execute commands (section 8). This is a core feature of the app, not information collection — but it does mean the content of files that get read ends up inside the requests sent to the model provider you selected.

3. What we process: the part that stays on your machine

All user data is written under the Electron user-data directory, by default %APPDATA%\pipeline-console\ (the app's own data sits in the pipeline-console\ sub-directory below it). You can change the target folder under "Configuration data directory" in Settings; only the pointer file data-root.json then remains in the original location. This data is not uploaded to any server automatically.

4. What we process: the part sent to AI provider APIs

When you run a text / image / smart node, or start an assistant conversation, the app sends whatever that request needs to the endpoint you configured yourself under "Settings · Providers" and for which you are billed by that provider directly (built-in default: https://api.deepseek.com; the paste-in sample configuration references https://api.siliconflow.cn/v1). This project does not resell or proxy model access: no request in this section ever passes through mt-agent.com. Requests are made by the main process or by the gateway child process — the interface itself cannot reach the network directly. What is sent includes:

  • The prompts and system / persona prompts you wrote; the body of any node @-referenced into the request; the content of images you uploaded and referenced in a node.
  • In an agent session, the local file content and command output that the agent was authorised to read — these come back as tool results and are included in the next model request.
  • The request header User-Agent: deepseek-harness/<version>: an application-attribution string the framework always sends and which contains no personal information.
  • On the DeepSeek official route, two additional HTTP headers: x-deepseek-harness-user-id (the locally generated random anonymous UUID described in section 3) and, when a session exists, x-deepseek-harness-session-id. Both appear in request headers only, are never written into the request body, and are not visible to the model.
  • Search queries for online search: the search provider is fixed to DeepSeek official and accepts only your own DeepSeek key.
  • MCP servers you added yourself: a stdio server is a local process; a remote server is connected at whatever URL you entered, and the inputs and outputs of its tool calls are sent to that address.

In other words: which provider receives your content and under which terms is entirely determined by the address you configure and the key you use. We keep no copy of these requests on our side (apart from the local session records described in section 3), and we do not process their content.

Every one of them is triggered by an action of yours (opening a panel, clicking "Check for updates", clicking install, posting, uploading) and carries a fixed application user agent (such as MTNodeAIO/1.1); requests never include your name, e-mail address, a device identifier or the content of your canvases. Access logs on the server side

The nginx server behind mt-agent.com keeps access logs for all requests (default combined format; no path is excluded). The fields recorded are: client IP address, timestamp, the full request line (method + path including the query string), status code, response bytes, Referer and User-Agent; for routes reverse-proxied to the Workshop service, X-Real-IP / X-Forwarded-For are additionally passed to the back end. Logs are rotated daily and compressed, and are deleted automatically after about 14 days.

The Workshop service itself has no per-request log — it emits only its startup line and save-failure records — and its data file contains no e-mail, telephone or IP field (your IP appears only in the nginx access logs described above).

When a download or update request is not matched by a local route, it is forwarded to Alibaba Cloud OSS (mtnode-download.oss-cn-beijing.aliyuncs.com); OSS-side logging is performed by Alibaba Cloud under its own terms and is outside this project's control.

About encryption in transit

Our cloud server currently listens on port 80 only (plain HTTP); port 443 and a certificate are not configured. Requests to the update source, the store, the Forum and package downloads are therefore readable in clear text on the network path. Please do not reuse a password from elsewhere when registering a Workshop account. Whether access to a third-party provider uses HTTPS depends on the address you configure.

6. Creative Workshop and Forum: uploading publishes content

No account is needed to use the app; an account is required only for uploading to / liking items in the Creative Workshop and for posting topics / replies in the Forum, and using those features is entirely optional — browsing the Forum needs no account.

  • Registration takes three values only: user name (3–24 characters: letters, digits, underscore), password (6–72 characters; the server stores it as a scrypt hash with a random salt and never keeps the plain text), nickname (1–32 characters). No e-mail address and no phone number is collected. The login token is stored locally in config.json, and subsequent requests carry it as Authorization: Bearer <token>.
  • Templates and preview images you upload are public content: when you upload a canvas (.mtnodes) or a skill (SKILL.md plus attachments) to the Workshop, its title, description, tags, preview images and canvas body are shown to all users and can be downloaded. Before uploading, the app deliberately clears the local working-directory fields (the workspace paths in the workflow and in the nodes are set to empty strings) so that local paths are not leaked; nevertheless the canvas body itself — the prompts you wrote, the parameters, the copies of your assets — is published, as you intended. Review the content before uploading, and do not upload canvases that contain private material, secrets or internal documents.
  • Deletion on request: templates and skills can be deleted by their author (or by an administrator) from within the store — removing the entry also removes the likes attached to it, the package file and the preview images, and the download counters go with them. If you cannot find the control in the app, or if you want your account, nickname or other published content removed, send us a request as described in section 15: the server currently has no self-service account-deletion endpoint, so this is done manually.
  • Forum: topics, replies and their status are browsable without signing in; signing in lets you post a topic, reply and change a status. A topic consists of a title, a body (up to 2000 characters), an optional image that is first rescaled locally to at most 1080 px on its longest edge and encoded as JPEG no larger than 3 MB, and its status; reading the Forum additionally sends the client time-zone offset tzOffset (in minutes, used only to bucket topics by day for display). Topics are kept long-term — they do not expire automatically — and you may ask us at any time (section 15) to delete topics or replies you posted.

7. Local back-ends: installing downloads dependencies and models

The music, video, speech and local-LLM back-ends (Music3 / H3 / GPT-SoVITS / llama.cpp / Remotion) are downloaded only after you click "Install". The installation fetches Python / Node dependencies and model weights from third-party sites; those requests carry your client IP address and user agent. What is downloaded contains none of your data, and its use is governed by the terms of the corresponding third party:

  • Dependencies: the domestic PyPI mirrors (Tsinghua / Alibaba Cloud), download.pytorch.org, mirrors.aliyun.com/pytorch-wheels, the npm registry, and the GitHub repository URLs involved when you install a DSH plugin or the Remotion back-end.
  • Model weights: ModelScope (modelscope.cn), the mirror hf-mirror.com and, where necessary, huggingface.co.
  • Browsing plugins / skills / MCP online in "Manage extensions" additionally sends search requests to the default online sources registry.npmmirror.com and data.jsdelivr.com, and these requests include the keywords you type into the search box.

These online sources can be added or removed in Settings. If you never use "Install" or online browsing, none of the requests above occur.

8. Agent gateway: reading and writing local files, running commands (a feature, not collection)

The app's smart nodes and assistant can, within the permissions you grant, read and write files on your machine and execute commands. Three points need to be clear about this:

  • This is a feature, not information collection. Before an agent modifies a file, a copy of the previous content is written to the local rollback directory (dsh-home/rollback/), and command output and conversation text are likewise written only to the local machine (dsh-home/sessions/).
  • Authorisation is governed by the agent preset. The permission preset can be chosen in Settings; the packaged app runs on the unattended preset by default. "Pure mode" strips all prompts and tools and leaves only online search. Whether tools may read or write files and run commands depends on the preset you select and on the individual approvals.
  • Data flows as described in section 4. The content the agent reads is sent to the model provider selected for that session as tool results — do not grant file and command permissions in directories that contain confidential files.

Two further items of the same kind — local functionality that you should still know about:

  • Global input listening by the desktop-pet plugin: while the pet is enabled it registers system-level keyboard and mouse hooks, but it passes only the key name and the mouse coordinates to the pet's own window for its animation reactions. Everything stays inside local processes, is not written to disk and is not sent over the network. Simply disable or uninstall the plugin when you do not need it.
  • The "Network Receive" node listens on 0.0.0.0: while that node runs, it listens on all of the machine's network interfaces on the port you filled in (TCP / UDP), so other devices on your local network can connect to it and push data. This is a data entry point you opened yourself; nothing sent or received passes through any server. Stop the node when you are not using it.

9. Crash and diagnostic reports: written locally, exported only by you

When something fails, the app appends the error stack and an environment block to local logs (logs/error.log and similar) and to the crash-report directory (logs/crash-reports/, the 30 most recent reports). The environment block contains the version number, the Electron / Chrome / Node versions, platform and OS release, architecture, interface language, and the executable, data and working directory paths. This information is never uploaded automatically: the crash dialog offers exactly three local actions — "Export diagnostic log…", "Open log folder" and "Close".

A MTNode-diagnostic-*.txt file is created only after you click "Export diagnostic log" and choose a path in the Save-As dialog (the Desktop by default). It consists of the tail of the log plus the environment block, and its first two lines state explicitly: note: API keys and secrets are NOT included. — that is, API keys and secrets are not collected into it. Until you forward that file yourself, it stays on your computer.

One boundary is worth noting: the log tail consists of text you produced yourself (workflow content, error messages, command output), and the paths in the environment block may contain your Windows user name. If you attach an exported diagnostic file to a GitHub issue or send it to anyone else, that information leaves your machine through your own action — check it and remove anything you do not want to disclose before submitting.

10. Cookies and similar technologies

The app does not use cookies. It is a desktop program: it does not identify users or serve advertising through cookies or comparable technologies (local shared objects, pixel tracking); the interface loads no third-party script and no external resource, and network requests are issued by the main process. The Workshop's signed-in state relies on the Bearer token stored in the local config.json (section 6), not on a cookie. This privacy policy page is a plain static single file: it contains no script and no analytics code, and it sets no cookie in your browser.

The only browser-like storage involved is the rendering cache that the Electron / Chromium runtime maintains locally (last two rows of the table in section 3), and it never leaves this computer.

11. No sale, no sharing

We do not sell or share your personal information with any third party. Neither this project's own server nor the shipped code contains any route that would forward user data to a third party. Apart from the following two categories, there is no automatic forwarding at all:

  • The providers you chose and pay for yourself listed in section 4, and the addresses you configured yourself (including MCP servers, online-browsing targets, and the sources from which dependencies and models are downloaded).
  • Content you deliberately publish in the Creative Workshop / Forum — once posted, it is visible to all users.

Where the law requires it (a request from a judicial or administrative authority following due process, or disclosure necessary to respond to litigation or a dispute involving this project), we may disclose information to the minimum required extent, and where legally permitted we will tell you about it. That is the only general exception in this section.

12. Retention and deletion

On your machine: delete the directory and it is gone

Quit the app and delete the data root %APPDATA%\pipeline-console\ (or the folder you pointed Settings at). In one step this removes all workflows, assets, snapshots and recycle bin, configuration and API keys, the fact database, agent session records and rollback copies, logs and caches. The Microsoft Store (MSIX) build is no exception: this project does not write user data into the registry or any other system location. You can also be selective — delete individual workflows in the app (they go to the recycle bin), clear a plugin's data in app-plugins/<plugin id>/, or remove only the key fields in config.json.

13. Minors

The app is a workflow-orchestration and content-production tool aimed at adult and professional users. It offers no feature intended for minors and has no age-verification mechanism. We do not target minors and we do not knowingly collect personal information from minors; a minor should use the app only under the guidance of a guardian. If you believe we have collected a minor's information knowingly, contact us per section 15 and we will verify it and delete it.

14. Policy changes and version record

When the app's outbound network behaviour, the server's retention policy or the permission model changes, we update the internal fact inventory first and this page afterwards, and we record the version and the substance of the change here. Continuing to use a newer build means accepting the policy version then in force; where the change is substantial we will also say so on the download page and inside the app.
