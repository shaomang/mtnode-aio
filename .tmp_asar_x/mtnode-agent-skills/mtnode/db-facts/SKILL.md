# 数据库事实查询纪律（mtnode_db）

任务接入「数据库副本」节点后，宿主会注入事实强制约束。模型只负责推理与执行，事实一律来自工具：

## 硬规则

1. **一切事实先查工具**：名称、数字、价格、条款、路径、状态等，先用 `mtnode_db` 的 `list` 看库里有什么，再用 `query` 检索、`get` 取全文。
2. **引用可回溯**：回答里每个关键断言必须写 `[记录id · 标题]`；挂不上引用的断言在交付前删除。
3. **查不到就明说**：`query` 返回 `found: 0` 或 `get` 报「没有该记录」时，明确回答「数据库中没有该信息」——不猜、不外推、不用参数记忆补全。
4. **数字交给 calc**：金额、日期、比例等任何计算用 `mtnode_db` 的 `calc` 动作（数字 + `+ - * / %` 括号），禁止心算。
5. **推断要标注**：数据库未记载、但任务本身需要的推断，必须标注「此为推断，数据库未记载」。
6. **未接入就拒绝**：工具报「当前任务未接入数据库副本」时，说明数据库不可用，并拒绝凭记忆回答事实。

## 查询技巧

- 先 `list`（一次看全部标题与 id），再按需 `query` / `get`，避免盲目多轮。
- `query` 支持字段过滤：`title:客户 kind:fact file:合同`。
- 中文检索按字与词匹配；拿不准时同时查同义词。
- 需要多个事实时逐条 `get` 并引用，不要改写记录原文（引用时可压缩，但数字与专名不得改动）。

## 与画布的关系

- 数据库超级节点（kind super · db:true）由用户维护与编译；你只读，不修改其内部节点与索引。
- 副本节点是只读引用；不要把副本当普通输入节点改内容。

## 存储与检索技术栈（宿主侧，模型勿越界）

- 事实存于项目子文件夹的 SQLite 库（`.mtnode-db.sqlite`），查询经 FTS5 BM25 排序 + `title:/file:/kind:` 结构化过滤，结果恒带溯源（`source`、`id`、`title`）。
- 编译只由用户手动触发（⚙），且为**增量**：按内容哈希 diff 新增/更新/移除，模型不得代替用户改库。
- 查询日志（audit）自动写入库内 `query_log`，供回放审计。
- 模型永远拿不到「整个库的内存副本」：每次事实都经工具实时查询，引用可回溯。
