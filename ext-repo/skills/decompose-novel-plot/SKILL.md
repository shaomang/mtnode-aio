# 小说剧情拆解

仅用于**智能会话**或**全局助手**。画布上的智能节点不能改图；若在节点里被调用，应改用读写文件完成拆解，不要调用画布工具。

用户给出一段（或多段）文字剧情即输入。在当前画布上完成：分幕 → 各类目纯文本 + 保存 → 全局设定库建档/补充。

## 步骤

1. `mtnode_canvas_get`，看现有节点、`superTree`、`taskFocus`；若已有「全局设定库」，**复用并合并**，勿重复创建。
2. 通读剧情，按情节切成若干**幕**（第1幕、第2幕…）；每幕起一个**短标题**（概括本幕核心冲突或转折，互不重名）。
3. **一次**（或分幕分批）`mtnode_canvas_edit` 搭图，`layout: true`。创建/收纳超级节点常需 `canvas_super` 审批。
4. 拆解结果写入各 `input_text` 的 `text`（合法 YAML）；保存节点 `savePath` 与范畴文件名一致。
5. 同步更新「全局设定库」中的人物画像、场景等档案（见下方合并规则）。
6. 用一两句话告诉用户：改输入后可点控制 ▶ 重跑；全局库会跨幕复用。

## 画布结构

### 顶层

| 节点 | kind | 说明 |
|------|------|------|
| 剧情原文 | `input_text` | 用户可编辑的原文；靠画布上方 |
| 拆解控制 | `control` | `ctrlAction: run`，连到需要重跑的处理链（若有） |
| 全局设定库 | `super` | **画布外部常驻**；`subFolder: 全局设定` |
| 第x幕：{标题} | `super` | 每幕一个；`subFolder: 第x幕` 或 `幕/第x幕-{标题}` |

`createMarks`：框「编辑区 / 分幕区 / 全局设定」，`around` 包住对应节点。

### 每一幕超级节点内部（六类目）

每个类目一对节点，标题互不重名（可加幕前缀，如「第1幕-人物」）：

1. **纯文本节点** `input_text`：`text` = 该类目 YAML 全文  
2. **保存节点** `save_text`（或 `save`）：上游接该类目文本；`savePath` 如下（相对幕的 `subFolder`）

| 范畴 | savePath |
|------|----------|
| 人物 | `人物.yaml` |
| 情节 | `情节.yaml` |
| 结构 | `结构.yaml` |
| 主题 | `主题.yaml` |
| 环境/背景 | `环境背景.yaml` |
| 语言风格 | `语言风格.yaml` |

连线：各类目 `input_text` → 对应 `save_*`。不要用智能节点（`agent:true` / `agent_task`）接 `save_*`。

### 全局设定库（外部超级节点）

用于跨幕**复用**与**持续补充**，不随单幕删除而丢失。

建议内部（均可再包一层 `super` 收纳）：

| 档案类型 | 纯文本标题示例 | savePath 示例 |
|----------|----------------|---------------|
| 人物画像 | 人物-{姓名} | `人物/{姓名}.yaml` |
| 场景档案 | 场景-{场景名} | `场景/{场景名}.yaml` |
| 道具/组织等（按需） | 道具-{名} / 组织-{名} | `道具/{名}.yaml` / `组织/{名}.yaml` |
| 索引（可选） | 设定索引 | `索引.yaml` |

规则：

- 首次出现：新建档案节点 + 保存节点，写入完整可得信息。
- 后续幕再出现：打开已有档案，**合并补充**（新别名、外貌细节、关系、状态变化、出场幕次）；不删已有字段；冲突时保留原文依据更强的一条，并在 `notes` / `revisions` 记下分歧。
- 幕内「人物.yaml / 环境背景.yaml」只写**本幕相关摘录与引用**；完整定妆/世界观以全局库为准，幕内用 `ref: 人物/张三` 一类键指向全局档案。

## 分幕原则

- 按**情节单元**分幕（目标推进、冲突升级、转折、收束），不要机械按字数切。
- 幕序连续：`第1幕`、`第2幕`…；标题 4–12 字，点出本幕动作或悬念。
- 单段短文可只有一幕；长文宁多幕勿把无关转折塞进同一幕。
- 每幕「情节.yaml」须能独立讲清：起承、冲突、结果、与前后幕衔接。

## 各类目 YAML 要点

一律 YAML 1.2；中文键名；未知用 `null` 或 `[]`；不编造原文没有的事实。推断须标 `confidence`（`explicit` / `inferred`）。完整字段见 [schemas.md](schemas.md)。

- **人物**：本幕出场角色、关系、动机、状态变化（完整画像进全局库）
- **情节**：事件序列、因果、冲突、结果、钩子
- **结构**：开端/发展/高潮/收束；叙事视角、时间线、伏笔回收
- **主题**：母题、象征、价值观张力、本幕主题功能
- **环境/背景**：时空、地点、氛围、社会/规则背景（完整场景进全局库）
- **语言风格**：语气、修辞、节奏、对话特征、可复用文风标签

## 注意

- 标题全局唯一（含幕前缀），否则 `@标题` 会乱。
- 超级节点 `subFolder` 保证各幕 `人物.yaml` 不会互相覆盖。
- 已有全局档案时先读盘/读节点再合并，禁止覆盖成更短的空壳。
- 不要删除正在运行的节点；简单短文也不要省略全局库（至少建空壳索引，便于后续续写）。
- 搭完说明：改「剧情原文」或某幕文本后，保存链可再跑；续篇拆解时只增幕并更新全局库。
