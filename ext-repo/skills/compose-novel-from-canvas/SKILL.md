# 画布合成小说

仅用于**全局助手**。本流程是 **decompose-novel-plot（小说剧情拆解）的逆操作**：从画布上的结构化档案合成**连贯可读的小说正文**，不是再拆一遍，也不是搭处理流水线。

**禁用**：任务节点、控制节点、处理节点（`proc_*` / `agent_task`）、绘制（`createMarks`）。只使用 `input_text`、`save`/`save_text`、必要时的 `super` 收纳输出，以及读文件工具。

用户意图示例：「根据当前画布写小说」「把拆解结果合成正文」「按世界书扩写成章」。

## 步骤

1. `mtnode_canvas_get`，盘点顶层与 `superTree`：是否有「世界书」、若干「第x幕」、其它散落的 `input_text` / 保存节点 / 分区说明。
2. 确认**成文档位**（见下）。若用户未提及长度/风格档位，**先问再写**，不得擅自默认。
3. **收集素材**（只读，勿覆盖档案）：
   - 幕超级节点内八类目 `input_text`（人物/情节/结构/主题/环境背景/语言风格/伏笔/事实）
   - 世界书：索引、人物、场景、势力、账本、写法资产、规则/概要
   - 若节点文案被截断或为空，按 `savePath` / `subFolder` **读磁盘 YAML**（优先完整落盘）
   - 其它节点（自由备注、原文、大纲）一并纳入；与 YAML 冲突时：**世界书与账本优先于幕内切片，幕内情节优先于笼统备注**
4. 按幕序拼**章/节大纲**（可先写在内部草稿，不必立刻落盘），再撰写正文。
5. **一次或分批** `mtnode_canvas_edit`：在画布上创建/更新输出节点（见「输出结构」），`layout: true`。不要改既有世界书与幕内档案内容，除非用户明确要求「回写修订」。
6. 用一两句话说明：成文依据了哪些幕/世界书；缺口如何处理；读者如何打开输出节点或文件。

## 成文档位

| 档位 | 篇幅目标 | 写法 |
|------|----------|------|
| 速写 | 每幕约 400–900 字 | 只写主冲突与结果；少对话；伏笔点到为止 |
| 标准 | 每幕约 1200–2800 字 | 起承转合齐全；关键对话与场面；回收本幕到期伏笔 |
| 长卷 | 每幕约 3000+ 字或按用户字数 | 扩场面、内心、环境；严格遵循写法资产与人物口吻；禁止注水空转 |

用户若指定总字数/章数/人称，以用户为准并覆盖上表。

## 合成原则（逆拆解）

1. **情节为骨，档案为肉**：以各幕 `情节.yaml` 的 beats / conflict / climax / outcome / hooks 为骨架；人物动机、关系阶段来自幕内切片 + 世界书档案。
2. **世界书定一致性**：姓名、别名、外貌时间线、势力规则、场景限制以世界书为准；幕内 `ref:` 必须解引用后再写。
3. **写法资产优先于临场发挥**：`写法/写法资产.yaml` 与各幕 `语言风格.yaml` 约束语气、修辞、对话特征；冲突时以写法资产中「启用」规则为准。
4. **伏笔与事实账本**：植入要自然；标注「已回收」的在对应幕兑现；禁止发明账本没有的关键反转（标准/长卷）；速写可弱化支线。
5. **推断可润色，不可造史**：`confidence: inferred` 可文学化描写，但不得升格为硬事实；禁止新增与档案矛盾的人物、地点、势力。
6. **幕间衔接**：用上一幕 `hooks_to_next` 与下一幕 setup 过渡；时间线遵循 `结构.yaml`；无时间信息则顺叙、少跳跃。
7. **散落节点**：不在拆解结构内的文本，当作作者备注或支线素材；写不进主线则放入「附录备注」节点，勿硬塞进正文。

## 输出结构

### 推荐（最小）

| 节点 | kind | 说明 |
|------|------|------|
| 合成小说 | `input_text` | 全文或分章合并正文；靠画布上方或独立区域 |
| 保存小说 | `save_text`/`save` | `savePath: 合成小说.md`（或用户指定） |

连线：`合成小说` → `保存小说`。

### 可选（长文 / 多幕）

- 超级节点 `小说成稿`（`subFolder: 合成小说`），内含：
  - `成稿大纲`（YAML，见 [schemas.md](schemas.md)）
  - `第x章：{标题}` 多个 `input_text`（一章一文件更利于续写）
  - 对应 `save_*`：`合成小说/第x章.md` 等
- 幕很多时**分批**写入章节，单次 `create` ≤ 40。

### 禁止

- 覆盖或清空「世界书」「第x幕」内已有档案节点。
- 为合成而新建处理/控制流水线。
- 在智能节点里改图（应退回全局助手）。

## 阅读顺序建议

1. 世界书 `索引.yaml`（若有）→ 规则/概要  
2. 按幕号升序：情节 → 人物 → 结构 → 环境 → 主题 → 语言风格 → 伏笔/事实  
3. 世界书人物/场景/势力全文（按 `ref` 按需读，勿一次灌爆上下文）  
4. 写法资产 → 动笔  

**防上下文撑爆**：先列目录与摘要再分批读全文；长 YAML 用文件读取；合成时按章落盘，勿在一次工具结果里回灌整本小说。

## 与「小说剧情拆解」的关系

| 拆解（decompose-novel-plot） | 本 skill（compose-novel-from-canvas） |
|------------------------------|----------------------------------------|
| 小说正文 → 幕 + YAML + 世界书 | 幕 + YAML + 世界书 → 小说正文 |
| 禁止编造原文没有的事实 | 禁止编造档案没有的硬设定 |
| 产出结构化节点 | 产出可读叙事；可选大纲节点 |

若画布几乎为空：说明缺少拆解产物，建议先跑拆解，或请用户粘贴素材后再合成。

## 注意

- 标题全局唯一。
- 合并/更新「合成小说」前先读已有输出节点，避免误盖用户手改。
- 创建超级节点需 `canvas_super` 审批；拒绝则改为顶层输出节点，勿强行平铺污染世界书。
- 完成后勿提示「点控制 ▶」。
